# B01 — 拖拽与版式实现

> 归属 `dev-nxsk`。**要动正文布局先读这篇**：这里写清了哪一层负责什么，改错层会互相打架。

## 一、三层分工（解耦的核心）

```
数据层   src/shared/blockLayout.js   （367 行，纯函数，无 react / 无 node）
         版式 JSON 的生成、校验、自愈、吸附、重排、高度换算——前后端共用
   ↓
视图层   src/web/frontend/components/blockBoard.jsx （307 行）
         面板（分组）+ 块（字段）+ 拖拽交互 + 测量挂载点
   ↓
引擎     react-grid-layout 2.3.0（Responsive + useContainerWidth）
         只负责：按 x/y/w/h 定位、按断点折列、给宽度拖拽手柄
```

**为什么这样分**：布局的「关系」（谁在谁上面、多宽、多高）是**数据**，必须能存能读能测；
碰撞/折列/像素换算是**引擎**的事，不自己写；两者之间只通过一份 JSON 通信。
所以「面板能拖」这件事一行数据库代码也没碰。

## 二、版式 JSON（存在 `section.layout`）

```jsonc
{
  "v": 1,
  "mode": "grid",                       // grid = 块面板（默认）· flow = 单列表单
  "panels": ["basic", "contact"],       // 面板（分组）顺序
  "groups": {
    "basic": {
      "collapsed": false,
      "layouts": {                      // 按断点各一份；i = 字段 key
        "lg": [{ "i": "name", "x": 0, "y": 0, "w": 6, "h": 4 }]
      }
    }
  }
}
```

| 常量 | 值 | 位置 |
| --- | --- | --- |
| 断点 px | `lg 1200 / md 996 / sm 768 / xs 480 / xxs 0` | `BREAKPOINTS` |
| 列数 | `lg 12 / md 10 / sm 6 / xs 4 / xxs 2` | `BP_COLS` |
| 行高 | **8px 一档**（`ROW_HEIGHT`）+ 间距 `MARGIN = [10,10]` | 内容驱动高度需要细档 |
| 最小行 | `MIN_H = 4`（≈62px）；最小列 `MIN_W = 2` | |
| 默认尺寸 | `DEFAULT_PX`（按类型给「最小高度像素」）→ `rowsForPx()` 换算成行 | 见 [[B02-扩展新字段类型]] |

### 三个纯函数撑起「自愈」

| 函数 | 什么时候跑 | 作用 |
| --- | --- | --- |
| `sanitizeLayout(raw)` | 读 store、写 store、面板收到脏数据 | 结构校验 + 夹到合法范围；**永不抛错**，坏数据不进 store |
| `reconcileLayout(layout, groups)` | `core/render.js` 的 `dumpSection()`、`sections/service.getSection()`、前端 `view.jsx` | 对齐到当前字段：删字段 → 摘块；新字段 → 接组尾；删分组 → 整块消失。幂等 |
| `repackBlocks(items, cols)` | 拖动排序落点 | 按给定**顺序**重铺，保留每块 `w` |

> 版式在服务端被对齐过一遍（dump 里就是对齐后的），前端再对齐一次——多跑一次没成本，但少跑一次就会「面板上有空块」。

## 三、内容驱动高度（这条最容易改错）

**目标**：md 正文多长就多高、清单加一行就长一行；删掉内容再缩回最小高。
**做法**：存储的 `h` 只是**最小高**，真实高度在视图期按内容量出来。

```jsx
// blockBoard.jsx 的 Block：ResizeObserver 盯「块体的第一个子元素」
const ro = new ResizeObserver(schedule);
ro.observe(body);
if (body.firstElementChild) ro.observe(body.firstElementChild);   // 块体被网格锁死，量它没用
// 需要的高度 = 块头 + 内容自然高度 + 8
```

```js
// shared/blockLayout.js
growHeights(items, measured)   // h = max(存储的 h, rowsForPx(内容像素)) —— 只长不缩到最小高以下
keepMinHeights(items, base)    // 回写前把「视图期算出来的高度」剥回最小高
```

四条必须遵守的边界：

1. **量的是内容，不是块体**：`.blk-body` 的高度由网格锁着，`overflow: visible` 下 `scrollHeight` 等于可视高度，
   量了也白量——必须量它里面的控件（`getBoundingClientRect().height`）。
2. **视图期高度不落盘**：那是「这一条内容有多高」，不同条目不一样。落盘只落最小高。
3. **只对当前断点生效**：不同断点列宽不同，内容折行高度本来就不同，别把 lg 的高度抄给 md。
4. **高度不给人拖**：`resizeConfig.handles = ['e','w']`，只留左右。再给一个手动高度会和内容打架。

## 四、拖拽：为什么不用引擎的自由拖拽

12 列里**全宽块只有 `x=0` 一个落点、半宽块只有两个**，再加上纵向压实实时回流——
用引擎拖时块只能在「合法格」之间跳，拖到空处还会被吸回上面（真实反馈：「只能停在能停的位置，非常卡手」）。

所以：**拖拽只表达顺序，位置由我们算**。

```jsx
<Responsive dragConfig={{ enabled: false }} … />       // 引擎不再搬块
```

- 块的顺序 = 版式里的 `(y, x)` 排出来的 key 序列（`order`）；
- 拖动走 `useListDrag`（`components/listDrag.jsx`，原生 HTML5 DnD，**只有块头可拖**），
  落点按块的上/下半算插入位，UI 是 2px 插入线；
- 松手 → `reorderAt(order, from, insertAt)` → `repackBlocks()` → 写回版式。

**面板**（分组）的顺序同理，走同一套 `useListDrag`，拖的是 `.panel-head`（整行可拖，行内按钮不触发）。

宽度是**另一个自由度**：拖块的左右边缘 → `onResizeStop` → `commit()` → `snapItems()` 吸附到
「自身宽度的整数倍」（半宽吸 0/6），宽除不尽列数的（用户特意拉的 5 列）不动。

## 五、保存链（两条，别混）

```
拖拽/改宽 ──► commit(layout items) ──► keepMinHeights ──► snapItems
                                         └─► onLayouts(gid, layouts)
                                               └─► view.jsx applyBoard(next)
                                                     ├─ sameLayout(next, boardView)? 相同就 return
                                                     └─ 防抖 700ms ──► PATCH /api/sections/:id { layout }
填字段   ──► patchField(key, value) ──► draft ──► dirty ──► 「N 处改动 → 保存」PATCH /api/entries/:id
```

为什么必须两条：拖一下版式不该把没填完的值一起提交；反过来改值也不该打乱版式。

**关键防抖守卫**（都在 `src/modules/entries/view.jsx`）：
- `sameLayout(next, boardView)` —— 引擎在挂载/断点切换/内容变高时也会回调，不加这道比较，
  打开一次页面就等于写一次版式（还会把当时的最小高冻结）。
- `boardTouched` —— 用户动过版式后，`load()`（保存值触发的重读）不再把 `board` 弹回服务端旧值。
- **不挂 `onLayoutChange` 落盘**，只挂 `onDragStop` / `onResizeStop`（现在只有后者）。

## 六、踩过的坑（都真机验证过）

| 现象 | 根因 | 正确做法 |
| --- | --- | --- |
| 拖动时**按下就报错** `DraggableCore not mounted on DragStart` | 把函数组件 `Block` 直接当网格子元素；引擎靠 `cloneElement + ref` 注入定位，函数组件接不住 ref | 子元素必须是**原生 `div`**（`.blk-cell`），块放里面 |
| `noCompactor`（自由摆放）后块**互相重叠** | 关掉压实就没人解冲突，`period` 与 `summary` 会落在同一格 | 别关压实；用插入式排序（本篇第四节） |
| 块高不跟内容 / md 被裁 | md 预览自带 `max-height` 或量的是块体而非内容 | 去掉 `max-height`；量内容元素 |
| 版式「打开就被改了」 | 在 `onLayoutChange` 里落盘 | 只在拖拽/改宽的 stop 回调里 commit |
| 拖拽时**不跟鼠标**（已知问题） | 原生 HTML5 DnD 的拖影是浏览器截图，`transform` 容器里常截成空白 | 待改：pointer 事件 + 自绘浮层（见下） |

### 已知待改进

原生 DnD 的**拖影**在 `position: absolute + transform` 的网格项上会被截成空白/不跟手，
表现为「拖的时候只有插入线在动，块不跟着鼠标」。改法（尚未实现）：把 `useListDrag` 换成一个 pointer 版
（`pointerdown` 抓起点 → `pointermove` 用 `elementFromPoint` 找落点并渲染跟随浮层 → `pointerup` 提交），
面板拖拽同样受益。改的时候**只替换交互层**，`reorderAt` / `repackBlocks` / 保存链都不用动——
这正是本节开头三层分工的价值。

## 七、调试手法（改这块时的常用指令）

```bash
npm run dev                                   # vite + serve
nx-sk section dump <栏目> --json | jq .layout  # 看落盘的版式（已对齐）
nx-sk section update <栏目> --clear-layout     # 回到默认编排（改坏了先回滚）
node --test tests/unit/block-layout.test.mjs   # 版式语义单测（16 条）
```

浏览器里：`document.querySelector('.blk[data-block="role"]')` 定位块；
`.blk-cell` 是网格项；拖动中的类名是 `react-grid-item … react-draggable-dragging`；
插入线是 `.blk-cell.drop-before / .drop-after`。

## 八、改动前的三条自检

- [ ] 我改的是**数据**（`shared/blockLayout.js`）、**视图**（`blockBoard.jsx`）还是**样式**（`styles.css`）？跨层改要同时更新这篇
- [ ] 新的坐标/尺寸有没有经过 `sanitizeLayout`（否则脏数据会进 store）
- [ ] 高度相关改动 → 跑一遍 `block-layout.test.mjs`，并手动确认长 md 不被裁、空字段不塌
