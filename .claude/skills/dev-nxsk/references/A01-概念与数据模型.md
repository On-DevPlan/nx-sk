# A01 — 概念与数据模型

> 归属 `dev-nxsk`。**动手改数据结构之前读这篇**：它决定你能改什么、改动会牵连到谁。

## 一、五个概念（称呼别混）

| 概念 | 代码里的名字 | 是什么 | 住在哪 |
| --- | --- | --- | --- |
| **栏目** | `section` | 一组同构条目的容器 + **一份字段字典** | `section.fields[]`（唯一结构） |
| **分组** | `group` | 表单里的小标题，也是**块面板**的分组单位 | **就是一条字段**：`{ key, label, type: 'group', keys: [...] }` |
| **字段** | `field` / `fieldDef` | 字典里的一条定义：`key / label / type / hint / options / fill …` | 在 `section.fields[]` |
| **条目** | `entry` | 一行数据：`title` + 每个字段一份值 | `entry_fields`（结构）+ `field_data`（值） |
| **版式** | `layout` | **显示关系**：面板顺序、每块的位置/宽高（按断点） | `section.layout`（独立 JSON，见 B01） |

一句话：**栏目负责结构，条目负责值，版式负责摆法。而结构只有一种东西——字段。**

> **0.42 的分水岭**：以前「分组」是栏目上的第二份结构（`groups[]`），字段再拿 `group` 指回去，
> 两份数据必须对账（`syncSectionGroups` 就是那次事故的补丁）。现在组是 `type: 'group'`
> 的**字段**，用 `keys` 引用同栏目其他字段——结构与值、面板与 CLI 都只有一份真相。
> `groups` 表已随 v6 迁移删除；运行时**不认旧形状**。

## 二、存储的真实形状（SQLite，schema v6）

默认库 `~/nx-sk/nxsk.db`（可用 `NX_SK_HOME` / `NX_SK_STORE` 覆盖，测试必用！）。
逻辑视图（`store.json` 只剩首启导入的历史意义）：

```jsonc
{
  "version": 4,                    // STORE_VERSION（JSON 侧）；DB 侧看 meta.schema_version
  "sections": [{
    "id": "job", "title": "求职", "kv": false,
    "fields": [
      // 组：容器，keys 就是成员（顺序即显示顺序）
      { "key": "basic", "label": "基本信息", "type": "group", "keys": ["name", "gender"] },
      // 普通字段：**没有** group 键——归属由上面那条组字段的 keys 表达
      { "key": "name", "label": "姓名", "type": "text" },
      { "key": "gender", "label": "性别", "type": "select", "options": ["男", "女"] },
      // 每个非 KV 栏目自带的资料袋：一组一字段
      { "key": "sourceGroup", "label": "原始资料", "type": "group", "keys": ["source"] },
      { "key": "source", "label": "原始资料", "type": "source", "fill": "optional" }
    ],
    "layout": { "v": 1, "mode": "grid", "panels": ["basic", "sourceGroup"], "groups": { /* … */ } }
  }],
  "entries": [{ "id": "e_x", "section": "job", "title": "张三" }]
}
```

要点：

- **组 key 与字段 key 共用一个命名空间**（DB 主键是 `(section_id, key)`）。旧数据里
  组 id 与成员字段撞名（`education` 组里有 `education` 字段）时，迁移/模板折算用
  `freeGroupKey()` 自动改名（`education` → `educationGroup`）；内置资料袋因此固定叫 `sourceGroup`。
- **嵌套组**：组字段之间可以互相 `keys` 引用；`normalizeStructure` 保证每层只有一个父、且不成环。
- **KV 栏目**（`kv: true`）没有分组：它是一张表，一行一个键值对。

读写只有一个入口：`src/core/store.ts` + `src/core/db/`：

- `loadStore()` / `mutateStore(fn)`：读走 DB，写=单事务全量重写（`writeStore`）。
- 归一化收口在 **`src/core/store-shape.ts` 的 `normalizeSection`**：字段过
  `normalizeStructure` → `ensureSourceBuiltin` → 再 `normalizeStructure`。
  **所有读路径都会过这里**，这是「结构永远自洽」的唯一保证。
- `normalizeStructure` 本体在 **`src/shared/fields/structure.ts`**（零依赖，面板也用同一份）。

## 三、四条不变量（都在归一化里强制）

| 不变量 | 在哪实现 | 破了会怎样 |
| --- | --- | --- |
| **组声明的成员必须存在**（且不能是自己） | `normalizeStructure` 第 2 步 | 面板渲染出空块 / 引用了不存在的字段 |
| **每个普通字段恰好归属一个组**（孤儿归根组 `root`，没有就合成） | `normalizeStructure` 第 4 步 | 字段「存了却不显示」——面板按组渲染 |
| **每个非 KV 栏目自带「原始资料」组与 `source` 字段** | `ensureSourceBuiltin()`（`core/fields/source-bag.ts`） | 资料袋消失、`source` 命令找不到入口 |
| **`layout` 里的块只引用现存的字段 key** | `reconcileLayout()`（`src/shared/blockLayout.ts`） | 删字段后留下空块 / 引用不存在的 key |

> 改任何结构后，先问一句：**归一化会不会把它改回去？** 会 → 改动要落在归一化里，而不是只改写入路径。
> 再加一句（0.42 特有）：**这条信息会同时改变「谁是组的成员」吗？** 会 → 改组字段的 `keys`，别在字段上挂新键。

## 四、字段类型

`FIELD_TYPES`（`src/shared/fields/types.ts`）：

```
text | textarea | number | date | month | bool | select | tags
entrylist | table | source | secret | file | md | shortcut | debug | group
```

| 类型 | 值的形状 | 关键语义 |
| --- | --- | --- |
| `text` / `textarea` / `number` / `date` / `month` | 标量 | `textarea` 前端自动增高 |
| `bool` | 布尔 | CLI 认 `是/否/true/false/1/0` |
| `select` | 字符串 | `options` 是**候选不是白名单**：不在候选里的真实值也允许写入 |
| `tags` | 字符串数组 | CLI 用 `、` 或 `,` 分隔；`maxItems` 上限 |
| `secret` | 密文对象 `{v,iv,tag…}` | 落盘 AES-256-GCM；读默认原文，`--mask` 打码 |
| `file` | 附件 id **数组** | 值不是路径；物理文件在 `~/nx-sk/files/`，同 sha256 去重 |
| `md` | markdown 字符串 | 正文里 `![说明](f_xxx)` 引用附件库、`http(s)` 自动成链接、`- [ ]` 可勾 |
| `entrylist` | 行对象数组 | 列在字段定义的 `fields[]` 里声明；**结构归定义** |
| `table` | `{columns, rows, totals}` | 格有类型、有计算列与统计；**结构归数据**（条目自己能加列） |
| `source` | 资料条目数组 | 内置「原始资料」袋；不计完整度（`fill: optional`） |
| **`group`** | **无值**（`cell: false`） | **容器**：`keys` 引用成员；不参与值、完整度、密文；面板渲染成小标题 |

密文判定不是靠 type：**键名含 `密码/口令/密钥/账号/token/apiKey/secretKey…` → 自动登记成 `secret`**
（`isSensitiveField`）。所以「直接写账号密码」也不会明文躺盘。

## 五、完整度与 `fill` 策略（别乱算）

- 完整度 = `已填 / 该填`，**只统计 `fill: normal`** 的字段；**组字段永远不计**（容器没有可填的值）。
- `fill`：`normal`（默认）· `optional`（不必填）· `avoid`（不填，填了可能减分）。
  `optional` / `avoid` **既不计分子也不计分母**——否则「主动跳过」会永远压着那个百分比。
- 读出来的形状：`completeness.ratio` + `missing[]` + `excluded[]`；面板据此显示未填清单。
  改算法只改 `src/core/render.ts` 的 `completeness()`，别在视图里再算一遍。

## 六、KV 栏目（`kv: true`）

「密钥」那种栏目**就是一张表**：一行 = 一个键，只有一个 `value` 字段，**没有组字段**。
- 面板渲染成表格（`src/modules/entries/kvTable.jsx`），不走条目表单/块面板；
- `key set/get/list/remove` 是 `entry *` 的语法糖，`set` 同名覆盖（`entry add` 会 CONFLICT）；
- **KV 栏目不许加字段**：`entry update --set 新键=值` 会被拒绝并告诉你去用 `key set`。

## 七、常见误区

| 误区 | 纠正 |
| --- | --- |
| 「分组是栏目上的一个数组」 | 0.42 起组就是**字段**（`type: 'group'` + `keys`）；`groups` 表已删 |
| 「字段上有 group 键」 | 没有。归属只住在组字段的 `keys` 里；读出口的 `group` 是**派生**的 |
| 「在条目里新增一个键，面板就该显示」 | 会显示，但**必须先登记进字段字典**（写入时自动登记；手改 store 不会） |
| 「删字段就是把值删了」 | 删字典只影响渲染，`field_data` 里的值仍在；要清值用 `--unset` |
| 「改字段 key 换个名字」 | **不许**：值按 key 存，改 key = 已有值读不出来。要换就新增字段再搬值 |
| 「删组就是把组字段删了」 | 非空组不给删（先 `set-field --group` 搬走成员）；内置「原始资料」组不可删 |
| 「模板改了，老栏目会自动跟上」 | 不会。模板改动只影响新建栏目；老栏目用 `section sync` 补（只增不改不删） |
| 「新组想放哪就插哪」 | `addGroupField` 默认插在 `sourceGroup` 之前；顺序由字典里组字段的位置决定 |
