# A01 — 概念与数据模型

> 归属 `dev-nxsk`。**动手改数据结构之前读这篇**：它决定你能改什么、改动会牵连到谁。

## 一、五个概念（称呼别混）

| 概念 | 代码里的名字 | 是什么 | 归属 |
| --- | --- | --- | --- |
| **栏目** | `section` | 一组同构条目的容器 + **一份字段字典** | `section.groups[]` + `section.fields[]` |
| **分组** | `group` | 条目表单里的小标题，也是**块面板**的分组单位 | `{ id, title }`，顺序即显示顺序 |
| **字段** | `field` / `fieldDef` | 字典里的一条定义：`key / label / type / group / hint / options / fill …` | 在 `section.fields[]` |
| **条目** | `entry` | 一行数据：`title` + `values{字段key: 值}` | `store.entries[]` |
| **版式** | `layout` | **显示关系**：面板顺序、每块的位置/宽高（按断点） | `section.layout`（独立 JSON，见 B01） |

一句话：**栏目负责结构，条目负责值，版式负责摆法。** 三者分家，改一个不会污染另外两个。

## 二、store.json 的真实形状

默认落在 `~/nx-sk/store.json`（可用 `NX_SK_HOME` / `NX_SK_STORE` 覆盖，测试必用！）：

```jsonc
{
  "version": 3,                         // STORE_VERSION，迁移动它
  "settings": { "defaultSection": "demo", "navGroups": [], "navOrder": [], "navHidden": [] },
  "sections": [{
    "id": "job", "title": "求职", "description": "", "order": 50, "template": "job",
    "kv": false,                        // true = 这个栏目是一张 KV 表（密钥那种）
    "titleField": "name", "titleLabel": "档案名",
    "groups": [{ "id": "basic", "title": "基本信息" }],
    "fields": [{ "key": "name", "label": "姓名", "type": "text", "group": "basic" }],
    "layout": { "v": 1, "mode": "grid", "panels": ["basic"], "groups": { "basic": { "collapsed": false, "layouts": { "lg": [{ "i": "name", "x": 0, "y": 0, "w": 6, "h": 4 }] } } } }
  }],
  "entries": [{ "id": "e_xxx", "section": "job", "title": "张三", "tags": [], "values": { "name": "张三" }, "createdAt": "…", "updatedAt": "…" }],
  "files": [{ "id": "f_xxx", "name": "简历.pdf", "sha256": "…", "path": "…" }]
}
```

读写只有一个入口：`src/core/store.js`
- `loadStore()`：按 mtime 失效的缓存 + 坏文件挪走（`.corrupt-<stamp>.json`）
- `mutateStore(fn)`：**深拷贝 → 改 → 原子写**（`writeTemp + rename`），抛错就不落盘
- `normalize()` / `normalizeSection()` / `normalizeEntry()`：**所有读路径都会过这里**，这是「老数据能读」的唯一保证

## 三、四条不变量（都在归一化里强制）

| 不变量 | 在哪实现 | 破了会怎样 |
| --- | --- | --- |
| **分组声明 ⊇ 字段引用**：字段 `group` 指向的分组必须被声明 | `syncSectionGroups()`（`src/core/fields.js`） | 面板按声明渲染 → **整组字段静默消失**（真实事故） |
| **每个非 KV 栏目自带「原始资料」分组与 `source` 字段** | `ensureSourceBuiltin()` | 资料袋消失、`source` 命令找不到入口 |
| **`values` 的键必须能在字段字典里找到** | 写入时自动登记（`entries/service.js`） | 值存了但面板不渲染 = 「存了却不生效」 |
| **`layout` 里的块只引用现存的字段 key** | `reconcileLayout()`（`src/shared/blockLayout.js`） | 删字段后留下空块 / 引用不存在的 key |

> 改任何结构后，先问一句：**归一化会不会把它改回去？** 会 → 改动要落在归一化里，而不是只改写入路径。

## 四、14 种字段类型

`FIELD_TYPES`（`src/core/fields.js`）：

```
text | textarea | number | date | month | bool | select | tags
entrylist | table | source | secret | file | md
```

| 类型 | 值的形状 | 关键语义 |
| --- | --- | --- |
| `text` / `textarea` / `number` / `date` / `month` | 标量 | `textarea` 前端自动增高 |
| `bool` | 布尔 | CLI 认 `是/否/true/false/1/0` |
| `select` | 字符串 | `options` 是**候选不是白名单**：不在候选里的真实值也允许写入 |
| `tags` | 字符串数组 | CLI 用 `、` 或 `,` 分隔；`maxItems` 上限 |
| `secret` | 密文对象 `{v,iv,tag…}` | 落盘 AES-256-GCM；读默认原文，`--mask` 打码 |
| `file` | 附件 id **数组** | 值不是路径；物理文件在 `~/nx-sk/files/`，同 sha256 去重 |
| `md` | markdown 字符串 | 正文里 `![说明](f_xxx)` 引用附件库、`http(s)` 自动成链接、`- [ ]` 可勾 |
| `entrylist` | 行对象数组 | 列在字段定义的 `fields[]` 里声明；**结构归定义** |
| `table` | `{columns, rows, totals}` | 进阶版：格有类型、有计算列与统计；**结构归数据**（条目自己能加列） |
| `source` | 资料条目数组 | 内置「原始资料」袋；不计完整度（`fill: optional`） |

密文判定不是靠 type：**键名含 `密码/口令/密钥/账号/token/apiKey/secretKey…` → 自动登记成 `secret`**
（`isSensitiveField`）。所以「直接写账号密码」也不会明文躺盘。

## 五、完整度与 `fill` 策略（别乱算）

- 完整度 = `已填 / 该填`，**只统计 `fill: normal`** 的字段。
- `fill`：`normal`（默认）· `optional`（不必填）· `avoid`（不填，填了可能减分）。
  `optional` / `avoid` **既不计分子也不计分母**——否则「主动跳过」会永远压着那个百分比。
- 读出来的形状：`completeness.ratio` + `missing[]` + `excluded[]`；面板据此显示未填清单。
  改算法只改 `src/core/render.js` 的 `completeness()`，别在视图里再算一遍。

## 六、KV 栏目（`kv: true`）

「密钥」那种栏目**就是一张表**：一行 = 一个键，只有一个 `value` 字段。
- 面板渲染成表格（`src/modules/entries/kvTable.jsx`），不走条目表单/块面板；
- `key set/get/list/remove` 是 `entry *` 的语法糖，`set` 同名覆盖（`entry add` 会 CONFLICT）；
- **KV 栏目不许加字段**：`entry update --set 新键=值` 会被拒绝并告诉你去用 `key set`。

## 七、常见误区

| 误区 | 纠正 |
| --- | --- |
| 「在条目里新增一个键，面板就该显示」 | 会显示，但**必须先登记进字段字典**（写入时自动登记；手改 store 不会） |
| 「删字段就是把值删了」 | 删字典只影响渲染，`values` 里的值仍在；要清值用 `--unset` |
| 「改字段 key 换个名字」 | **不许**：值按 key 存，改 key = 已有值读不出来。要换就新增字段再搬值 |
| 「模板改了，老栏目会自动跟上」 | 不会。模板改动只影响新建栏目；老栏目用 `section sync` 补（只增不改不删） |
| 「store 是给人看的，随手编辑」 | 可以读，但要用 `mutateStore`/CLI 改；手改后至少跑一次归一化（任何命令都会） |
