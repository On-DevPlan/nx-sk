# A02 — 模块与工程契约

> 归属 `dev-nxsk`。这篇是「往哪儿放代码、按什么形状声明」的规矩；具体动手清单见 [[A03-扩展方式]]。

## 一、分层与依赖方向（eslint 会拦）

```
bin/nx-sk.mjs            极薄入口 → src/runtime/cli.js
src/runtime/             装配层：registry（模块表 + 装载期自检）/ spec（参数校验强转）/ cli / api / server
src/modules/<id>/        一个模块 = index.js（action 声明）+ service.js（纯逻辑）+ view.jsx（面板）
src/core/                最底层：store / fields / render / crypto / vault / attachments / source / paths …
src/shared/              前后端共用纯函数（table.js 表格计算、blockLayout.js 版式）——不得 import node
src/web/frontend/        React 面板：App / registry / store.jsx / components/* / styles.css
```

依赖方向（`eslint.config.js` 里的 `no-restricted-imports`，逐条真实生效）：

| 层 | 可以依赖 | 禁止 |
| --- | --- | --- |
| `src/core/**` | `core`、`shared` | `modules` / `runtime` / `web` |
| `src/modules/**` | `core`、`shared`、自己的 `./service.js`，以及 `../settings/service.js` | **任何兄弟模块** |
| `src/modules/system`、`src/modules/transfer` | 全部（刻意的聚合例外） | — |
| `src/web/frontend/**` | `shared`、自己这层 | 直接 import `core`（浏览器里没有 node API） |

> 新模块要记得**不会**自动进 `SIBLING_MODULES`——漏补 = 它能被别人 import 却没有断言会红（写新模块时顺手加一行）。

## 二、一个模块的三件套

```js
// src/modules/sections/index.js —— 只声明，不实现
import * as service from './service.js';
export default {
  id: 'sections',          // 与目录名一致（一致性测试会核对）
  title: '栏目',            // 面板 tab 文案
  order: 500,              // tab 顺序 / help 分组顺序
  view: () => import('./view.jsx'),  // 有面板就写；没有写 null
  resource: 'section',     // 声明「这是一组 CRUD 实体」→ 一致性测试要求 list/get/add/update/remove 齐备
  actions: [ /* … */ ],
};
```

- `service.js`：纯业务（读写 store、算完整度、拼输出），**不 import react，不读 `process.argv`**
- `view.jsx`：只渲染 + 调 `/api`；能力必须来自 action（`consistency.test.mjs` 会反查 `/api` 字面量）

## 三、action 契约（CLI 与 HTTP 的同源点）

```js
{
  id: 'section.update',                       // 全局唯一（装载期自检）
  cli: ['section', 'update'],                 // 命令路径；也能给多条别名 [['a','b'], ['c']]
  http: ['PATCH', '/api/sections/:ref'],      // null = 只走 CLI
  summary: '改栏目（PATCH 语义：只改传入项）…', // help 与 bootstrap 命令表用它
  args: ['ref'],                              // 位置参数（数组或 {name, required}）
  flags: {
    title: { type: 'string', hint: '栏目标题' },
    order: { type: 'number' },
    force: { type: 'boolean' },
    'remove-field': { type: 'array', hint: '字段 key，可重复' },
    layout: { type: 'json', hint: '{…} 或 @file.json' },
    fill: { type: 'kv', hint: '字段=策略，可重复' },
  },
  run: (ctx) => service.updateSection(ctx.ref, ctx),
  render: (d) => service.renderSectionChange(d),   // 人读输出；--json 时直接用 run 的返回值
}
```

`src/runtime/spec.js` 负责**同一套强转**（两端不会各写一遍）：

| `type` | CLI 写法 | HTTP body | 强转要点 |
| --- | --- | --- | --- |
| `string` | `--title x` | `{title:'x'}` | 原样 |
| `number` | `--order 50` | `{order:50}` | 非数字报 `INVALID_INPUT` |
| `boolean` | `--force` / `--kv=false` | `{force:true}` | 认 `是/否/true/false/1/0` |
| `array` | `--remove-field a --remove-field b` 或 `a,b` | `{...:['a','b']}` | **每个元素再按逗号切一次** |
| `json` | `--layout '{"mode":"grid"}'` / `@layout.json` | 直接给对象 | 失败报「不是合法 JSON」 |
| `kv` | `--fill 入党时间=avoid` | `{fill:{…}}` 或 `['a=b']` | 收成对象 |

HTTP 路由由 `src/runtime/api.js` 从 `action.http` **编译**（`compileRoute`），路径占位符按**同名**绑定到 `ctx`；
写操作校验 `Origin`（只允许 127.0.0.1 / localhost / ::1）。

## 四、装载期自检（改完立刻炸，不等到用户敲错命令）

`src/runtime/registry.js` 的 `selfCheckActions()` 在 import 时就跑，检查：`id` 唯一、CLI 路径不重复、
`http` 是 `[method, path]` 或 null、`run` 是函数。重复 / 缺字段 = **进程起不来**。
这也是为什么「加 action」的报错通常出现在 `node --test` 的第一步。

## 五、前端：两张注册表与一个动态挂载点

```js
// src/web/frontend/registry.js
export const VIEWS = [
  { id: 'sections', title: '栏目', order: 500, component: lazy(() => import('../../modules/sections/view.jsx')) },
  { id: 'entries', title: '条目', order: 600, tab: false, component: lazy(() => import('../../modules/entries/view.jsx')) },
  // …
];
export const SECTION_VIEW = VIEWS.find((v) => v.id === 'entries').component;  // 每个栏目 tab 共用它
```

- **必须用字面量 `lazy(() => import('…'))`**：变量拼路径会让 Vite 静态分析不了，丢代码分割。
- `tab: false` = 不出现在导航里，但仍要登记（栏目 tab 由 `App.jsx` 动态挂载，传 `sectionId`）。
- 前端状态只在 `src/web/frontend/store.jsx`：`ui`（view / entry / mask / listW…）+ `toast` / `dialog` / `guard`。
  **只持久化选择，不缓存数据**——数据永远从 `/api` 拉。
- 请求统一走 `src/web/frontend/api/client.js` 的 `api(path, {method, body})`。

## 六、样式与视觉约束（写 UI 前必看）

`src/web/frontend/styles.css` 是全站唯一样式表，token 在 `:root`：

| token | 用途 |
| --- | --- |
| `--ink / --paper / --soft / --soft-2 / --mid / --danger` | 单色阶 + 唯一语义色（红 = 危险） |
| `--line / --line-strong` | 分隔线（rgba 8.5% / 14%）——全站「无边框」靠它 |
| `--row-h 28px / --btn-h 32px / --fs-core 12px` | 密度三件套 |
| `--radius-btn 8px / --radius-box 10px` | 圆角 |
| `--shadow-float` | 浮层（弹窗/侧边栏/toast/拖动中的块）唯一允许的投影 |

规矩：**容器不投影**；正文块里字号 13px（比工具条大一号）；**面板源码里不许有 emoji**（含注释，测试会抓）。

## 七、构建与测试

```bash
pnpm dev            # scripts/dev.mjs：vite dev + serve 双进程
npx vite build      # 产物写 src/web/public（服务端就直接读它）
npx eslint .        # 分层 + hooks 规则
node --test         # 单测（tests/unit/*.test.mjs，全部用临时 HOME）
node tests/smoke.mjs # 端到端：真起服务 + 真跑 CLI + 真发 HTTP
```

`consistency.test.mjs` 钉死的四张表（改任何一张都要同步改另一边）：
**模块目录 ↔ 后端 `MODULES`**、**声明 view 的模块 ↔ 前端 `VIEWS`**、**CRUD 五操作 ↔ 两张注册表**、
**视图里的 `/api` 字面量 ↔ action 的 http**。另加：面板无 emoji、文档与命令漂移检查。

## 八、别做的事

| 不做 | 因为 |
| --- | --- |
| 在 `view.jsx` 里直接 `fetch('/api/...')` 干新能力 | 绕过 action = CLI 做不到，两端就此分叉 |
| 在 `service.js` 里 `import` 兄弟模块 | eslint 直接报错；共享逻辑下沉 `core/` |
| 在 `core/` 里碰 `window` / DOM | core 同时被 CLI 用 |
| 把 `store.json` 路径写死 | 一律走 `core/paths.js`（`NX_SK_HOME` / `NX_SK_STORE` 必须能覆盖，否则测试写脏真实数据） |
