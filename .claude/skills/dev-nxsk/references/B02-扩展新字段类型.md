# B02 — 扩展一个新字段类型

> 归属 `dev-nxsk`。一个字段类型要穿过 **6 个位置**，少一处就会出现「某一端不认」。
> 顺序按依赖走：先核心声明 → 写入 → 读取 → 渲染 → 版式 → 测试/文档。

## 零、先判断该不该新增类型

| 你的需求 | 更省事的做法 |
| --- | --- |
| 只是候选值不同 / 单位不同 | 用现有 `text` / `number` + `hint` / `options`，别新增 type |
| 想存多组「名称·链接·账号」 | 用 `entrylist`（列在字段定义里声明） |
| 想要带类型/公式/统计的表格 | 用 `table`（结构归数据，条目自己能加列） |
| 想存一段带截图的说明 | 用 `md` |
| 想存文件 | 用 `file` |
| **交互形态本质不同**（自定义评分、颜色、坐标、关系引用…） | 才新增 type |

## 一、`src/core/fields.js` —— 类型注册（2 行）

```js
export const FIELD_TYPES = ['text', 'textarea', …, 'rating'];   // ① 加进白名单
export const FIELD_TYPE_LABELS = { …, rating: '评分（1-5 星）' };  // ② 面板下拉框的中文名
```

> 漏 ①：`section update --add-field '{"type":"rating"}'` 直接报「type 非法」。
> 漏 ②：面板类型下拉里显示英文 id（能选，但没人看得懂）。

## 二、`src/modules/sections/service.js` 的 `validateFieldDef()` —— 定义校验

只处理**这个类型特有的约束**，通用键（`key/label/type/group/hint/fill/options/maxItems/sensitive`）已经被统一处理：

```js
if (type === 'entrylist') { /* 必须声明子字段 fields[]，key 唯一 */ }
if (type === 'table') { /* columns 可选，但给了就要能编译公式 */ }
```

新类型如果**没有**结构（如 `rating`），这里不用加任何代码；
如果有结构（像 `entrylist` 那样带列），必须在这里校验，并把结构存进字段定义——
否则「定义了也用不上」的键会静默进 store。

## 三、`src/modules/entries/service.js` 的 `normalizeValue(def, raw)` —— 写入强转

**这一步最容易被忘**。忘了会怎样：`--set 评分=5` 存进去变成字符串 `"5"`，
读出来能看，但排序/比较/公式全错，而且**没有任何报错**。

```js
if (type === 'rating') {
  const n = Number(String(raw).trim());
  if (!Number.isFinite(n) || n < 1 || n > 5) {
    throw badInput(`字段「${def.label}」是 1-5 的评分，收到 ${JSON.stringify(raw)}`);
  }
  return Math.round(n);
}
```

三个约定：
- **标量新类型**放在 `const s = String(raw)` 兜底之前；
- **数组/对象新类型**必须自己 `JSON.parse`（`--set` 传的是字符串），解析失败要**报错而不是吞掉**；
- 空值统一返回 `null`（`--set 字段=` 就是清空，与其它类型一致）。

## 四、`src/core/render.js` —— 读出去的形状

| 函数 | 影响 | 要做什么 |
| --- | --- | --- |
| `isBlank(v)` | 完整度、`--unset`、导出时的「有没有内容」 | 新值形态若是数组/对象，确认空形态被判空（表格是「有列没行也算空」） |
| `formatValue(v)` | `entry get` / `section dump` 的人读文本 | 加分支，输出一行可读值（例如 `评分: 4/5`——项目单色无符号，别用星星） |
| `serializeEntry()` | `--json` 的 `values` | 一般无需改（值原样带出），但**密文/敏感**要确认走的是同一条打码逻辑 |

## 五、`src/web/frontend/components/fieldEditor.jsx` —— 控件

`FieldControl` 是一个按 `type` 分派的 switch，加一个分支即可：

```jsx
if (type === 'rating') {
  return (
    <div className="rating">
      {[1,2,3,4,5].map((n) => (
        <button key={n} type="button" className={n <= (Number(v) || 0) ? 'on' : ''} onClick={() => onChange(n === Number(v) ? null : n)}>{n}</button>
      ))}
    </div>
  );
}
```

四条前端约定：
- 控件的根节点**不要固定高度**（块高由内容量出来，见 [[B01-拖拽与版式实现]] 第三节）；
- 长内容用 `AutoTextarea`（同文件）；多值/附件复用 `FileFieldControl` 的交互范式；
- 敏感字段要跟着工具栏的「打码显示」（`ui.mask`）走 `type="password"` 或替代文本；
- 值可能来自历史数据（字符串形态），控件要**宽松读**（`Number(v)` 而不是 `v.toFixed()`）。

## 六、`src/shared/blockLayout.js` —— 版式默认值（2 处）

```js
const DEFAULT_PX = { …, rating: 66 };            // ① 默认最小高度（px）→ rowsForPx 换算
const WIDE_TYPES = new Set([…, 'rating']);        // ② 是否天然要一整行（宽控件才加）
```

- 漏 ①：落到 `DEFAULT_H.text` 兜底，不一定难看，但高度会偏小/偏大；
- 漏 ②：半宽块里塞宽控件，列宽一挤就换行，看着像坏了。
- 判据：**控件里有横向并排多个元素**（星级、色板、滑块）→ 半宽通常够；**表格/图片/多行** → 整行。

## 七、测试与文档（缺一不可）

```bash
# 1) 强转与校验（最该钉的）
node --test tests/unit/core.test.mjs      # 或新建 tests/unit/<类型>.test.mjs
# 2) 端到端：CLI 写 → HTTP 读，两条路都要覆盖
node tests/smoke.mjs
# 3) 全量门禁
npx eslint . && npx vite build && node --test && node tests/smoke.mjs
```

单测至少三条：
1. `normalizeValue` 接受合法值、**拒绝非法值**（报错文案里要有字段名）；
2. `formatValue` 输出人读形态、空值输出空串；
3. 值能经 `mutateStore` 落盘并被 `dump` 原样读回（形状不变形）。

文档（**用户向**，agent 填数据时看的那份）：
- `assets/nx-sk/references/15-special-fields.md`：加一节「这个类型是什么 / 值的形状 / CLI 怎么写」；
- 若新增了专用命令（像 `entry table`），先在 action 里实现，再写进文档——
  `tests/unit/consistency.test.mjs` 会校验文档里出现的命令真实存在。

## 九、反面案例（真实踩过的）

| 现象 | 根因 |
| --- | --- |
| CLI 写进去是字符串 `"5"`，公式算不出来 | 漏了 `normalizeValue` 分支，走了 `String(raw)` 兜底 |
| 面板能填、`entry get` 显示 `[object Object]` | 新类型值是对象，但没在 `normalizeValue` 里 `JSON.parse`，也没在 `formatValue` 里格式化 |
| 字段加上了但面板不显示 | 字段的 `group` 指向了没声明的分组 → 归一化会自动补声明；但若手改了 store 且 key 重复，会被 `normalizeSection` 拦掉 |
| 新类型在半宽块里挤成一团 | 没加进 `WIDE_TYPES` |
