# nx-sk · 本机个人资源管理器

一句话：**把「你的信息」按条目存起来，用目录树组织；条目模板只负责初始化，CLI 与 Web 面板是同一套业务。**

数据落在 `~/nx-sk/`（可用 `NX_SK_HOME` / `NX_SK_STORE` 覆盖），**永远在仓库之外**。
首次运行只播种一个「字段样例」条目模板（`demo`）和一条示例条目；求职 / 项目 / 密钥 / 部署 / 平台 / 论文都是**条目模板预置**，
用时 `entry add --template <id>` 按条目模板初始化条目。条目模板建完就与条目脱钩，不再回刷。
左侧导航是**条目父子树**：有子条目就是文件夹，没有独立的条目模板容器。

> 0.43 术语：旧文档里的「条目模板」是重构前的容器；现在按语境读作**模板**（初始化蓝图）
> 或**目录**（条目父子关系）。命令组叫 `template *`，实际操作的是条目模板。

## 两条序列（先判，再动手）

- **A 序列 = 动作（do something）**：文件名就是一句动作——`A07-把PDF转成图文SOP` 就是「把 PDF 转成图文 SOP」这件事。
  有一件具体的事要做，照着做完。
- **B 序列 = 知识（名词）**：`B02-字段类型与格式` 是「字段怎么用」的手册，不是动作。要查值形状、放哪儿，翻它。

> 起名规矩：**A 一律是动词开头的动作**（填 / 整理 / 回写 / 存 / 收 / 排 / 搬 / 转），**B 一律是名词知识**。

## 三条核心不变量

1. **结构归条目，条目模板只初始化。** 条目自己持有字段结构（分组 + 字段）；
   条目模板在 `entry add --template` 时深拷贝一份结构，此后两边独立。条目模板后续改动不回刷条目。
   台账不拦写入——`--set 任意键=值` 一律能存，没见过的键自动登记（键就是键，中文也行）。
   但**没登记的值面板看不见**，所以「写新键」= 顺手登记。
2. **面板与 CLI 是同一套业务。** 面板能做的 CLI 都能做，参数名与错误码一致。
3. **失败抛异常（退出码 1），业务结果返回 `{status}`（退出码 0）。** `conflict` / `blocked` / `skipped`
   都是正常返回，看 `status` 而不是退出码。

## 第 0 步：先 `status` 拿上下文

每次会话开头、或换了一个话题 / 条目，先跑这一条：

```bash
nx-sk status                    # 默认条目 + 它这一支的条目（含 desc）+ 该怎么动的提示词
nx-sk status --json             # 同一份上下文的结构化形态（要精确取字段时用）
```

它一次回答三件事：**在操作哪条**（默认条目与祖先链）、**周围有什么**（广度优先的子条目，
最多 `entryScopeLimit` 条，默认 5；默认先带直接子条目，再往孙条目走）、**该怎么动**
（哪些命令能省略 `<ref>`、写值前该看什么）。默认输出就是提示词，不需要再翻文档。

- 没设默认条目：`status` 会给候选，并提示 `nx-sk setting set --set defaultEntry=<条目id或标题>`。
  先设再动，不要靠猜。
- 上下文被截断（「还有 N 条没带出来」）：先用 `entry context` / `entry list --parent` 下钻，
  不要凭标题猜。默认只带 5 条——超过 8 条 agent 就开始认串；该数在设置里可调（1–50）。
- 换了项目 / 话题：顺手把默认条目改到新条目，后面所有省略 `<ref>` 的命令才落在正确的地方。

### 默认条目如何影响命令

| 场景 | 省略 `<ref>` 时 | 必须显式给 id |
| --- | --- | --- |
| 读 / 改内容 | `entry get/update/table/history/field-history/add-field/field-update`、`entry context`、`source get/add/update` → 默认条目 | — |
| 新建子条目 | `entry add --parent <默认条目>` 是常见用法，但父级仍要写 | — |
| 破坏性动作 | —（刻意不回落） | `entry remove` / `entry move` / 改标题 / `save-as-template` |
| 密钥 | `key set/get/list/remove` 作用于 `secret` 的承载条目 | — |

> 破坏性动作不回落是设计：一次手滑的 `entry remove` 不该删掉默认条目整棵子树。
> 这张表对 A 序列各篇**同样生效**——各篇里的 `<条目>` 都遵循「省略 = 默认条目」，不逐篇重复。

### desc：每条条目的「一句话」

- 新建就写：`nx-sk entry add --title "名" --desc "这条是什么"`；补写：`entry update <id> --desc "…"`。
- 它不是字段：不进 `values`、不进完整度、不占块版式；`status` / `entry list` / `entry get` 会带出来，
  导出 / 导入也保留。
- 找还没写的：`nx-sk entry list --missing-desc`；`status` 也会报「其中 N 条还没写 desc」。
- 与 tag 的分工：tag 是**横切分类**（客户 / 部署 / 论文），desc 是**这一条自己的说明**，两者互补。

零知识主力命令：

```bash
nx-sk entry fields --template job --json    # 填之前先看台账，别猜字段名
nx-sk entry get                             # 省略 <ref> = 读默认条目（含 desc / 完整度 / 未填清单）
nx-sk entry update --set 字段=值              # 省略 <ref> = 改默认条目；先加 --dry-run
nx-sk entry add --title "新条目" --template job --parent <父条目> --desc "一句话说明"
nx-sk entry tree --json                     # 目录树（左侧导航同源）
nx-sk entry search --q "关键词" --json       # 轻量定位；找不到再新建
nx-sk template dump job --json              # 条目模板全量 + 条目 + 未填清单
nx-sk template list --json                  # 现有条目模板（先查后建）
nx-sk template reorder job,projects         # 重排条目模板（面板拖动排序的 CLI 入口）
```

## 字段速查（细节全在 B02）

| 类型 | 值 | 一句话 |
| --- | --- | --- |
| text / textarea / number / date / month / bool / select / tags | 标量 | `select.options` 是候选不是白名单 |
| secret | 密文对象 | 落盘 AES-256-GCM，读出默认原文，`--mask` 打码 |
| file | 附件 id **数组** | 物理文件在 `~/nx-sk/files/`，同 sha256 去重 |
| md | markdown 字符串 | 图片只认 `![说明](f_xxx)` 与 http(s) 外链；`- [ ]` 可勾 |
| entrylist | 行对象数组 | 列在字段定义的 `fields` 里声明，`sensitive` 列同样加密 |
| table | `{columns, rows, totals}` | 结构在数据里，可带计算列与表尾统计 |
| shortcut | 组 → 条目 → 按键 | 折叠条报组数/条数；`详细` 打开键位面板 |
| grill | `{questions:[…], ack}` | AI 写问题，用户在 Web 三态子页面逐条答；`ack.status=acknowledged` 才算确认 |
| source | 资料条目数组 | 每个条目模板自带的「原始资料」袋，不计完整度 |
| group | 无值（容器） | 分组**就是字段**：`keys` 引用成员；面板只渲染小标题 |

**键名像凭据（密码/口令/密钥/账号/token/apiKey/accessKey/secretKey…）→ 自动登记成 `secret`**，
所以「直接写账号密码」也不会明文躺盘。

## 凭据自动化（最短版，全文 A04）

- **场景凭据跟着场景走**：阿里云的密码写在 `deploy` / `platform` / 自建条目模板里，不要塞进 `secret`。
- **跨场景通用 key 进 `secret`**：`key set OPENAI_KEY sk-…`（`key *` 是 `entry *` 的糖，同名覆盖）。
- **要配置文件就出成品**：`entry get … --json` 取真值 → `scripts/render-config.js` 渲染 `${VAR}` → 落盘。
- **风险出口只有三个**：推 git / 打印给第三方 / 导出外发。本机文件带真值可以，但别进仓库、别进日志。

## 能力边界（什么时候不用）

- 只是随口问一句、不需要落盘——别动数据。
- 只要读一份 PDF 回答问题——直接读；用户说「保存这份文件里的 xx」才是反例（先挂原件再写字段）。
- 扫描件无文字层——先 OCR，别对着图片猜正文。
- 想找「面板上的 skill 页」——没有：skill 只走 CLI（`skill install` / `skill get`）。
- 要把密钥同步到云端/团队——只做本机落盘与本地导出，不做上传。

## 硬约束

- 所有写命令都有 `--dry-run`，先试运行；**删除不可撤销**——删条目模板/条目/附件前先
  `transfer export`（或面板「导出导入」→ 导出），这是唯一回退手段。
- 密文读出来默认原文（本机单人工具），投屏/截图才显式 `--mask`；把打码值写回会被拒绝。
- 导出包里是**明文凭据**（没有「打码导出」）：外发必须 `--passphrase` 整包加密，且只发可信对方。
- **绝不把密钥明文打进日志、提交进 git、或写进给第三方的输出。**
