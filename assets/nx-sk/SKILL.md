# nx-sk · 本机个人资源管理器

一句话：**把「你的信息」按栏目存起来，凭据就放在它该在的地方，CLI 与 Web 面板是同一套业务。**

数据落在 `~/nx-sk/`（可用环境变量 `NX_SK_HOME` / `NX_SK_STORE` 覆盖），**永远在仓库之外**。
首次运行按内置模板播种 6 个栏目：

| 栏目          | id              | 内容                                                                                                                                                       |
| ------------- | --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 求职          | `job`         | 求职用的个人信息档案（姓名/学历/求职意向/简历头像成绩单附件…约 80 个字段）                                                                                |
| 项目经历      | `projects`    | 一个项目一个条目：名称 / 角色 / 时间 / 技术栈 / 职责与亮点                                                                                                 |
| 实习/工作经历 | `internships` | 一段经历一个条目：公司 / 岗位 / 时间 / 职责                                                                                                                |
| 校内职务/实践 | `campus`      | 一条职务或实践一个条目                                                                                                                                     |
| 密钥          | `secret`      | **一张 KV 表**（`kv: true`）：一行一个键值对。**只放跨场景通用的 key**（见下节）                                                             |
| 部署配置      | `deploy`      | **一份配置文件一个条目**（Dockerfile / compose / k8s 清单）：正文即文件原文 + 放哪 + 哪些值要替换 + **这个场景自己的凭据清单** + 何时用。详见 [[50-deploy]] |

**这 6 个只是起点，不是固定清单**：栏目可以新建（`section add`，不给模板就是空栏目全自定义）、
可以加/删字段（`section update --add-field`，或直接 `entry update --set 任意键=值` 自动登记）、
也可以删掉整个栏目。内置模板共 **8 个**——除上面 6 个外还有
`platform`（容器平台：控制台链接 / 账号 / 密码 / 镜像，一个平台一个条目）与
`thesis`（毕业论文规范字段化），`section templates` 列出它们；
模板在栏目实例化时被**深拷贝**，此后各自独立演化，
模板后来的新增用 `section sync` 补（只增不改不删）。

## 核心不变量

1. **结构归栏目，值归条目：栏目持有「固定的结构」，条目只装「值」。**
   每个栏目持有一份**字段台账**（分组 + 字段：key / 中文标签 / 类型 / 是否密文 / 填写策略），
   它是**数据不是代码**、随栏目存在 store 里，所以 agent 与面板看到的字段永远一致——
   「这个栏目有哪些字段」永远只有一个答案，在栏目里；条目里的每一把键都能在那儿找到。
   **台账不拦写入**：`--set 任意键=值` 一律能存，没见过的键会**自动登记**进台账
   （键名就是它本身，中文也可以）——写新字段不必先改 schema，但**必须登记**：
   没进台账的值，面板按台账渲染时**看不见**（像「存了却没生效」）。
   台账的用处是「模板建议 + 你实际写过什么」，不是门禁。
   *违反会怎样*：反过来把它做成门禁，用户每换一个表单就要先改一次 schema ——
   而那正是「只想存个 kv」时最不想付的成本；而不登记就往条目里塞值，存了也看不见。
2. **面板与 CLI 是同一套业务。** 面板上能做的，CLI 都能做；两边参数名、错误码一致。
   所以「让用户在面板上点一下」和「让 agent 敲一条命令」是同一件事的两面。
   *违反会怎样*：只能靠字符串匹配猜错误，无法可靠分支。
3. **失败抛异常（退出码 1），业务结果返回 `{ status }`（退出码 0）。**
   `conflict` / `blocked` / `skipped` 都是**正常返回**，agent 要看 `status` 字段而不是退出码。
   *违反会怎样*：把一个「等用户决策」的冲突当成失败去重试。

## 凭据自动化（大胆写，别绕路）

**这是 nx-sk 的主用途：把账号密码这类东西存在它该在的地方，然后直接拿它产出能用的东西。**

### 一条场景的凭据，写在那个场景的栏目里

不要为了存「阿里云的密码」去动 `secret` 密钥栏目 —— **凭据跟着场景走**：

| 凭据类型                                                 | 放哪                                                                     | 为什么                                                     |
| -------------------------------------------------------- | ------------------------------------------------------------------------ | ---------------------------------------------------------- |
| 某个平台 / 项目的账号密码                                | **那个场景自己的栏目条目**（`deploy` / `platform` / 自建栏目） | 场景换了凭据就换，换的时候只改一处；取的时候一眼知道是谁的 |
| 到处都要用的通用 key（`OPENAI_KEY`、`GITHUB_TOKEN`） | **`secret` 密钥栏目**（KV 表）                                   | 跨场景复用，抽出来当全局环境变量用                         |
| 简历 / 头像 / 证书                                       | `job` 栏目的 `file` 字段                                             | 见「附件」一节                                             |

怎么写（**不需要先声明 schema**，键名像凭据就自动加密）：

```bash
nx-sk entry update "阿里云" --section deploy --set 账号=ops@example.com --set 密码='P@ss…'
```

**键名长得像凭据（密码 / 口令 / 密钥 / 账号 / token / apiKey / accessKey / secretKey…）时，
自动登记出来的字段直接就是密文字段**：落盘是 AES-256-GCM 密文，读出来默认原文。
所以「大胆写」不等于「明文裸奔」——**大胆的是操作方式，不是安全性**。

> 想要更明确的结构（一个场景多组账号），就声明一个**结构清单**字段，密码列标 `sensitive`：
>
> ```bash
> nx-sk section update mycloud --add-field '{"key":"creds","label":"凭据清单","type":"entrylist","group":"main","fields":[{"key":"name","label":"名称"},{"key":"user","label":"账号"},{"key":"pass","label":"密码","sensitive":true},{"key":"token","label":"令牌","sensitive":true}]}'
> nx-sk entry update "阿里云" --section mycloud --data '{"凭据清单":[{"名称":"控制台","账号":"ops","密码":"P@ss…"}]}'
> ```
>
> `deploy` 模板**自带**这个字段（`section sync deploy` 能给老栏目补上），自建栏目则要自己声明一次。
> 清单的行**列名用 key 或中文标签都认**（`名称` / `name` 等价）。

### 一条命令看全部凭据（跨栏目台账）

```bash
nx-sk entry keys                    # 所有栏目里的 链接/账号/密码/令牌/镜像 —— 值默认打码
nx-sk entry keys --reveal           # 明文（给自己看 / 喂给脚本）
nx-sk entry keys --section deploy --q 密码   # 只看某栏目、含"密码"的
```

这是「凭据散在各个栏目里」的对账表：改密码、找某个平台的入口，都从这儿过一遍。

### 需要配置文件，直接给

**nx-sk 的作用就是把凭据变成能用的配置。** 用户要 compose / k8s / .env / Dockerfile 时，
不要只丢一个模板让他自己填 —— **取真值、渲染、出成品**：

```bash
# ① 取真值（密文字段自动解密）
nx-sk entry get "阿里云" --section deploy --json      # → .values.creds[] / .values.密码 …
# ② 用真值渲染模板里的 ${VAR} 占位，产出配置文件
# ③ 落盘到项目里
```

渲染的机械步骤（`content` 是模板正文，`creds` 是这个场景的凭据）：

```bash
nx-sk entry get "阿里云" --section deploy --json > /tmp/e.json
node assets/nx-sk/scripts/render-config.js /tmp/e.json ./docker-compose.local.yml
```

脚本把 `creds` 里每行的「名称」当变量名（值取密码 / 令牌 / 账号），
把条目其它标量字段按字段 key 也当变量，替换正文里的 `${VAR}`（支持 `${VAR:-默认值}`），
最后报出**替换了哪些、哪些没解析**。已装 skill 的话脚本在
`~/.claude/skills/nx-sk/scripts/render-config.js`（在 nx-sk 源码仓库里是 `assets/nx-sk/scripts/`）。

**成品里带真值是可以的**（本机文件、没人看），但要守住两条：

- **别让它进 git** —— 仓库里提交的是**占位符版本**（`docker-compose.yml` 用 `${VAR}`，
  另附 `.env.example`），真值落在本机 `.env` / `*.local.yml`，并确保 `.gitignore` 盖住。
  nx-sk 的数据目录本身就在仓库之外，并且有测试钉住「`store.json` 不许被 git 跟踪」。
- **别把它打进日志 / issue / 聊天 / 给第三方的输出** —— 这一条才是硬边界。

### 「本机 = 安全」的准确口径

| 事实                       | 依据                                                               |
| -------------------------- | ------------------------------------------------------------------ |
| 凭据落盘是密文             | AES-256-GCM，每值独立 IV；`store.json` 里没有明文                |
| 数据不在任何仓库里         | `~/nx-sk/`，仓库外；仓库有测试钉住「store.json 不许被 git 跟踪」 |
| 面板只监听本机             | `127.0.0.1`                                                      |
| **风险出口只有三个** | ① 推到 git / 上传云端；② 打印到日志或贴给第三方；③ 导出包外发   |

所以口径是：**只要不推送到 git、不把明文交给第三方，剩下都是安全的** ——
在「本机单人自用」的前提下，这已经足够大胆，不必再自我审查一遍密码本身。

## 命令面（先跑这一条）

```bash
nx-sk bootstrap --json        # 版本 / 存储路径 / 栏目 / 设置 / 命令表，一次拿齐
```

零知识时的主力命令：

```bash
nx-sk entry fields --section job --json              # ① 看台账：模板建议字段 + 你写过什么
nx-sk entry update <条目id或条目名> --set 字段=值     # ② 直接写：字典里没有的键会自动登记
nx-sk section dump job --json                        # ③ 一个栏目的全部信息 + 每个条目的未填清单
```

**键就是键**：`--set 微信=xxx` 存下去就是 `微信`，不需要先翻译成英文 key。

`--set` 的键**可以用 key 也可以用中文标签**（`--set 电话=138…` 与 `--set phone=138…` 等价）。
一次写很多字段用 `--data @file.json`（`--data` 也接受内联 JSON）。

存/取**跨场景通用**的 key 走这四条（缺省作用在标了 `kv` 的栏目上，`--section` 可指定）：

```bash
nx-sk key set OPENAI_KEY sk-xxxxxxxx     # 写入（存在即覆盖，返回 created 告诉你是哪种）
nx-sk key get OPENAI_KEY                 # 取值：默认就是原文
nx-sk key get OPENAI_KEY --mask          # 投屏/截图时才打码
nx-sk key list                            # 所有键（默认原文）
nx-sk key remove OPENAI_KEY               # 删除，不可撤销 → 先 nx-sk transfer export
```

`key *` 是 `entry *` 的**语法糖**（同一套读写流程）。区别只有一个：
`key set` 遇到同名是**覆盖**，`entry add` 是报 `CONFLICT`。

**KV 栏目不许加字段**：它的形状就是一行一个键值对。想加东西就用 `key set <名称> <值>`
（在 KV 栏目里 `entry update --set 新键=值` 会被拒绝并告诉你该用哪条命令）。
**场景级的账号密码不要往这儿塞** —— 见「凭据自动化」。

附件（简历、头像、成绩单等二进制原件）走统一附件库，物理文件在 `~/nx-sk/files/`：

```bash
nx-sk file add --path "D:\简历\张三-简历.pdf"  # 默认把原件移动进库（--copy 仅复制）
nx-sk file list                                 # 台账：按栏目汇总 + 被引用情况
nx-sk file list --section none                  # 只看还没有条目引用的
nx-sk file restore f_xxxx                       # 可逆：移回原始位置并撤销台账
nx-sk file restore f_xxxx --to DIR --copy       # 或导出副本、库中保留
nx-sk file open f_xxxx                          # 系统默认程序打开原件
```

求职条目里的「简历附件 / 头像图片 / 成绩单 / 证书扫描件」是 `file` 字段，
它的值是**附件 id 的列表**——一个字段可以挂**多个**附件（简历多版本、头像多张）
（id 全局唯一 → 各条目互不串台；同内容去重后是同一条，可被多条条目共享）：

```bash
nx-sk entry update 张三 --set resumeFile=f_aaa,f_bbb   # 逗号分隔挂多个（也接受 --data 传数组）
nx-sk entry update 张三 --set resumeFile=f_aaa         # 只挂一个（存下来也是单元素数组）
nx-sk entry get 张三 --section job                # 每个附件各占一行：附件名 + 物理路径
nx-sk file get f_bbb                              # 反查「被引用：求职 / 张三 / 简历附件」
```

**上传 / 选择发生在栏目条目里**（Web 的表单字段可直接「上传文件」或从库里选）；
「附件」中心只负责**统一展示与库存管理**，由栏目驱动（筛选片 = 哪些栏目在引用附件 + 未引用），
**不预定义任何分类或槽位**，也不做指派。相同内容（sha256）自动去重，不重复占空间。

**看不到 `file` 上传字段？** 栏目字段台账是**持久化数据**——栏目实例化时深拷贝模板字段，此后独立演化，
所以模板**后来**新增的字段不会自动出现在已建好的栏目里。用 `nx-sk section sync <栏目>`（可先 `--dry-run`）
把模板新增的分组与字段补进来（只增不改不删）；面板侧是「栏目 → 编辑 → 同步模板字段」。

图文混排字段（`type: 'md'`）——SOP、操作手册、图文笔记用它。正文里贴图片：

```markdown
1. 登录容器平台

![容器平台登录页](f_aaa111)     ← 附件库 id，点开可放大
![外部架构图](https://example.com/a.png)   ← http(s) 外链
```

- **只认附件 id 与 http(s) 外链**：本地路径、`file://`、相对路径都渲染不出来（也会传不走）。
- 图片会**自动算作已引用**：`nx-sk file list` 里它们的 `usedBy` 指向引用它的栏目 / 条目 / 字段，
  不会因为「只出现在正文里」被列进「未引用」。
- 面板里支持 Ctrl+V、拖拽、附件库插图；插入光标处即时预览。
- 可勾选待办：`- [ ] 步骤` 在预览里就是勾选框，点一下写回正文。

结构清单字段（`type: 'entrylist'`）——一个条目要挂**多组 链接/账号/密码**这类密集结构时用它：
值 = 行对象的**数组**（变长，空行写入时自动剔除），列在字段定义的 `fields` 里声明；
声明 `sensitive: true` 的列与顶层敏感字段同一条边界（密文落盘、`--mask` 打码）；
行里的列名**用 key 或中文标签都认**。

```bash
# 建字段：列就是一份小字典（面板「新增字段」选「结构清单」会预填 名称/链接/账号/密码 四列）
nx-sk section update <栏目> --add-field '{"key":"accounts","label":"账号清单","type":"entrylist","fields":[{"key":"url","label":"链接"},{"key":"pass","label":"密码","sensitive":true}]}'
# 写入：值是行数组（--data 直接给 JSON；--set 认 JSON 串；行键写错当场报，不静默丢）
nx-sk entry update 张三 --data '{"账号清单":[{"链接":"https://…","密码":"…"}]}'
```

面板渲染成密集迷你表（直接增删行）；`entry get` 里清单一行一条、带列标签。口径见 [[10-sections-entries]]。

原始资料袋（`type: 'source'`）——**每个栏目都自带一个**的「乱入区」。值 = 一组资料条目
（`{id, kind, name, text|fileId|url, addedAt, note, mapped}`；kind = text / file / url）。
杂乱资料（邮件、截图、PDF 摘录、手抄的表）先**原样**丢进袋里，之后由 agent 或人
按栏目字段字典整理进上面的字段——「先乱入、后整理」因此成立：没有这个袋子，
用户只有两个坏选择：把乱数据硬塞进结构化字段（把结构搞脏），或干脆不存（信息丢了）。

```bash
nx-sk source list                       # 各栏目的袋概况
nx-sk source get <条目> --json          # 某条目的袋（item 明细 + 附件信息）
nx-sk source add <条目> --text "…"      # 加一条文字（原样存，不改写）
nx-sk source add <条目> --file <路径>   # 加一个文件（先进附件库，原件保留不搬走）
nx-sk source update <条目> --id <itemId> --mapped 字段key   # 标注「这条已整理到哪些字段」
nx-sk source ensure                    # 给老栏目补上这个字段（模板是后加的，老栏目没有）
```

面板上：条目表单底部一条**折叠条**「原始资料 · N 条」，点开是右侧抽屉（左清单、中正文），
文件可拖进去（也给了「选择文件」按钮与粘贴框——拖拽不能是唯一入口，WCAG 2.2 AA）。
三条纪律：**原文不改写**、**不确定就留空**、**敏感内容不进袋**（袋是明文的；
密码走场景栏目的密文字段，不进袋）。

**把袋子里的东西整理成字段**（agent 侧）有配套 skill：

```bash
nx-sk skill install sk-source     # 装到 ~/.claude/skills/sk-source
```

它讲的是双向同步：source → 字段（整理）与 字段 → source（回写留痕），
以及「哪些资料还没被整理过」怎么查（每条资料的 `mapped` 标记）。

**把 PDF 变成图文 SOP 栏目**（抽文字、按版面挑截图、建栏目、写图文步骤）有配套 skill，
含两个已验证的抽取脚本：

```bash
nx-sk skill install sk-pdf      # 装到 ~/.claude/skills/sk-pdf
nx-sk skill get sk-pdf          # 外部 agent 直接取全文
```

不装也能用（脚本零依赖，只需 PyMuPDF）：

```bash
python ~/.claude/skills/sk-pdf/scripts/pdf_probe.py <pdf>       # 先探查：有没有图、是不是扫描件
python ~/.claude/skills/sk-pdf/scripts/pdf_extract.py <pdf> --out /tmp/pdf-out
```

## 什么时候不用

- 用户只是随口问一句、不需要落盘 —— 别动数据。
- 用户只是**要读一份 PDF 的内容**（问"这文档讲了啥"）—— 直接读就行，别建栏目、
  别上传附件。先问一句要不要沉淀。
- 用户给的是**扫描件**（无文字层）—— 先 OCR，别对着图片猜正文（容易编造内容）。
- 想找「面板上的 skill 页」—— 没有：**skill 只走 CLI**（`nx-sk skill install` / `nx-sk skill get`），
  面板里不呈现它。
- 用户要把密钥**同步到云端/团队** —— nx-sk 只做本机落盘与本地导出，不做上传。
- 只是要看一眼面板 —— 提示 `nx-sk serve`，别用 CLI 重放一遍。

## 硬约束（动手前先记住）

- 所有写命令都有 `--dry-run`，先试运行再落盘；**删除不可撤销** —— 删栏目/条目/附件前先
  `nx-sk transfer export`（或面板「导出导入」→ 选中范围 → 导出），这是唯一的回退手段。
- 密文字段**落盘是密文，读出来默认是原文** —— 本机单人工具，自己看的东西不先拦一道。
  要打码形态（投屏 / 截图）显式加 `--mask`。
- 把打码后的值（含 `******`）当新值写回去会被拒绝 —— 那通常意味着「不修改」，什么都不传即可。
- 导出包里是**明文凭据**（`--no-secrets` 已移除，没有「打码导出」）；外发时必须
  `--passphrase` 整包加密，且只发给可信对方。
- **绝不把密钥明文打进日志、提交进 git、或写进给第三方的输出里。**
  「本机就安全」的豁免只到**本机文件**为止：真值渲染进配置文件是可以的，
  但那份文件要么不进 git（`.gitignore` + `.env`），要么只提交占位符版本。
