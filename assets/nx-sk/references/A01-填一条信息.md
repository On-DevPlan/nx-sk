# A01 · 填一条信息（条目优先）

> 用户说「记一下 / 改一下 / 补一个字段」时先读这篇。
> **先认这一条，再决定写哪儿**：条目是唯一内容节点，模板只是新建时的初始化蓝图。
> 不要一上来先建模板、先设计 schema——多数需求只是给已有条目补一个值。

## 一、先判断：这是「一条」还是「一类」

| 信号 | 做法 |
| --- | --- |
| 已经有明确落点（某个人 / 某个项目 / 某个平台 / 某个配置） | 直接找那条条目，读现状后改 |
| 新的一件事，但同类已有 3 条以上 | 建一条条目；需要同样结构时再选已有模板 |
| 新的一件事，只此一条 | 建空白条目即可，字段随写随登记 |
| 一次来了 5 件互不相关的事 | 拆成 5 条，见 `A02-整理一堆乱资料` |
| 一类结构要复用给很多条 | 才考虑新建/调整模板；模板建完不回刷旧条目 |

**条目优先的判定顺序：**

1. **先定位已有条目**（`entry search` / `entry list --tag` / `entry tree`）；
2. 找不到再 **`entry add`**，有合适模板就 `--template`，没有就空白起步；
3. 只有「很多条要共用同一套字段」时才动 `template *`；
4. 写特殊字段前先读对应的 field ref（见第三节路由表），不要凭印象塞 JSON。

## 二、四步写入（默认流程）

```bash
# ① 先找：标题、tag、字段值都能搜；找不到才新建
nx-sk entry search --q "关键词" --json
nx-sk entry search --tag 项目 --json

# ② 看这条现在有什么（字段 key / 中文标签 / 类型 / 完整度）
nx-sk entry get <条目id或名> --json
nx-sk entry fields --template <所属模板> --json

# ③ 新建（有合适模板才带 --template；模板只初始化）
#    --desc 是「这条是什么」的一句话：status / entry list 靠它认条目，别省
nx-sk entry add --title "条目名" [--template <模板id>] [--tags 标签1,标签2] --desc "一句话说明"

# ④ 改值：先 dry-run，再落盘
nx-sk entry update <条目id或名> --set 字段=值 --dry-run
nx-sk entry update <条目id或名> --set 字段=值
nx-sk entry update <条目id或名> --data @整份值.json
```

要点：

- **键可以用字段 key 或中文标签**；批量写用 key 更稳。
- **没登记过的键会自动登记**，但类型按值推断，面板可能长得不对；要精确控制就显式加字段。
- **`--set 字段=` 等于清空**；要清空多个用 `--unset a,b`。把打码值写回会被拒绝。
- 写多字段优先 `--data @file.json`：推荐扁平形状 `{"字段key":"值"}`；也兼容 `{"values":{"字段key":"值"}}`，但不要把 `entry get` 的完整结果（id/title/字段结构等）原样抄进去。
- 条目内新增字段：面板「＋ 添加字段」，或 `entry add-field`；它只影响这一条，不污染模板。

## 三、特殊字段：先读 field→ref，再写

普通标量（text / textarea / number / date / month / bool / select / tags）按上面的写入即可。
下面这些字段的值不是标量，**每种都有自己的形状和读写路径**：

| 字段 type | 什么时候用 | 专用 SOP |
| --- | --- | --- |
| `table` | 每行列结构可能不同、要类型/公式/统计 | `A10-记一张表` |
| `entrylist` | 列固定、行数不定的密集清单（账号/链接） | `A11-记一份结构清单` |
| `md` | 图文正文、步骤、待办、嵌截图 | `A12-写一段图文` |
| `grill` | 需要用户逐题拍板的确认单 | `A13-让用户逐条确认` |
| `shortcut` | 快捷键/键位库（组 → 条目 → 按键） | `A14-记一套快捷键` |
| `file` | 附件 id 数组（简历/头像/证书） | `A05-收一份附件` |
| `source` | 原始资料袋（先乱入、后整理、留痕） | `A03-把原件回写进条目` |
| `secret` / `sensitive` | 密码/token/证件号，密文落盘 | `A04-存密钥和凭据` |
| 条目归类 / 按标签检索 | 跨模板的语义标签、快速定位 | `A15-标签与搜索` |

> 选择口径：列会不会每条都不一样？会 → `table`；不会 → `entrylist`。
> 附件是二进制原件 → `file`；只是正文里引用图片 → `md` + 附件库。

## 四、tag：条目天生带标签

- **模板默认 tag**：模板新建时默认 `[模板 id, 模板标题]`；可用 `template update <id> --tags ...` 整体替换。
- **条目继承**：`entry add --template <模板>` 自动带上模板 tags；`--tags` 是追加，不覆盖模板语义。
- **条目自己的 tag**：`entry update <条目> --tags 客户,紧急` 整体替换条目 tags。
- **检索**：`entry list --tag 客户`；多个 tag 默认任一命中，`--tag-mode all` 要求全中。
- **快速搜索**：`entry search --q "词"` 扫标题、模板标题/描述、tag、字段标签和非敏感字段值；
  只返回定位信息（id / 标题 / 模板 / tags / 命中的字段 key），不返回完整 values。

## 五、Web 面板同一条路

- 左侧是**条目父子树**：点节点 = 选中条目；有子条目就是文件夹。
- 条目页顶栏只保留保存/放弃和一个「更多」菜单；变化历史、存为模板、删除都在菜单里。
- 条目名下方显示继承来的 tag；模板页工具条显示模板默认 tag。
- 块布局拖动、字段增删、密文打码都与 CLI 是同一套 action，不存在「面板能做 CLI 不能」。
- 新建条目弹窗只决定「建在哪个父级 + 用哪个模板初始化」；建完独立演化。

## 六、写完自检

```bash
nx-sk entry get <条目> --json          # 值、tags、完整度、未填清单
nx-sk entry search --tag <标签> --json # 同类条目是否被正确归档
nx-sk template dump <模板> --json      # 这类条目的整体缺口（不是单条）
```

给用户汇报时说清三件事：**落在哪条 / 改了哪些字段 / 哪些值没敢写（缺依据）**。
不确定的值留空，不要编造；敏感值写前确认来源。

## 七、常见错与正确姿势

| 现象 | 原因 | 改法 |
| --- | --- | --- |
| 写进去了但面板看不见 | 键没登记成结构行 | 看 `entry get` 的 `entryFields`；用 `entry add-field` 显式登记 |
| `entry add` 报 CONFLICT | 同模板已有同名条目 | 改用 `entry update`，不要重复 add |
| 想清空却写成了字符串 `"null"` | `--set 字段=` 才是清空 | 用 `--unset` 或空值 |
| 表格/清单写入被拒 | 值形状不对 | 读对应 A10/A11，按列 key 写 |
| 打码值回存报错 | 打码占位不是真值 | 不修改就什么都不传 |
| 新建条目后模板改动不生效 | 模板只在创建时深拷贝 | 这是设计；要补结构用 `template sync` 或条目内加字段 |
