# A07 · 把 PDF 转成图文 SOP

> 一份手册 / 用户指南 / 操作说明，要变成「新手打开就会做」的 nx-sk 栏目时走这条线。
> 只是要读 PDF 回答问题 → 直接读，不落盘。

## 三条铁律

1. **先看清版面，再动手**：截图是 SOP 的一半，按页码猜位置必错。
2. **截图上传成附件，正文用 `![说明](附件id)` 引用**：本地路径与外链都不算正式引用。
3. **密码账号不进 md**：md 是明文渲染；用 `sensitive` 字段，正文写「见〈某字段〉」。

## 六步

```bash
python scripts/pdf_probe.py <pdf>                      # ① 探查：页数 / 每页图数 / 有无文字层
python scripts/pdf_extract.py <pdf> --out /tmp/pdf-out  # ② 抽文字 + 图片占位（按版面 y 坐标）
python scripts/pdf_extract.py <pdf> --images-only --img-dir /tmp/pdf-imgs  # ③ 挑图
nx-sk file add --path <图> --note "p6 第1图" --json      # ④ 图进附件库
nx-sk section add <id> --title "<标题>"                  # ⑤ 建栏目（结构见下节）
nx-sk entry update <条目> --set "操作手册=$SOP"           # ⑥ 写正文并回读验收
```

脚本只依赖 **PyMuPDF**（`get_image_rects()` 给图片在页面上的摆放矩形，别的库给不出）。
缺依赖：`python -m pip install pymupdf`。扫描件（无文字层）先 OCR，不要对着图片猜正文。

## 结构设计（摘要）

聚合类文档的标准栏目：简介 / 准备材料 / 入口与地址 / 操作手册 / 常见问题 / 自检清单，
三层账号体系各一个 `sensitive` 字段。细节见下节「栏目结构」。

## 抽取原理：为什么按版面位置来

抽取原理：为什么必须按版面位置来

### 三个顺序，只有一个是对的

PDF 里取文字和取图片，各自有「自己的顺序」，都不等于人读到的顺序：

| 来源 | 它给的顺序 | 问题 |
| --- | --- | --- |
| `page.get_text()` | 内部文本块顺序 | 通常还行，但和图的相对位置无关 |
| `page.get_images()` | xref 顺序（资源表顺序） | 与版面完全无关，纯技术顺序 |
| `page.get_image_rects()` | 页面上的摆放矩形 | ← **只有这个带位置信息** |

于是做法是：把文字块和图片矩形都换算成「页面坐标 + 类型」，
放进同一个列表按 `y0` 排序再拼。

实测（川农容器平台指南第 6 页）：

```text
文字块  y= 342  2.3 堡垒机用户指南
文字块  y= 381  学校分配的容器资源无法直接访问，需通过堡垒机进行访问…
文字块  y= 413  堡垒机地址：https://blj.sicau.edu.cn
图片    y=  78 → 315
图片    y= 445 → 702
```

排序后得到 `图(78) → 说明(342) → 说明(413) → 图(445)` —— 这就是人读到的样子。
若按 xref 顺序出图，就会变成 `图(445) → 说明(342) → 图(78) → 说明(413)`，图全配错。

### 图片编号为什么是 `页码_页内序号`

`006_1` = 第 6 页第 1 张。好处：

- 挑图时用编号对话（"留 006_1、006_2、012_1"）比描述画面内容更不容易出错；
- 事后核对"这张图到底来自哪页"一眼就知道，不用回头翻 PDF；
- 上传后写进 `note`，图与来源的对应关系留在库里。

页内序号按 `get_image_rects()` 返回的顺序（同页多图时按上→下），
不是按 xref —— 否则同一页两张图谁在前谁是 1 就不确定了。

### 装饰件要滤掉

`MIN_IMG_W = 200` / `MIN_IMG_H = 100`（**显示尺寸**，不是像素尺寸）：

- 页眉 logo、分隔线、纯色块宽度接近整页而高度几十像素；
- 真正的界面截图显示宽度约 400pt、高度 200pt 以上。

**注意用显示尺寸判断**：同一张图内嵌像素可能是 1425×701，但在页面上只显示成 415×293。
拿像素尺寸判断会漏掉「像素很大但只是小图标」和「像素一般但页面上的大截图」两类偏差。

漏滤的代价不大（多几张图，人工挑掉即可），错滤的代价是**丢步骤** —— 所以宁可放宽。

### 文字块的处理

- 只取 `b[6] == 0` 的块（1 = 图片块，已单独处理，否则重复）；
- 块内换行**保留但逐行 trim**：PDF 的硬换行常把一句话拆成两行，
  但直接 join 会粘成一坨，所以按行输出、行间留空；
- 空块直接丢 —— 大量空块是排版留白，不输出能显著减少噪声。

脚本不做的事：不猜标题层级、不改写措辞、不纠错别字。
**整理措辞是人的活**，脚本只负责把版面原样搬出来。

### 扫描件（无文字层）

`pdf_probe.py` 会列出无文字层的页码。整份都没有就是扫描件，
必须先 OCR（转成带文字层的 PDF）再走本流程 —— 否则抽出来是空 markdown，
只有图片占位符，正文得靠人对着图重写。

部分页缺文字层（比如附录是扫描的）可以混合处理：那些页只出图占位，
但要**明确告诉用户这部分正文缺失**，别让它看起来像原文就这么短。



## 栏目结构：新手照着能做完

栏目结构：怎么设计才「新手照着能做完」

### 不要照抄 PDF 的目录

手册目录是给**已经会的人**翻的；新手需要的是「我现在该干什么」。
所以结构要按**操作流**重排，而不是按文档作者的章节划分。

聚合类信息源（平台指南、SOP 手册）的标准六段：

| 字段 | 类型 | 为什么必须有 |
| --- | --- | --- |
| 简介 | md | 这是什么、能干什么、文档版本 —— 让新手知道自己在哪 |
| **准备材料** | md | **动手前要准备什么**：登录哪些网站、认证哪几层、装哪些工具、各环境用哪个执行器 |
| 入口与地址 | md | 所有 URL 一条一行，避免到处找链接 |
| 操作手册 | md | 图文 SOP 主体，按任务分步骤，每步配图 |
| 常见问题 | md | 报错原文 → 原因 → 处理，新手卡住时先查这里 |
| 自检清单 | md | `- [ ]` 可勾选项，做完打勾，确认真的完成了 |

**「准备材料」是最容易漏、又最影响成功率的一段。** 新手按操作手册做到第三步
才发现「原来要先装 VPN」，整份文档的可信度就没了。

### 账号体系怎么拆

三类账号各自一个 `sensitive` 字段，别混在一起：

```jsonc
{
  "keys": [
    { "key": "平台账号",     "label": "容器平台账号", "type": "text", "sensitive": true },
    { "key": "平台密码",     "label": "容器平台密码", "type": "text", "sensitive": true },
    { "key": "认证账号",     "label": "川农 e 认证账号", "type": "text", "sensitive": true },
    { "key": "认证密码",     "label": "川农 e 认证密码", "type": "text", "sensitive": true },
    { "key": "堡垒机账号",   "label": "堡垒机账号",   "type": "text", "sensitive": true },
    { "key": "堡垒机密码",   "label": "堡垒机密码",   "type": "text", "sensitive": true }
  ]
}
```

在「准备材料」里**点名引用**：

```markdown
### 动手前先确认

- 容器平台：用〈容器平台账号〉/〈容器平台密码〉登录
- 川农统一认证：用〈川农 e 认证账号〉/〈川农 e 认证密码〉，与平台账号**不是同一套**
- 堡垒机（校外必须）：先连 UniVPN，再用〈堡垒机账号〉/〈堡垒机密码〉
```

### 分组（groups）怎么用

把六段放进 2–3 个分组，条目列表才不糊：

- **入门**：简介、准备材料、入口与地址
- **操作**：操作手册（可以按任务拆成多个条目）
- **排错**：常见问题、自检清单

条目多于一个时（一份 50 页手册通常要拆），
**一条 = 一个完整任务**（「怎么部署一个服务」比「部署」有用），
而不是「一条 = PDF 的一章」。

### 多页长文档：主条目 + 子条目

- 一个**总览条目**放简介、准备材料、入口与地址、自检清单 —— 新手从这里开始；
- 每个大任务一个**子条目**放各自的图文步骤。

这样新手先读总览就知道整体要干什么，再按需进子条目，不必一次读完 50 页。

### 可直接粘贴的建栏目命令

```bash
nx-sk section add <栏目id> --title "<标题>" --description "<一句话说明>" --json

## 建字段（分组 / 类型 / 是否密文）
nx-sk section update <栏目id> \
  --add-field '{"key":"简介","label":"简介","type":"md","group":"g1","groupTitle":"入门"}' \
  --add-field '{"key":"准备材料","label":"准备材料","type":"md","group":"g1","groupTitle":"入门"}' \
  --add-field '{"key":"入口与地址","label":"入口与地址","type":"md","group":"g1","groupTitle":"入门"}' \
  --add-field '{"key":"操作手册","label":"操作手册","type":"md","group":"g2","groupTitle":"操作"}' \
  --add-field '{"key":"常见问题","label":"常见问题","type":"md","group":"g3","groupTitle":"排错"}' \
  --add-field '{"key":"自检清单","label":"自检清单","type":"md","group":"g3","groupTitle":"排错"}' \
  --json

## 账号类字段一律 sensitive: true（密文落盘）
nx-sk section update <栏目id> \
  --add-field '{"key":"平台密码","label":"平台密码","type":"text","group":"g0","groupTitle":"账号","sensitive":true}' \
  --json
```

`--add-field` 遇到同名 key 会报冲突；先 `nx-sk entry fields --section <栏目id> --json`
看已有字段，别重复登记。

### 写 md 字段的实操

md 内容往往几百行、有反引号和换行，直接 `--set` 会被 shell 折腾。用文件传：

```bash
SOP="$(cat /tmp/sop.md)"
nx-sk entry update <条目名> --set "操作手册=$SOP" --json
```

Windows（Git Bash）下多行内容推荐：

```bash
SOP="$(cat /tmp/sop.md)"
nx-sk entry update <条目名> --set "操作手册=$SOP" --json
```

同一段内容要同时进多个字段时，写一次变量复用，别手抄三遍 —— 抄错一处两边就不一致了。
