# B04 · 项目组织架构与布局（项目条目怎么搭）

> 要为一个真实项目建库、或觉得「条目越建越乱、找不到东西」时读这篇。
> 这里讲**项目在 nx-sk 里怎么组织**；字段值形状看 B02，单条写入看 A01。

## 一、先定「项目根」，再谈子条目

一个项目 = **一个项目根条目** + 它的子条目树。不要把项目的每个文档都建成根条目：
根条目是入口，子条目是分区，层级就是导航。

```
项目根（条目：某项目）
├─ 01 需求与范围
├─ 02 设计与决策
├─ 03 开发与配置
├─ 04 验收与证据
└─ 05 资料与附件
```

- 项目根只放「一眼要看到」的字段：名称、状态、负责人、起止、目标、当前阶段。
- 子条目优先按**阶段/职责**分，不要按文件类型分（「所有 PDF」放一起，读的时候没有上下文）。
- 子条目可以继续嵌套，但**三层足够**：项目 → 分区 → 具体事项；再深就说明该拆项目了。

## 二、建法（条目优先）

```bash
# 1) 项目根：没有合适模板就空白起步，字段随写随登记
nx-sk entry add --title "某项目" --tags 项目,进行中

# 2) 分区：建成项目根的子条目
nx-sk entry add --title "需求与范围" --parent 某项目 --tags 项目,需求
nx-sk entry add --title "设计与决策" --parent 某项目 --tags 项目,设计
nx-sk entry add --title "验收与证据" --parent 某项目 --tags 项目,验收

# 3) 把项目根设成默认条目：这个项目的省略 <ref> 命令都落在它上面
nx-sk setting set --set defaultEntry=某项目
nx-sk status                      # 复核：默认条目 + 分区（默认最多 5 条，多了先下钻）
```

- **父子关系**决定左侧导航；模板只决定初始字段，不当文件夹用。
- 同一类分区在多个项目复用，再把它的字段结构 `entry save-as-template` 存成模板。
- 项目根 tags 用 `项目` + 项目代号；分区用 `需求/设计/验收` 这类跨项目语义 tag，便于横向检索。
- **换项目就换默认条目**：`settings.defaultEntry` 是持久化的「当前位置」，它不会因为你在聊天里换了话题
  而自动变。忘了换的后果是「改 A 项目」写进了 B 项目（见 `B03-踩坑合集` 第 13 条）。

## 三、每层放什么

| 层 | 放什么 | 不放什么 |
| --- | --- | --- |
| 项目根 | 目标、范围、负责人、状态、关键链接 | 大段正文、每个文件的细节 |
| 分区 | 该阶段的索引、决策记录、清单 | 另一棵完整项目树 |
| 具体事项 | 一条可独立完成/验收的事 | 多件事塞一条 |
| 资料袋 | 原始邮件/截图/PDF（先入袋后整理） | 已整理的结构化结论（那进字段） |

判断「一件事要不要独立成条」：**它会单独被完成/使用吗？有自己的时间/状态吗？删掉它另一条还完整吗？**
三个都「是」就独立；否则是父条目的属性。

## 四、布局：导航与阅读分开

- **左侧树 = 组织架构**：只表达父子与顺序；拖拽可调同级顺序、拖进节点成为子条目。
- **条目页 = 布局**：一个分组一块面板、一个字段一个块；块可拖宽/换行/调序，版式自动保存。
- **两种视图**：块布局适合日常阅读与图文；表单视图适合长文、表格字段多时逐项填。
  入口在正文版式栏右侧的「更多」菜单里，不占常显版面。
- 布局是显示关系，不是数据结构；改布局不会改值，也不会影响别的条目。
- 模板页的布局只影响「用该模板新建的条目」的默认编排，已有条目有自己的版式。

## 五、项目级检索

```bash
nx-sk entry tree --json                    # 整棵项目树（左侧导航同源）
nx-sk entry list --tag 项目 --json         # 所有项目根
nx-sk entry search --tag 验收 --json       # 跨项目的验收分区
nx-sk entry search --q "某项目 决策" --json  # 标题/字段值定位
```

- 项目代号、阶段、分区类型都做成 tag；不要只靠标题前缀。
- 搜到条目后先 `entry get` 看现状，再改；不要凭搜索结果里的摘要直接覆盖。

## 六、常见乱法

| 症状 | 根因 | 调整 |
| --- | --- | --- |
| 根目录几十条，滚动找不到 | 把文档都建成根条目 | 收一个项目根，文档挂子条目 |
| 项目之间串味 | 所有东西共享一个「资料」父级 | 每个项目自己的资料袋/子条目 |
| 同类分区字段不一致 | 每次手搭字段 | 先定一个分区模板，再复用 |
| 条目里塞三件事 | 拆条判据没做 | 按「独立完成/时间状态/删除后完整」拆 |
| 树深到点不动 | 超过三层 | 拆项目，或把细节收进 md/table |
| 改着改着写进了别的项目 | 默认条目还停在上一个项目 | 换项目先 `setting set --set defaultEntry=<项目根>`，`status` 复核 |

> 组织架构是**给人读的导航**，不是数据库范式。宁可少一层、字段宽一点，也不要为了「整齐」把一条内容切成五条碎片。
