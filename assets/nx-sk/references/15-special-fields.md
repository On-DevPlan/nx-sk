# 特殊字段：值不是标量的那几种

大多数字段的值是标量（一行字、一个数字、一个日期）。这一篇只讲**值不是标量**的字段，
以及它们各自的规则、写入时的体检、空值与默认值怎么处理：

`table`（表格）· `entrylist`（结构清单）· `md`（图文）· `file`（附件）· `source`（原始资料袋）· `secret`（密文）

> 为什么要单独一篇：这些字段的**值形状**决定了怎么读、怎么写、怎么在面板上编。
> 把它们当普通字符串塞进去，最常见的后果不是报错，而是「存进去了但面板看不见」——
> 那比报错难查得多。

## 速查

| type | 值形状 | 结构（列）归谁 | 面板怎么编 | 读它 |
| --- | --- | --- | --- | --- |
| `table` | `{v, columns, rows, totals?, summary?}` | **数据自己**（字段定义只给初始列） | 表格控件 + 「列设置」 | `entry table` / `entry get` |
| `entrylist` | `[{列key: 值}, …]` | 字段字典的 `fields` | 密集迷你表（直接增删行） | `entry get` |
| `md` | 一段 markdown 字符串 | — | 图文编辑器（Ctrl+V 贴图） | `entry get`（图片还原成路径） |
| `file` | `[附件id, …]` | 字段字典的 `kind` / `maxItems` | 附件选择器（上传 / 从库里选） | `entry get`（附件名 + 物理路径） |
| `source` | `[{id, kind, name, text\|fileId\|url, addedAt, …}]` | 内置（每个栏目自带一个） | 底部折叠条 → 右侧抽屉 | `source get` |
| `secret` | 一个字符串（落盘是密文） | — | 输入框 | `key get` / `entry get` |

共同点：**写入即校验**（不合法就整条拒绝，不会存半条）、**空值有明确语义**、
字段值只在这一处定义（面板与 CLI 不会各理解一套）。

---

## `table` 表格

### 结构归数据，不归栏目

```json
{
  "columns": [
    {"key":"task","label":"任务","type":"text"},
    {"key":"state","label":"状态","type":"select","options":["未开始","进行中","已完成"]},
    {"key":"done","label":"已办","type":"bool"},
    {"key":"hours","label":"工时","type":"number"},
    {"key":"rate","label":"单价","type":"number","total":"avg"},
    {"key":"cost","label":"费用","formula":"hours * rate","unit":"元"}
  ],
  "rows": [{"task":"写文档","state":"已完成","done":true,"hours":2,"rate":100}],
  "totals": [{"label":"完成率","expr":"pct(countTrue(col(\"done\")), n)","unit":"%"}]
}
```

- **列定义、行、公式、统计配置全在值里**。字段字典里的 `columns` 只是**初始列**
  （新建条目时表格长什么样），条目一旦有了自己的 `columns` 就以数据为准。
  所以「这一条想多一列」不必改 schema，也不会影响同栏目其它条目。
- 值可以整体是 `{v:1, columns, rows}`，也可以是**行数组**（列取初始列或从行推断）。
- 必填的只有「能自洽」：有行就必须有列；没列没行 = 空（见下面「空与默认」）。

### 列（column）的每个键

| 键 | 说明 |
| --- | --- |
| `key` | 列标识，也是公式里的变量名。中文可以，但不能有空白 / `/` `\` / `..` |
| `label` | 表头显示名。**中文列名也能直接当公式变量**（`工时 * 单价`） |
| `type` | `text` \| `textarea` \| `number` \| `bool` \| `select` \| `date` \| `month` \| `tags` |
| `formula` | 给了就是**计算列**（不落盘、不可编辑、读时按顺序现算） |
| `options` | 仅 `select`：候选项数组，**必须给**；写入时值必须在列表里 |
| `total` | 表尾这一格怎么算：`sum` `avg` `min` `max` `count` `countTrue` `countFalse` `distinct` `median` `first` `last` `none` |
| `sensitive` | `true` = 密文落盘（与顶层敏感字段同一条边界）；计算列不能是密文列 |
| `width` / `align` / `precision` / `unit` / `hint` | 显示用：列宽(px) / 对齐 / 小数位(0-8) / 单位 / 悬停提示 |
| `default` | **新增行时的初值**（按类型强转；`0` / `false` 都合法；不写进已有行） |

未声明 `total` 时的默认：数字列 `sum`、勾选列 `countTrue`、其它不统计。

### 公式：JS 表达式，不是自造语法

公式只被包成 `return ( … )` 求值，所以**语句写不进来**（`for` / `var` 在这里=语法错）。

- 变量：列 `key`、中文 `label`、`row` / `行`（原值，空格子是 `null`）、`rows` / `表`（整张表）、
  `i`（行号）、`n`（行数）；`col("单价")` 取一整列。
- 内建：`sum avg min max count countTrue countFalse distinct uniq median first last join`
  / `round floor ceil abs pct ratio clamp` / `toNum isBlank ifEmpty fixed`
  / `Math Number String Boolean Array Object JSON Date`。
- **顺序**：计算列按声明顺序算，只能引用排在它**前面**的列（引用自己或后面的列 = 成环，直接拒绝）。
- **空格子**在短变量里当 `0` / `false` / `''`（`hours * rate` 不会因为空格子变 NaN）；
  要判「到底填没填」用 `isBlank(row.hours)` 或 `row.hours === null`。
- 取不到全局：`window` / `document` / `process` / `fetch` / `require` 一律报「不存在的名字」。
  这不是安全沙箱（公式是数据所有者自己写的），而是把写错的边界前移。

### 统计：两个轴

1. **列上的 `total`** → 表尾那一格。多种统计方式会自动分组成多行
   （`sum` 与 `countTrue` 都是「合计」，`avg` / `max` / `median` 各成一行）。
2. **值里的 `totals`** → 整表表达式行，如
   `{"label":"完成率","expr":"pct(countTrue(col(\"done\")), n)","unit":"%"}`，
   也可写 `{"label":"合计","agg":{"工时":"sum","费用":"sum"}}`（写了 `agg` 就接管整块表尾）。

`summary: false` 关掉整块表尾；`totals: []` 同样表示「不要表尾」。
统计**不落盘**，每次读现算——不会出现「存下来的合计和现在的数据对不上」。

### 写入即体检（不通过就不保存）

写入路径（`section update --add-field`、`entry add/update`）会对**每一条公式**做一次
静态体检：拿一行空值当探针跑一遍，只拦**与数据无关**的错：

| 拦（定义/数据写错了） | 放行（这条数据不巧，渲染时逐格报） |
| --- | --- |
| 语法错：`hours *` | 除以 0 → `#错误：结果不是有限数字` |
| 名字解析不到：`qty` 打错、引用自己或后面的计算列、`col("不存在的列")` | 对空格子做类型操作抛的错（换个数据就没事） |
| 结果不是单值：返回数组 / 对象（该用 `join`） | |

列、行、默认值、下拉候选、`total`、`totals` 全部在这条路径上校验；
**面板与 CLI 走同一个函数**，不可能出现「面板能存的列，CLI 存不进去」。

### 空与默认

「清空」= 清掉**行**。列还留不留，看你有没有在字段定义里给初始列：

| 写入 | 结果 |
| --- | --- |
| `--set 表=` / `[]` / `{}` / `{"columns":[],"rows":[]}` | 清掉所有行。**没有初始列**时值 = `null`（字段真空了）；**有初始列**时留下骨架（列在、行空） |
| `{"columns":[…],"rows":[]}` | 骨架：列齐、没有行，下一步直接填 |
| `{"columns":[],"rows":[{…}]}` | **报错**：有数据没列，没法强转 |
| 全空行 | 写入时剔除（不占位） |

默认值只在**新增行**时用（面板「添加行」按列的 `default` 预填），不会回头改已有行；
字段级的默认是：初始列 + 表尾自动统计（数字 sum / 勾选 countTrue）+ 列类型默认 text。

### 常见错 → 改法

| 报错 | 改法 |
| --- | --- |
| `公式里用了不存在的名字「qty」…可用的名字：a、b` | 列名打错，或那列还没加 |
| `「x」是计算列…只能引用排在它前面的列` | 把被引用的计算列往前挪 |
| `列「密码」既是密文列又是计算列` | 计算列不落盘，加密没意义；二选一 |
| `列「状态」是下拉框（select），必须给 options` | 补 `options`，或把类型改回 `text` |
| `不在候选里（可选：…）` | 写入的下拉值不在 `options` 里 |
| `需要数字，收到「两小时」` | 数字列只能写数字（`1,200` 这种千分位也认） |
| `有 N 行数据却没有任何列` | 把 `columns` 一起写进值里 |

## `entrylist` 结构清单

- 值 = **行对象的数组**，列在字段字典的 `fields` 里（`{key, label, sensitive, hint}`）。
- 适合「一个条目挂多组 链接/账号/密码」这类**列固定、行变长**的密集结构。
- 列名用 key 或中文标签都认；全空行剔除；`sensitive: true` 的列密文落盘。
- 与 `table` 的分界线：**列会不会每条都不一样 / 需不需要类型和计算**。会 → `table`；不会 → `entrylist`。

## `md` 图文

- 值 = 一段 markdown 正文；图片用 `![说明](f_xxx)` 引用附件库里的图（外链也直接显示）。
- 正文即真相：预览里勾选待办就是改正文那一行的 `[x]`，没有第二份「勾选状态」。
- `entry get` 会把本地图片引用还原成「[图片: 说明] 本地路径」，方便 agent 直接读文件。

## `file` 附件

- 值 = **附件 id 的列表**（不是路径），一个字段可挂多个；id 全局唯一，原件的物理路径由附件库管。
- `sensitive` 不适用（附件本身不是密文）；`maxItems` 限个数。
- 上传 / 选择发生在**字段里**；`nx-sk file get <id>` 可反查被谁引用。

## `source` 原始资料袋

- 每个非 KV 栏目自带一个：杂乱资料先**原样**入袋（不改写），之后按字段字典整理。
- 不计完整度（`fill: optional`）；袋里是明文，**敏感内容不要进袋**。

## `secret` 密文

- 值是一个字符串，落盘 AES-256-GCM 密文；读出来默认原文，`--mask` 打码。
- 键名像凭据（密码 / token / key / 账号…）时**自动**建成这种字段，不必先声明 schema。

---

## 共同规矩

1. **密文边界只有一条**：`sensitive` 字段 / `entrylist` 与 `table` 的 `sensitive` 列，
   都是密文落盘、默认原文、`--mask` 打码。面板把打码值原样回传时保留原密文（不把掩码存成新值）。
   *已知限制*：打码状态下若两格打码值一模一样（短密码全是星）又拖动了行，无法判断谁是谁——打码时别调行序。
2. **空只有两种落盘形态**：`null`（结构 + 数据都空）或「只含 `columns` 的骨架」（结构在、行空）。
   写入什么形态进去（`''` / `[]` / `{}`）都会被归一，读出来不会出现半吊子形状 ——
   所以「值是不是空」判 `null` 就够，不必再猜 `[]` 还是 `''`。
3. **完整度只看「有没有数据」**：有列没行的表算**没填**（不会把进度撑满），但它的骨架会照常带出去。
4. **写入即校验**：类型、候选值、公式、默认值全部在写入路径上验；错就整条拒绝并给出**能照着改**的话。
5. **面板与 CLI 是同一套业务**：这里写的每条规则对两边都成立，没有「面板能存、CLI 存不进去」的列。
