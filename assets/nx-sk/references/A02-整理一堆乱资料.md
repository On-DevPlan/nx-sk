# A02 · 整理一堆乱资料（条目优先，模板按需）

> 有一段话、聊天记录、链接、表格、截图清单，用户说「帮我存起来 / 整理进 nx-sk」时走这条线。
> 已经有明确条目模板与字段时不用走这里，直接 `entry add` / `entry update`。

## 三条铁律

1. **先条目，后模板**：先在 `entry search` / `entry tree` 里看这批东西能不能挂到已有条目；只有「同类要建多条、字段要复用」时才新建模板。不要为了整齐先造一个空模板。
2. **结构先定，值后填**：确定要新建模板时，先给用户看「复用/新建哪个模板 + 哪些字段 + 预计几条」，拍板后再写盘；已有条目则直接补值。
3. **原文不丢**：杂乱原件先进条目自带的「原始资料」袋（`source`），再整理进字段；摘要可以写，原文不能只剩摘要。

## 第 0 步：先 `status` 看「这批该挂在谁的下面」

```bash
nx-sk status
```

乱资料最常见的错不是字段填错，而是**挂错父级**：明明该进「某项目」，却建在根上，
以后再想按项目看就翻不出来。

- `status` 给出默认条目与它的子条目（含 desc）——如果这批资料就是这个条目的事，
  直接把子条目建在它下面（`entry add --parent <默认条目>`）。
- 上下文被截断说明条目已经多到容易认错：先 `entry context <候选父级>` 看清楚再建，
  别在根上堆一批同名条目。
- 这批资料属于别的项目：先 `nx-sk setting set --set defaultEntry=<那个条目>`，
  把工作位置换过去，再按下面的五步走。

## 五步

```bash
nx-sk entry search --q "<关键词>" --json             # ① 侦察：已有条目里有没有能接的（含默认条目这一支）
nx-sk entry tree --json                              #    看这批资料该挂哪个父级
nx-sk template list --json                           #    再看有没有能复用的模板
nx-sk entry fields --template <条目模板> --json        # ② 看台账：字段名不要凭印象猜
nx-sk entry add --title "<名>" [--template <模板>] --data @值.json  # ③ 有模板就初始化，没有就空白起步
nx-sk entry get <名> --json                          # ④ 自检：值 / 完整度 / 未填清单
#    目标就是默认条目时可省略 <名>：nx-sk entry get --json
```

只有在「没有可复用模板、且同结构要建多条」时，才在 ② 与 ③ 之间插入 `template add`。

## 每个条目模板自带「原始资料」袋

它是结构的一部分，**设计字段时不要再造「来源 / 原文 / 备注」字段**去装乱数据——那是重复造袋。
袋不计完整度，文件进袋算已引用（cleanup 不删、导出随包走）。

## 拆条：一团输入到底算几条

拆错的代价是双份的：拆太细 → 几十条碎片，谁也读不出上下文；拆太粗 → 一条里塞三件事，
以后想按"截止时间"排序、按"状态"筛都做不到。

### 判据：一条 = 一件独立的事 / 一份独立的资料

问自己三个问题：

1. **它会单独被"完成"或"使用"吗？** 会 → 独立一条。
2. **它有自己的时间 / 状态 / 归属吗？** 有 → 独立一条。
3. **删掉它，另一条还完整吗？** 完整 → 本来就是两条。

| 输入 | 拆法 | 理由 |
| --- | --- | --- |
| "明天下午三点开会，记得带 Q4 预算，会议室在 3 楼" | **1 条**（会议），时间/地点/要带的东西进字段 | 同一件事的三个属性 |
| "① 交周报 ② 报销截止周五 ③ 服务器到期提醒" | **3 条** | 三件互不相关的事 |
| 一份《2026 值班表.pdf》 | **1 条** + 原件进附件库 | 一份资料一条 |
| 群公告里 5 个人的任务分配 | 先问：**只存公告**（1 条），还是**每人一条待办**（5 条）？ | 两种都合理，取决于用户要"查公告"还是"催人" |
| 一列 `A 100 元 / B 200 元` | **2 条**（明细），除非它本身是"报销单"（1 条 + 明细字段） | 明细要不要独立，看是否单独流转 |

**拿不准就问一句**，别自己拍。拆条是最容易返工的一步。

### 文字里混着链接：原文不动，链接附挂

一段话里出现 `https://…` 时：

- **整行只有一个 URL** → 这条是"链接条目"，链接是它的主体。
- **URL 夹在句子里** → 仍按文字条目存，原文一字不改，另外把链接抽出来放进 `links` 字段
  （或直接在 `md` 字段里保留，nx-sk 的预览里裸链接可点）。

抽链接的边界（这几条都是踩出来的）：

- **中文标点不是 URL 的一部分**：`https://a.com/x，第一遍` 里的 `，` 必须断开。
  顿号、句号、括号、书名号同理。
- **尾部 ASCII 标点要修剪**：`（见 https://a.com/x）` 的 `）`、`https://a.com/x.` 的 `.`。
- **只认 http(s)**：`ftp://`、`www.example.com`、`mailto:` 不当链接（否则文件名、包名全变成可点的）。
  nx-sk 的预览会自己把裸域名识别成可点链接（默认补 `http://`），不用你手动改。

### 文件：原件是资产，提取文本是加分项

| 类型 | 处理 |
| --- | --- |
| PDF / DOCX / TXT / MD | 原件进附件库；能提文本就把关键内容写进 `md` 字段 |
| 扫描件 / 加密 PDF / 图片 | **不提文本**：原样进附件库，标题写清"这是什么"，别硬猜内容 |
| 图片（截图） | 进附件库，`md` 里 `![说明](id)`；截图里的密码提醒用户打码 |
| 表格（xlsx/csv） | 原件进附件库；行数少就把关键几行写进 md 表格，行数多只存原件 |

**原件一律 `file add --path <路径> --copy`**（`--path` 默认是**移动**原件！用户的文件不该被搬走）。

提取文本失败不是错误：收件箱的第一承诺是"收进来"，文本化是加分项。

### 不该入库的东西

- 寒暄、感谢、纯查询（"这个怎么用"）—— 那不是数据。
- 一次性验证码、临时口令 —— 用完就没意义，存了反而是泄漏面。
- 别人的隐私（同事的手机号、客户名单）—— 除非用户明确要求且说清用途。
- 已经存在的内容 —— 先 `entry list --q <关键词>` 查一遍，重复入库比不入库更糟。

### 标题与摘录

- **标题**：取首行 / 文件名 / 会议名，**≤ 60 字**。超过就截断，别让面板列表变成一堵墙。
- **摘录**：≤ 200 字，只用于列表里的一行提示；全文进正文或 md 字段。
- 标题里不要带日期前缀（`2026-10-18 开会`）——日期有专门的字段，塞进标题就没法按日期排了。



## 字段设计：以后还能长

字段设计：给这批数据定一个「以后还能长」的骨架

字段台账（template.fields）是**数据不是代码**：它随条目模板存在 store 里，面板、CLI、agent 看到的是同一份。
所以字段一旦写下去，就是"这个条目模板长什么样"的长期承诺。

> **例外（不用设计、也删不掉）**：每个条目模板都自带 `source` 字段（label「原始资料」，
> 独立一组，`fill: optional`）——杂乱输入先原样入袋、再整理，它是结构的一部分。
> 设计字段时不要重复加「来源/原文/备注」袋；老条目模板缺袋跑 `nx-sk source ensure`。

### 先定 titleField

`template add` 建结构，`template update` 再指定 `--titleField <字段key>`（和 `--titleLabel <中文名>`）：

```bash
nx-sk template add memo --title "备忘" \
  --fields @fields.json --groups @groups.json
nx-sk template update memo --titleField name --titleLabel 名称
```

- 它决定"用哪个字段的值当条目名"。**不给的话**，每条都得 `entry add --title …`，
  否则报「无法确定条目名」；给了就能直接 `entry add --data @item.json`。
- 选**最短、最能代表这件事、几乎不会变**的那个字段（名称、标题、公司名）。
- 别选会频繁改的字段（备注、状态）—— 条目名是 `entry get <名字>` 的定位键。

### 一个字段由这些组成

```json
{
  "key": "due",
  "label": "截止",
  "type": "date",
  "group": "main",
  "hint": "报销单要在这一天前提交",
  "fill": "optional",
  "sensitive": true,
  "options": ["待办", "进行中", "已完成"],
  "maxItems": 3
}
```

| 属性 | 必填 | 说明 |
| --- | --- | --- |
| `key` | ✅ | 英文小写下划线，**稳定**（改名等于换字段） |
| `label` | ✅ | 中文标签，面板上显示的就是它 |
| `type` | ✅ | 见下表 |
| `group` | ✅ | 分组 id（要在 `groups` 里声明，否则面板渲染不出来） |
| `hint` | | 一句话说明"填什么"，直接显示在输入框下面 —— 三个月后救的是你自己 |
| `fill` | | `optional` 不必填 / `avoid` 填了可能减分（求职场景）/ 缺省 = 正常 |
| `sensitive` | | `true` = 密文落盘（AES-256-GCM），面板打码 |
| `options` | | `select` 的候选值 |
| `maxItems` | | `tags` / `file` 的上限 |

### 类型怎么选

| 内容 | type | 反例（别这么干） |
| --- | --- | --- |
| 名称、标题、短句 | `text` | 把备注写成 text，长文本会挤成一行 |
| 多行说明、步骤 | `textarea` | 用 text 存 500 字 |
| 要贴图 / 要待办 / 要表格 | `md` | 用 textarea 存 `![](f_x)`，图不会显示 |
| 日期 | `date`（`YYYY-MM-DD`） | 塞进 text 写成"下周三" |
| 月份 | `month`（`YYYY-MM`） | |
| 金额、数量 | `number` | 写成"约 300 元"（没法排序/汇总） |
| 是 / 否 | `bool` | 用 text 写"是"/"否" |
| 固定几个状态 | `select` + `options` | 用 text 随便写，之后没法筛 |
| 多个标签 | `tags` | 用一个 text 存"a、b、c"，没法单独筛 |
| 密码 / token / 证件号 | `secret` 或 `sensitive: true` | **绝不放普通 text** |
| 附件（简历、合同、截图） | `file` | 把文件路径写成 text（路径会失效） |

`md` 是 nx-sk 的特色：一段 markdown 正文，能嵌附件库的图片、能写待办（`- [ ]`）、
预览里标题/列表/表格/代码块都按标准 markdown 渲染，裸 IP 点击即复制、裸域名点击即打开。
"说明 + 截图混排"的东西（SOP、报错复现、会议纪要带图）优先用它。

### key 怎么起

- 英文、小写下划线：`due`、`owner`、`meeting_room`、`reimburse_amount`
- **别用中文当 key**（虽然合法）：面板、CLI、`--set` 混着用时最容易写错
- **别用 label 当 key**：label 是给人看的，随时可能改；key 是给程序用的，改了等于换字段
- 同一个条目模板里 key 唯一；跨条目模板可以重名（互不影响）

### 分组：按"读的时候的注意力顺序"

- **≤ 4 组**，组名是中文短语（"基本信息""进度""附件"）
- 第一组放"一眼要看到的东西"（名称、状态、截止），后面放细节
- 组 id 用英文（`main` / `detail` / `files`），title 用中文
- 新增字段时**一定要给 group**，且该 group 必须在 `groups` 数组里声明过 ——
  否则面板读声明数组渲染，整组字段会静默消失（CLI 从字段推导，看不出来）

### 必填与完整度

- 缺省 = 必填，会计入完整度；`optional` 不计入
- **只给"每次都有"的字段必填**：给"备注""来源""附件"设必填，等于永远 80% 完整度，完整度就没人看了
- `avoid` 用在"填了可能减分"的场景（求职条目模板的政治面貌、婚育），不是"不想填"

### 字段数量的经验值

- **3–8 个**：一个条目模板读起来舒服的区间
- **超过 12 个**：八成该拆成两个条目模板（"基本信息" vs "过程记录"）
- **只有 1–2 个**：可能不值得建条目模板，塞进现有条目模板的 `md` 字段或 `notes` 更合适

### 先给用户看的格式

设计完别直接建，用这张表让用户拍板：

```
条目模板：备忘（memo，新建）
  名称      text     必填   一眼知道是什么
  类型      select   必填   待办 / 通知 / 资料
  截止      date     可选   过期就不显眼
  正文      md       可选   截图、步骤、清单
  原始资料  source   自带   乱输入先入袋（不计完整度，不用设计）
```

用户看得懂这张表，看不懂 JSON。



## 填值：一条一个 entry add

填值：一条一个 `entry add`，值走文件

### 基本形状

```bash
## 1) 先试运行：看清楚会写哪些字段
nx-sk entry add --template memo --title "10 月值班表" --data @item-1.json --dry-run

## 2) 真写
nx-sk entry add --template memo --title "10 月值班表" --data @item-1.json
```

`item-1.json` 两种写法都认：

```json
{ "kind": "待办", "due": "2026-10-20", "body": "1. 交周报\n2. 报销" }
```

```json
{ "values": { "kind": "待办", "due": "2026-10-20" } }
```

- **标题走 `--title`**，不要塞进 `--data`（否则会变成一把叫 `title` 的字段值）。
- 键可以是 `key` 也可以是**中文 label**（`--set 截止=2026-10-20` 也行），但批量时用 key 更稳。
- 没见过的键**会自动登记**进台账 —— 能存，但别指望它长得对（类型会默认成 text）。

### 重跑与去重

`entry add` 同名会报 `CONFLICT`（不会静默覆盖）。所以：

```bash
nx-sk entry list --template memo --q "值班" --json   # 先查
nx-sk entry update <条目id> --data @item-1.json     # 有就改
```

**幂等靠两件事**：标题稳定 + 自带的「原始资料」袋（原文入袋，袋里每条带 `addedAt`、
可标 `mapped`）。重跑时先按袋里的内容查（`source get`），命中就 update，没命中才 add。

### 附件：先入库，再引用

```bash
## ⚠️ --path 默认是「移动」原件；只想留副本必须加 --copy
nx-sk file add --path "D:/下载/2026值班表.pdf" --copy --category document --json
## → {"id":"f_xxx","name":"2026值班表.pdf", ...}

## 图片在 md 字段里这样引用（标准 markdown，导出/贴进 README 也能渲染）
## ![10 月值班表](f_xxx)
```

- **多图**：一个 `file` 字段可以存多个 id（数组），`md` 里就多写几行 `![说明](id)`。
- **外链图**：`![说明](https://…)` 直接写，不进附件库（要联网才显示）。
- 附件字段（`type: file`）存的是**附件 id 列表**，不是路径 —— 路径会失效，id 不会。

### `md` 字段的写法

```markdown
### 背景
一句话说清这是什么。

- [ ] 待办一（预览里能直接点勾，勾完写回正文）
- [x] 待办二

| 字段 | 值 |
| --- | --- |
| 时间 | 2026-10-20 15:00 |

![现场截图](f_abc123)
```

> **⚠️ 任何"一串要做的事"都用 `- [ ]` 写。** md 字段里的 `- [ ]` 在面板里是**可点的复选框**：
> 勾一下 = 把 `[ ]` 改成 `[x]` 并写回条目正文（行号定位，只动复选框不动其他字符）。
> 适用：待办、Action items、复现步骤、上线 checklist、验收项——任何「一串要做的事」
> +「在 md 字段里」就该用 `- [ ]`，不要用 `1./2.` 序号（序号只是字，不可点）。
> 勾选只改正文里的那一个字符（按行定位），其余内容原样不动；改完记得点「保存」，否则只改了界面没写回库。

- 单个换行会保留（渲染成 `<br>`），但**结构还是靠空行分段**。
- 代码块用三反引号；`md` 里不要写密码（明文渲染）。
- 待办勾选状态只有正文一份 —— 用户勾完记得点面板的「保存」，否则只改了 UI 状态没改 store。

### 日期与数字

- `date`：`YYYY-MM-DD`；`month`：`YYYY-MM`
- 原始输入是"下周三""月底"这种 → **先换算成具体日期再写**，把原话放进 `hint` 或备注
- `number`：纯数字（`300`），单位写进 label（"金额（元）"）

### 批量填值的脚本姿势

```bash
## 生成一堆小 JSON，再逐条 add；先全跑一遍 --dry-run 看输出
for f in /tmp/items/*.json; do
  nx-sk entry add --template memo --data "@$f" --dry-run
done
```

失败**不要整批重来**：`CONFLICT` 是"已经有了"，跳过或改 update 即可；
`INVALID_INPUT` 是这条数据本身有问题，单独修。

### 写完的自检三连

```bash
nx-sk template dump memo --json            # 条目数、每条缺什么
nx-sk entry get <id> --json               # 值真的进去了吗
nx-sk file list --template memo --json     # 附件挂上了吗
```



## 完整示例

完整示例：一段混乱输入 → 一个条目模板 → 四条条目

### 用户丢来的东西

```
明天下午三点在 3 楼会议室开季度复盘会，记得带 Q4 预算表
另外报销单周五截止，别忘了
服务器 10.0.0.8 的证书 11 月 3 号到期
https://example.com/2026-q4-plan
```

### 第 0 步：清点

| # | 内容 | 类型 |
| --- | --- | --- |
| 1 | 季度复盘会（时间/地点/要带的材料） | 待办 |
| 2 | 报销单周五截止 | 待办 |
| 3 | 证书 11/3 到期 | 待办（运维） |
| 4 | Q4 计划链接 | 资料 |

注意第 1 条里"记得带 Q4 预算表"是会议的**属性**，不单独拆。

### 第 1 步：侦察

```bash
nx-sk template list --json
```

现有条目模板是求职/项目/实习/校内/服务器/密钥/部署配置 —— **没有"随手记"这一类**，
硬塞进"项目经历"会把结构搞坏。结论：新建。

### 第 2 步：设计

```
条目模板：备忘（memo，新建）
  名称    text     必填  一眼知道是什么
  类型    select   必填  待办 / 资料
  截止    date     可选  过期就不显眼
  正文    md       可选  细节、链接、截图
```
