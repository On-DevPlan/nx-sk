> A 序列各篇踩过的坑集中在这里；做对应场景前扫一眼。


## PDF / 图文 SOP

踩过的坑

都是实际做一份 52 页手册时踩到的，不是假想。

### 1. 图 51 张，SOP 只要 18 张 —— 剩下的是什么

`pdf_probe.py` 报 51 张，但直接全灌进去就是噪音。真正进 SOP 的是**界面操作截图**；
其余是目录页截图、附录里的架构图、与本次任务无关的章节。

**做法**：先导出全部图片，**逐张看过再挑**。
判断不了就宁可多留 —— 留错了删掉是一分钟，漏了用户照着做不下去。

一整份文档不要只凭尺寸筛：尺寸只能滤掉装饰件（页眉 logo、分隔线），
筛不出「内容不相关」。

### 2. 图配错步骤：顺序必须来自版面，不能来自页码

最贵的错误 —— 文字全对，截图全错位，用户照着图文对不上，完全做不下去。
原因见 [[10-extract]]：`get_images()` 的 xref 顺序与版面无关。

`pdf_extract.py` 已经按 y 坐标排好了，直接用它出 md，别自己拼。

### 3. 占位符忘了换成附件 id

抽取出的 md 里是 `![p6-1](IMG_006_1)`。`IMG_006_1` 是**占位符**，不是附件 id，
面板只会显示「图片缺失」。

上传后要把占位符整体替换成真实 id：

```bash
pic=$(nx-sk file add --path images/006_1.png --category other --json | python -c "import json,sys;print(json.load(sys.stdin)['id'])")
sed -i "s#IMG_006_1#$pic#g" sop.md
```

**验收必查「有没有显示缺失」** —— 有缺失就是忘了替换。

### 4. 本地路径不能当图片地址

写成 `![图](C:/Users/.../006_1.png)` 面板**渲染不出来**，
因为它只认两种值：附件库 id 与 http(s) 外链。
`transfer` 打包时也带不走这种引用。

（注意 nx-sk 的 md 渲染与标准 markdown 有差别：标准写法允许相对路径，
这里不支持；这是有意为之 —— 相对路径换个机器就失效，而 id 能被包带走。）

### 5. 密码写进正文 = 泄漏

`md` 字段是明文渲染的，还会进导出、截图、分享出去的包。
账号密码一律走 `sensitive: true` 字段，正文只写「见〈某字段〉」。

**截图里的密码也要管**：如果 PDF 原图里就打着密码，要么提醒用户打码重截，
要么别放这张图 —— 图片本身也是明文。

### 6. md 正文里的图片，附件中心曾经显示「未引用」

2026-10-18 之前，`fileReferences` 只扫 `file` 字段、不看 md 正文，
于是图片明明在 SOP 里用着，附件中心却说未引用。已修：现在 `file` 字段与 md 正文两种引用都认，
命中判定按附件 id 比，不再看是不是同一个对象。

如果又看到「未引用」而图片明明在正文里，先确认 nx-sk 版本 ≥ 修好的版本。

### 7. 附件按 sha256 去重 —— 测试与实际导入都会撞

同一张图重复上传会**复用已有记录**（不存两份）。这是特性，但有两个后果：

- 写测试时用相同字节造两张图，第二张会拿到第一张的 id，测试看着失败其实是用例写错；
- 换了一张内容完全相同的图却发现 id 没变，先确认是不是同一张图。

### 8. `file add` 默认移动原件

`nx-sk file add --path x.png` 会把 x.png **搬进** `~/nx-sk/files/`。
从临时目录抽的图无所谓；想保留抽取结果就加 `--copy`。

同理，别对唯一的原始 PDF 跑任何「移动」语义的命令。

### 9. 页脚混进正文

PDF 页脚（`Copyright © 2023 …`）会被当成正常文字抽出来，出现在步骤中间，
读起来很怪。抽取后**扫一遍 md**，把重复出现的页脚删掉。

（`pdf_extract.py` 目前不自动滤页脚 —— 不同文档页脚样式差异太大，
按位置（y 接近页底）+ 跨页重复来判定更准，这一步留给人工更稳。）

### 10. 扫描件抽出来是空

没有文字层的 PDF，`get_text()` 返回空串 —— md 里只剩图片占位符。
先 OCR 再走本流程，别对着纯图像页猜正文（很容易编造出原文没有的内容）。

`pdf_probe.py` 会列出无文字层的页码，部分页缺层时要明确告诉用户那部分正文缺失。



## 毕业论文格式

已经踩过的坑（含开题报告里的实例）

下面每一条都是从**真实文档**里量出来的，不是凭空列的清单。改之前先对一眼，能省一次返工。

### 1. 题目超过 20 字

- **实例**：「融合多智能体协作与RAG检索的多端智能知识记录系统研发」——按字符计 **27 个**。
- **规范**：题目原则上不超过 20 字，必要时加副标题。
- **怎么改**：压到 20 字内，例如「融合多智能体与RAG的多端知识记录系统」（19 字）；
  或保留长题、加副标题把范围说清楚。定稿前和导师确认，别自己改完就交。

### 2. 一级标题被加粗

- **实例**：开题报告里「1 立题依据」的 run 被设成了 `bold=True`，而同文件的
  「2 研究的主要内容及预期目标」没有加粗——同一份文档里两种样式。
- **规范**：一级标题黑体四号，**不加粗**（黑体本身就重，再加剧就过了）。
- **怎么改**：选中标题 → 清除格式 → 重新套「标题 1」样式。不要手动按 Ctrl+B。

### 3. 图题写成「图 1 系统架构图」

- **实例**：开题报告正文里的图题是「图 1 系统架构图」——图与序号之间多了一个空格。
- **规范**：「图1 系统架构图」。**图与序号之间不空格**，序号与图名之间空一格。
- **为什么容易错**：Word 默认会在中文与数字之间自动加一点空隙，看起来就像多了个空格。
  模板里已把「图题 / 表题」样式的 `autoSpaceDE/DN` 关掉。
- **怎么改**：套模板的「图题」样式；自己排版时在段落设置里关掉
  「自动调整中文与西文的间距」。

### 4. 用 Word 自动编号做（1）（2）

- **实例**：开题报告的列表用了 `numPr` 自动编号，编号格式是 `(%1)`，
  缩进是 `left=720, hanging=360`（悬挂缩进）。
- **两个错**：
  1. 编号用了**半角括号** `(1)`，规范要求中文括号 `（1）`。
  2. 自动编号带**悬挂缩进**，换行后第二行顶到编号位置，而规范要求
     「按正文格式排版」——首行缩进 2 字符、换行回左边界。
- **怎么改**：手打「（1）」，段落用正文样式（首行缩进 2 字符），不要用项目符号/编号按钮。
  模板里的 3.1 节就是正确写法。

### 5. 目录没更新 / 页码对不上

- **现象**：目录还是上一次的页码；改了标题后目录里没有新章节。
- **怎么改**：右键目录 → 更新域 → **更新整个目录**。只更新页码不够，标题增删后必须整份更新。
  模板已设成打开时提示更新；提交前再手动更一次。

### 6. 批注与修订痕迹没删

- **实例**：文件名里带「保留痕迹」，正文也留着大量批注。
- **为什么必须删**：打印/导出 PDF 时批注会以气球形式印在页面右侧，还会把正文宽度压到 74%，
  整份排版都变形。导师一眼就能看出来。
- **怎么改**：审阅 → 删除 → **删除文档中的所有批注**；再「接受所有修订」。
  模板自带 23 条格式提示批注，交稿前一定清掉。

### 7. 用了教务处直接下载的模板

- **规范原文的批注**：教务处下载的模板**页面设置有误**，以规范文档里的模板为准。
- **怎么改**：用本 skill 的 `templates/毕业论文模板-设计开发类.docx`（页面已按 2.5/2/2.5/2 cm 设好），
  或自己核对一遍页边距再动手。

### 8. 表格用了全框线

- **现象**：Word 默认插入的表格是四边框线全有。
- **规范**：三线表——无左右边线，上下底 1.5 磅，表头下 1 磅。
- **怎么改**：表格工具 → 边框 → 先「无框线」，再手动加上框、下框，表头行加下框；
  线宽在「边框和底纹」里设 1.5 磅 / 1 磅。模板里两张表可直接照抄。

### 9. 参考文献用了全角标点

- **现象**：`张三，李四．题名［J］．刊名，2023，40（5）：1-6．`
- **规范**：标点统一用**英文半角**，标点后空一格；每条以实心点结束。
- **正确**：`[1] 张三, 李四, 王五, 等. 题名[J]. 刊名, 2023, 40(5):1-6.`
- **怎么改**：关闭输入法的中文标点再录入；或把条目粘到记事本里替换一遍全角符号。

### 10. 页码写成「第 1 页」或「－1－」

- **规范**：页脚居中、小五 Times New Roman、纯阿拉伯数字；封面与目录不编页码。
- **怎么改**：插入页码 → 页面底端 → 普通数字 1；再在「设置页码格式」里把起始页码设为 1，
  并把封面/目录所在节设为「不显示页码」（模板已用分节做好）。

### 11. 图片不是嵌入型

- **现象**：图片「浮于文字上方」，一动文字图片就跑，打印时还会盖住正文。
- **规范**：嵌入型、居中、首行不缩进；四周不留大片空白；不加底纹网格。
- **怎么改**：选中图片 → 布局选项 → 嵌入型 → 段落居中。

### 交稿前 60 秒自检

```bash
nx-sk template get thesis        # 条目模板「毕业论文」里是全部硬指标
```

按 `checklist` 字段逐条打勾；或直接打开模板，对照 23 条批注过一遍。



## 混乱数据归档

踩过的坑（每条都真实发生过）

### 1. 字段没登记 → 存了却看不见

面板按**字段台账**渲染。`entry add --set 临时字段=值` 会自动登记，但如果你直接改 store 或用
没声明过的键，值在库里、面板上看不到 —— 表现就是"我明明存了"。

**判据**：写完 `template dump <条目模板> --json`，看 `fields` 里有没有这个 key。

### 2. 条目模板爆炸

每来一批数据就新建一个条目模板，三个月后侧边栏 30 个 tab，每个条目模板 2 条数据。
**规则**：能塞进现有条目模板就塞；只有当主题确实不同（求职 vs 服务器）才新建。
新建前先 `template list --json` 看一眼 `description`。

### 3. 把一整批塞进一个 `md` 字段

"这 20 条待办我全写进一个 md" → 没法按截止日期排序、没法标记谁负责、没法单条完成。
**一条一件独立的事**，md 只装"这件事的说明"。

### 4. 密文进了普通字段

`text` 字段是明文落盘的，导出、`transfer`、截图都会带出去。
密码 / token / 证件号 → `secret` 类型字段，或 `secret` 条目模板的 `keys` 清单（值列 AES 密文）。
`md` 字段里也**不要写密码**（它是明文渲染）。

### 5. `file add --path` 把用户的原件搬走了

默认是**移动**。用户说"把这个文件存进库"通常不是"从我的下载目录里删掉它"。
**默认加 `--copy`**，除非用户明确说"移进去"。

### 6. 重复导入产生 `（导入）` 副本

同名条目重跑 `entry add` 会 `CONFLICT`；如果用 `transfer import --on-conflict copy` 反复导入同一份包，
会得到 `甲（导入）`、`甲（导入 2）`…… 一批越来越长的副本。
**重跑用 `entry update`**，导入前先看预览里的冲突明细。

### 7. 抽链接把中文标点吃进去

`https://a.com/x，第一遍` 里的 `，`、`（见 https://a.com）` 里的 `）` 都不是 URL 的一部分。
只认 `http(s)`，并把尾部的中文标点与不配对括号剥掉。
（nx-sk 的预览层已经处理了这件事，但你自己抽链接写进字段时要按同一口径。）

### 8. 标题为空 → 条目叫「（无名）」

`titleField` 没填、`--title` 又没给，面板上就是一排"（无名）"。
**每条都必须有标题**：取首行、文件名、或"<类型> · <日期>"。

### 9. 完整度虚高 / 虚低

- 把"备注""来源""附件"设成必填 → 永远 80%，完整度失去意义
- 把所有字段设 `optional` → 永远 100%，也失去意义
**只给"每次都有"的字段必填。**

### 10. 分组没声明 → 整组字段消失

字段的 `group` 必须在 `groups` 数组里声明过。`--add-field` 会自动补声明，但手写
`--fields` 整体替换时容易漏 —— 漏了面板就渲染不出这一组（CLI 看不出来）。

### 11. 在命令行里拼多行中文 JSON

引号、换行、中文标点会在 shell 层被吃掉一部分，报错还看不懂。
**一律写文件，用 `@file.json`**。

### 12. 把「不该入库的」也收进来

一次性验证码、别人的隐私、纯寒暄、已经存在的重复内容 —— 收进来只会增加清理成本。
先问一句"这个要长期留着吗"，比事后删十条便宜。
