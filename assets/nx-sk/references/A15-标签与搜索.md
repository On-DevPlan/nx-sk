# A15 · 打标签与搜索（tag / 快速搜索）

> 要给条目归类、按标签找同类、或让 agent 快速定位时读这篇。
> tag 是**名词精确匹配**，不是全文搜索的替代品；两者配合用。

## 一、tag 从哪来

1. **模板默认 tag**：新建模板时默认 `[模板 id, 模板标题]`（空白模板除外）。
   可用 `nx-sk template update <模板> --tags 客户,项目` 整体替换。
2. **条目继承**：`entry add --template <模板>` 自动带上模板 tags；`--tags` 只追加，不覆盖模板语义。
3. **条目自己的 tag**：`entry update <条目> --tags 紧急,本周` 整体替换。

一个条目可以有多个 tag；tag 存在 `entries.tags`，与字段值完全分开。

## 二、写

```bash
# 新建时追加
nx-sk entry add --title "某客户报价" --template <模板> --tags 客户,报价

# 改已有条目：整体替换（先看现在有什么）
nx-sk entry get <条目> --json
nx-sk entry update <条目> --tags 客户,报价,已确认
```

**注意**：`--tags` 是整体替换，不是追加。模板 tags 与条目 tags 是两份数据：创建时模板 tags 合并进条目；
之后 `entry update --tags` 只替换条目这一份，不回头改模板。把继承来的 tag 替换掉后：
`entry search --q` 仍能命中模板 tags（搜索范围含模板元信息），`entry list --tag` 只筛条目标签、不会再命中。
想保留旧 tag，就先把它们一起写进去。

## 三、找

```bash
nx-sk entry list --tag 客户 --json
nx-sk entry list --tag 客户,报价 --tag-mode all --json   # 两个都要有
nx-sk entry search --tag 客户 --json                    # 轻量 hit，不返回完整 values
nx-sk entry search --q "报价" --json                  # 标题/模板/tag/字段标签/非敏感值
nx-sk entry search --q "报价" --tag 客户 --limit 20 --json
nx-sk entry list --missing-desc --json                   # 找还没写 desc（一句话说明）的条目
```

- `entry list` 返回完整条目序列化；`entry search` 只返回定位信息，适合 agent 先查再读。
- `--tag` 筛的是**条目自己的 tags**；要按模板默认 tag 找，用 `--q`（扫模板标题/描述/tags）
  或直接 `--template <模板>`。多个 tag 默认**任一命中**；`--tag-mode all` 才是全部命中。
- `entry search` 扫：标题、模板标题/描述、tag、字段 key/label、**非敏感字段值**；
  敏感字段只匹配标签，不解密、不扫密文。
- 搜索结果按 `updatedAt` 倒序；默认 50，最多 200。
- `--missing-desc` 与 `--tag` / `--template` / `--parent` 可叠加：用来「补全条目说明」而不是找内容。

## 四、命名口径

- 一个 tag 是一个**短名词**：`客户`、`报价`、`部署`、`论文`。
- 不要用句子/日期当 tag；日期放字段，别塞 tag。
- 同一概念只用一个写法：`客户` 与 `客户资料` 是两个 tag，检索会分裂。
- 模板默认 tag 已带模板 id 与标题；条目自己的 tag 只补「跨模板的语义」。
- **tag 和 desc 不是一回事**：tag 是横切分类（一个 tag 覆盖很多条），desc 是这一条自己的
  一句话说明（`entry update <id> --desc "…"`）。`status` 与 `entry list` 靠 desc 区分相近条目，
  靠 tag 做集合筛选——两者都写，检索才既「分得开」又「筛得出」。

## 五、Web

- 条目名下方显示 tag chips，旁边的标签图标打开「编辑条目标签」；模板页工具条的标签图标编辑模板默认 tag。
- 编辑弹窗用逗号或空格分隔多个 tag，保存即生效；条目标签保存不会冲掉未保存的字段草稿。
- 模板默认 tag 只影响以后从该模板新建的条目，已建条目的标签不会自动跟改；Web 新增条目会继承模板 tag。
- 左侧目录树搜索已包含 tags；点搜索结果可跳到条目。CLI 的 `entry search --tag` / `entry update --tags` 仍是批处理与脚本入口。

## 六、常见错

| 现象 | 原因 | 改法 |
| --- | --- | --- |
| 改了 tag 后旧 tag 没了 | `--tags` 整体替换 | 把要保留的 tag 一起写 |
| `entry list --tag` 没结果 | tag 是精确匹配，不是模糊 | 先 `entry search --tag` 或看条目现有 tags |
| 搜字段值搜不到 | 该字段是敏感字段 | 敏感值不解密搜索；按 tag/标题定位后 `entry get` |
| 模板 tag 改了，旧条目没变 | 条目创建后才独立演化 | 需要就逐条 `entry update --tags` |
| 条目一多就分不清谁是谁 | 只有标题、没有说明 | 每条补 `--desc`，先 `entry list --missing-desc` 列出来 |
| 写了 tag 还是找不到 | tag 是分类，不是说明 | 补 desc；搜索会扫标题/字段，但 `status` 只认 desc |
