# A14 · 记一套快捷键（shortcut 字段）

> 要存「某个软件的键位表 / 自己的快捷键方案」时读这篇。
> 普通「多个标签」用 `tags`；键位不是标签，它要记物理键位和生效范围。

## 一、值形状：组 → 条目 → 按键

```json
[
  {
    "name": "全局",
    "shortcuts": [
      { "combo": "Ctrl+Shift+R", "description": "刷新" },
      { "combo": "Ctrl+K", "description": "命令面板", "condition": "编辑器内" }
    ]
  }
]
```

- 组（`name`）是目录；条目是「这条快捷键做什么」；`condition` 写生效范围（不写 = 全局）。
- `combo` 存 **`KeyboardEvent.code`（物理键位）**，不是 `key`——换键盘布局/输入法不会错位。
- 每条必须有 `description`；说明可以为空串，但不能没有。

## 二、三种等价写法

```bash
# 1) 最省事：组合键字符串
nx-sk entry update <条目> --set 'keys=[{"name":"全局","shortcuts":[{"combo":"Ctrl+Shift+R","description":"刷新"}]}]'

# 2) 键名数组
nx-sk entry update <条目> --set 'keys=[{"name":"列表","shortcuts":[{"combo":["J"],"description":"下一条"}]}]'

# 3) 面板存下来的按键对象（精确控制左右修饰键）
nx-sk entry update <条目> --set 'keys=[{"name":"全局","shortcuts":[{"combo":[{"code":"ControlLeft","label":"Ctrl"},{"code":"KeyK","label":"K"}],"description":"命令面板"}]}]'
```

三种都会归一成同一种形状；批量建议 `--data @keys.json`。

## 三、读

```bash
nx-sk entry get <条目>          # 按组输出，组数/条数 + 每条键位与说明
nx-sk entry get <条目> --json   # values.keys 是原始三层数组
```

## 四、Web

- 条目里是折叠条，只报组数/条数；点 `详细` 打开键位面板（默认全屏，可切侧边/居中）。
- `新增` 后直接按组合键即可录入；悬停条目光亮对应键。
- 键位画的是物理键盘，特殊键（Ctrl/Shift/Alt/Meta）左右可区分。

## 五、写前先想清

| 问题 | 建议 |
| --- | --- |
| 这是哪个软件的键位 | 组名写软件/场景，不要所有都塞「全局」 |
| 同键不同场景 | 用 `condition`，不要建两组同名 |
| 只记得字符不记得物理键 | 写字符组合即可；要精确控制左右修饰键才用对象写法 |
| 键位有冲突 | 在说明里写清优先级/覆盖关系，不要靠猜 |

## 六、常见错

| 报错 | 改法 |
| --- | --- |
| 键位认不出（如 `Ctrl+？`） | 用合法键名；中文标点不是键 |
| 第几组第几条缺 description | 每条都补说明（空串也合法，但要有字段） |
| 把快捷键写进 table | shortcut 不能当表格列；用独立字段 |
