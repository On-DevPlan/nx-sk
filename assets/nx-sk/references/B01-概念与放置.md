# B01 · 概念与放置（条目 / 条目模板 / 目录 / 字段）

> 想搞懂「为什么这么设计、东西该往哪儿放」时读这篇。怎么调命令看 A 序列。
> 调命令看 `A01-填一条信息` / `A04-存密钥和凭据` / `A05-收一份附件` / `A06-存一份部署配置` / `A09-搬走一个条目模板`；
> 项目整体怎么搭看 `B04-项目组织架构与布局`。

## 一、一句话：条目是唯一内容节点，条目模板只负责初始化

```
条目（entry）   = 一条内容：自己的字段结构（分组 + 字段）+ values{ 字段 key: 值 }
条目模板（template）= 初始化蓝图：建条目时深拷贝一份字段结构，建完就与条目脱钩
目录（folder） = 不是独立实体：一条条目有子条目，它就是文件夹
```

- **内容只在条目里**：字段结构、字段值、附件引用、父级关系，全部挂在条目上。
- **条目模板只读来建新条目**：`entry add --template <条目模板>` 时复制结构；之后条目模板加字段、改标签、
  删字段，都不会回刷已有条目。
- **层级只在父子关系里**：`folders` 表只存 `parent_id` 与 `sort`；左侧导航就是这棵树。

这样最直接的好处：**一条条目可以长成任何形状**，不因为它属于某个「条目模板」就被限制在固定字段里；
想复用一套结构，就把它存成条目模板，下次建条目时再挑。

## 二、内置条目模板：开箱即用的初始化清单

新条目可以从一个条目模板开始：内置条目模板直接给出一套**该填什么**的建议字段。

| 条目模板 | 给你的建议字段 |
| --- | --- |
| `job` 求职 / 个人信息 | 姓名 / 学历 / 联系方式 / 求职意向 / 附件资料（约 80 个字段，10 个分组） |
| `projects` / `internships` / `campus` | 一段经历 = 一个条目，角色 / 时间 / 技术栈 / 职责各自独立成字段 |
| `secret` 密钥 | 普通模板 + 一个 `keys` 结构清单字段：一行一个键值对，值列密文 |
| `deploy` 部署配置 | 一份配置文件 = 一个条目：正文 / 放哪 / 哪些值要替换 / **凭据清单** / 何时用 |
| `platform` 容器平台 | 一个平台 = 一个条目：控制台链接 / 账号 / 密码 / 镜像 / 命名空间 |
| `thesis` 毕业论文 | 规范里的每条硬指标 = 一个字段（页边距 / 字号 / 图表规范 / 参考文献…） |

**条目模板是建议，不是合同**：字段可以改标签、可以删、可以加；条目建出来之后就**独立演化**。
条目自己新增的字段只进这条条目，不污染条目模板；想把当前结构固化成新条目模板，用
`nx-sk entry save-as-template <条目> --id <条目模板id> --title <条目模板名>`。

首次运行只**播种 1 个「字段样例」条目模板**（demo，连示例条目一起：每种字段一格、表格带公式与统计），
其余条目模板（job / projects / … / platform / thesis）需要时自己建。

## 三、动态条目 + 动态目录：任何东西都能存

这个工具不预设「你的信息」长什么样。三层都是动态的：

| 层 | 能做什么 |
| --- | --- |
| 条目 | 想加就加（`entry add`），想删就删（`entry remove`，有子条目会删整棵子树）；标题与字段结构都可独立演化 |
| 目录 | 任意条目都能当文件夹：`entry add --parent <父>` 建子条目，`entry move --parent` 移动，拒绝成环；面板左侧目录树可拖动（中央 = 收成子条目，上/下缘 = 同级前/后） |
| 字段 | 每条条目能加字段（`entry update --set 任意键=值` 自动登记，或面板字段编辑器）、能删、能改标签与提示 |
| 条目模板 | 能加（`template add`）、能改、能删（条目回落到空白模板，不删条目）；能由一条条目反存；面板可拖 `⠿` 排序（`template reorder`） |

**台账不拦写入**：`entry update --set 任意键=值` 一律能存，结构里没有的键会**自动登记**
（键名就是它本身，中文也可以，类型按值推断）。

> 但有一个**义务**：自动登记只保证「值存进去了」，**面板按条目自己的结构行渲染**——
> 没登记的字段在界面上看不见。所以写完新键，要么让它自动登记成功（看返回里的
> `createdFields`），要么显式加一次字段声明。

例外只有一处：**密钥清单本身不是普通标量字段**，它是 `secret` 里的一个 `keys` 结构清单（一行一个键值对），
要加东西就用 `key set <名称> <值>`——见 `A04-存密钥和凭据`（密钥部分）。

## 四、默认条目：agent 的「当前位置」

条目一多，agent 最容易犯的错不是不会写，而是**写到了另一条上**。所以库里有一处持久化的
「当前位置」——`settings.defaultEntry`：

```bash
nx-sk status                                          # 默认条目 + 祖先链 + 它这一支的条目（含 desc）
nx-sk setting set --set defaultEntry=<条目id或标题>     # 换位置（存 id；写标题会归一）
nx-sk setting set --set entryScopeLimit=5             # 一次带多少条（默认 5，1–50）
```

三条规则：

1. **省略 `<ref>` = 默认条目**：`entry get/update/table/history/field-history/add-field/field-update`、
   `entry context`、`source get/add/update`。这是用户说「这条」时的最短路径。
2. **破坏性动作不回落**：删除 / 移动 / 改标题 / 存为模板必须显式给 id。
   一次手滑不该删掉默认条目整棵子树。
3. **只带一小片**：`status` 默认最多 5 条，广度优先（默认条目 → 直接子条目 → 孙条目）。
   再多 agent 就开始认串；要更大范围就用 `entry context` / `entry list --parent` 下钻，
   而不是把上限调到 50 然后指望它自己看住。

默认条目不是「文件夹」，也不是新实体：它只是一个设置项指向某个条目 id。
条目被删掉之后设置会失效——`status` 会明说「默认条目不在了」并给出重选指引，不会悄悄换成别的条目。

配套的是每条条目的 **`desc`**（落在 `entries.description`）：一句话说明它是干什么的。
它**不是字段**——不进 `values`、不进完整度、不占版式；`entry add --desc` / `entry update --desc` 写入，
`status` / `entry list` / `entry get` / 导出导入都会带出去。

## 五、值的三种形状（外加附件）

| 形状 | 什么时候用 | 长什么样 |
| --- | --- | --- |
| 标量字段 | 一个值 | 文本 / 数字 / 日期 / 是否 / 多值标签 |
| **结构清单** `entrylist` | 一个条目挂**多组**结构（多组账号、多条链接） | 行数组，列在字段定义里声明；密码列标 `sensitive` 即密文落盘 |
| **原始资料袋** `source` | 还没整理的杂乱资料（邮件 / 截图 / 摘录）；**字段值的溯源锚点** | 一袋资料条目，**先乱入、后整理**；袋里的文件算正式引用（cleanup 不删、导出随包走） |
| **附件** `file` | 二进制原件（简历 / 头像 / 证书） | 附件 id 列表，原件在 `~/nx-sk/files/` |

「先乱入、后整理」是刻意留的：真实数据几乎不是一次填对的，没有这个袋子，
用户只有两个坏选择——把乱数据硬塞进结构化字段（把结构搞脏），或者干脆不存（信息丢了）。

## 六、聚合所有信息

结构可以无限动态，但**信息要能一眼看全**。所以有四个聚合点：

| 聚合点 | 命令 | 用途 |
| --- | --- | --- |
| 一个条目模板的全貌 | `nx-sk template dump <条目模板>` | 条目模板字段 + 用它初始化过的条目 + 每条完整度与**未填清单** |
| 当前工作上下文 | `nx-sk status` | 默认条目 + 它这一支的条目（含 desc）+ 命令与写作口径提示词 |
| 整棵目录树 | `nx-sk entry tree` | 所有条目的父子层级（左侧导航同源） |
| 跨条目的凭据台账 | `nx-sk entry keys [--reveal]` | 所有条目里的 链接 / 账号 / 密码 / 令牌 / 镜像 |
| 跨条目的关键字段 | `nx-sk entry fields` | 条目模板给了什么 + 你实际写过什么（哪些键在用、哪些是死字段） |
| 整库搬家 | `nx-sk transfer bundle-export` / `bundle-import` | 一份 ZIP 带全部条目、字段结构与附件（设置页「全量备份」同源） |

另外，`settings.navGroups` 是**旧版头部导航的遗留显示配置**，0.43 起左侧目录树由
条目父子关系生成，不再用它分组内容。

## 七、密文边界

不是所有字段都一样：**标了 `secret` / `sensitive` 的字段落盘是 AES-256-GCM 密文**，
读出来默认是原文（自己看的东西不先拦一道），`--mask` 才打码。

- 键名像凭据（密码 / 口令 / 密钥 / 账号 / token / apiKey / accessKey…）时，
  **自动登记出来的字段直接就是密文字段**——「大胆写」不等于「明文裸奔」。
- 一条场景的凭据写在**那个场景的条目**里；跨场景通用的 key 才进 `secret` 密钥条目模板。详见 `A04-存密钥和凭据`。

## 八、给 agent 的三条不变量

1. **台账不拦写入，但必须登记。** `--set 任意键=值` 一律能存；没见过的键自动进字典，
   否则面板看不见（像「存了却没生效」）。
2. **面板与 CLI 是同一套业务。** 面板上能做的，CLI 都能做，参数名与错误码两端一致——
   所以「让用户在面板上点一下」和「让 agent 敲一条命令」是同一件事的两面。
3. **失败抛异常（退出码 1），业务结果返回 `{ status }`（退出码 0）。**
   `conflict` / `blocked` / `skipped` 都是**正常返回**——agent 要看 `status` 字段，
   而不是拿退出码判断失败。把「等用户决策」的冲突当成失败去重试，是这里最容易犯的错。
