# A11 · 记一份结构清单（entrylist 字段）

> 一个条目下要挂**多组列固定、行数不定**的数据时读这篇：多组账号/密码、多个链接、
> 多台机器的镜像清单。每行列会变、要公式/统计 → 用 `A10-记一张表`。

## 一、最小模型

```
字段定义：{ key: "accounts", type: "entrylist", fields: [列…] }
条目值：  [{ "name": "主控台", "url": "https://…", "user": "ops" }, …]
```

- 列（子字段）住在**字段定义**的 `fields` 里：`{key, label, sensitive?, hint?}`。
- 行是普通对象数组；`sensitive: true` 的列与顶层密文字段同一条加密边界。
- 列名用 key 或中文 label 都认。

## 二、建字段

```bash
# 面板：添加字段 → 类型「结构清单」；默认预填 名称/链接/账号/密码(密文) 四列
nx-sk template update <模板> --add-field '{
  "key":"accounts","label":"账号清单","type":"entrylist","group":"main",
  "fields":[
    {"key":"name","label":"名称"},
    {"key":"url","label":"链接"},
    {"key":"user","label":"账号"},
    {"key":"pass","label":"密码","sensitive":true}
  ]
}'
```

也可以在条目内加字段，但 **`entry add-field` 不接受列定义**；带列的 entrylist 必须先加到条目模板，再新建条目或 `template sync` 给存量条目补行。只影响单条的临时改法走面板「添加字段 → 结构清单」。

## 三、写入

```bash
# --data 直接给行数组
nx-sk entry update <条目> --data '{"账号清单":[
  {"名称":"主控台","链接":"https://console.example.com","账号":"ops","密码":"…"},
  {"名称":"备份机","链接":"https://backup.example.com","账号":"root","密码":"…"}
]}'

# --set 也可以，值是 JSON 串
nx-sk entry update <条目> --set 'accounts=[{"name":"主控台","user":"ops"}]'
```

- 全空行写入时自动剔除；`--set 字段=` 清空整份清单。
- 行里出现没声明的键会**当场报错**，不会静默丢掉。
- 没登记过的键直接写行数组时，会自动登记成 entrylist 并从行推断列——能用，但列类型/标签不如显式声明。

## 四、读

```bash
nx-sk entry get <条目> --json      # values.accounts 是行数组
nx-sk entry get <条目>             # 文本渲染：一行一条，列名=值；--mask 时密文列打码
```

## 五、Web

- 渲染成密集迷你表，直接增删行；行尾 `⠿` 调行序（hover 才出现的小图标）。
- 敏感列默认显原文，「打码显示」勾选后打码；打码时不要拖行序（短密码打码值相同会认错行）。
- 列结构在字段属性里改；要把「清单」升级成会算公式的表，新建 table 字段再迁值。

## 六、与相邻字段的边界

| 需求 | 用什么 |
| --- | --- |
| 多组账号，列固定 | `entrylist` |
| 每行列不同、要合计/公式 | `table`（A10） |
| 一组简单的多个值（城市/技能） | `tags` |
| 上传原件（PDF/图片） | `file`（A05） |
| 原始杂乱资料先入袋 | `source`（A03） |

## 七、常见错

| 现象 | 改法 |
| --- | --- |
| 行里写 `密码` 却被当成未知列 | 确认列已声明；label 与 key 都认，但别混用未声明的名字 |
| 面板看不到清单 | 字段没登记成结构行；用 `entry add-field` 或模板 `--add-field` 显式建 |
| 密文列导出后打不开 | 导出包里是明文（这是设计）；外发必须整包口令加密 |
