# 40 · 附件库

> 归属 `nx-sk` skill 主文档。要把「简历 / 头像 / 成绩单 / 证书扫描件」这类**二进制原件**收进库、
> 挂到条目上、或还原拿走时读这篇。
> 栏目与条目的通用命令见 `10-sections-entries`；这篇只讲「文件」这一块。

## 一、数据模型

```
~/nx-sk/files/<分类>/            二进制原件（真实文件，移动/复制进来的）
~/nx-sk/store.json 的 files[]    台账：id / name / rel / ext / bytes / sha256 / 标签 / 备注
~/nx-sk/store.json 的 entries[].values[<file字段>] = [f_xxxx, …]   ← 链接：字段值 = 附件 id 列表（可挂多个）
```

- 一个**附件** = 一次导入的原件 + 一条台账记录。物理文件永远以台账 `rel` 为准。
- 条目里的 `file` 字段（如 `resumeFile` / `avatar`），**值就是附件 id 的列表**（形如 `[f_xxxx, …]`；
  一个字段可挂多个）。id 全局唯一 → 各条目的附件空间天然隔离；同一个原件（sha256 相同）**去重**后是同一条，
  可被多条条目共享，不重复占空间。
- **上传 / 选择发生在栏目条目里**；「附件」中心只负责统一展示与库存管理，不做指派。

## 二、命令

| 操作 | 命令 |
| --- | --- |
| 列表 | `nx-sk file list [--section job] [--q 关键字]` |
| 单条 | `nx-sk file get <id>` |
| 导入 | `nx-sk file add --path <本机文件>` |
| 改属性 | `nx-sk file update <id> [--name …] [--tags …] [--note …]` |
| 取本体 | `nx-sk file content <id> [--download]` |
| 打开 | `nx-sk file open <id>`（本机默认程序） |
| 还原 | `nx-sk file restore <id> [--to DIR] [--copy]` |
| 删除 | `nx-sk file remove <id>` |
| **清理未引用** | `nx-sk file cleanup [--dry-run]` |

- `file list --section <栏目>` 只看「被某栏目引用」的附件；`--section none` 只看**还没有任何条目引用**的。
- `file content` 是浏览器链接：内联预览，加 `--download` 强制下载；CLI 侧打印物理路径与链接。
- 所有写命令都支持 `--dry-run`；`file remove` 连物理原件一起删**不可撤销**——
  只想「拿出原件、库里留着」应该用 `file restore --copy`。

## 三、三种「正式引用」（cleanup 与「未引用」判同一套）

附件算不算「已引用」，**判据只有一套**，附件中心的「未引用」筛选与 `file cleanup`
都用它（`fileReferences` 为空 = 未引用）。三种引用方式都算数：

| 引用方式 | 在哪 | 典型场景 |
| --- | --- | --- |
| `file` 字段值里有它的 id | 条目的 `values.<file字段>` | 简历 / 头像 / 成绩单挂条目上 |
| `md` 正文里写了 `![说明](f_xxx)` | 图文字段正文 | SOP 截图、图文笔记 |
| `source` 袋里有 kind=`file` 的 item 指着它 | 条目的原始资料袋 | **溯源**：字段值是从这份原件整理出来的 |

第三种是溯源的锚点：字段值会过时，「它是从哪份原件来的」必须永远能反查——
所以袋里的原件**受保护**：cleanup 不删、`transfer export` 随包带走、
`file get` 能反查到「条目 / 原始资料」。
反过来，一条附件三种引用都没有，就是真孤儿——`file cleanup` 会连物理原件一起删（不可撤销）。

### 「保存这个文件里的 xx」：先挂原件，再写字段

信息来自一份文件（图片 / PDF / Word…）时，**第一步是把原件收进库、挂到条目上**，
第二步才是把内容抄进字段。顺序反了，原件随手一放（桌面、下载目录、对话里），
被移动或清理之后字段就成了无源之水。

```bash
# ① 原件进库 + 挂条目（两种落点，判据见上表）
nx-sk source add <条目> --file "D:\扫描\成绩单.pdf" --name "教务处成绩单"  # 不好区分 / 先乱入：进袋
nx-sk file add --path "D:\扫描\成绩单.pdf" && nx-sk entry update 张三 --set 成绩单=f_xxx  # 有贴切 file 字段：直接挂
# ② 抄内容进字段（照字段台账的 key/label 写，别编字段名）
nx-sk entry update 张三 --data '{"绩点":"3.6/4.0"}' --dry-run      # 先试运行
# ③ 留痕：这条袋资料已整理到哪个字段（下次同步不重复）
nx-sk source update 张三 --id s_xxx --mapped gpa
```

- 扫描件先 OCR 再抄（见主文档「什么时候不用」）；OCR 拿不准的值**留空**，
  在袋里那条的 `--note` 里写明疑点——原件挂上了，随时能回看。
- 第 ③ 步的 `--mapped` 与双向同步见 `sk-source` skill。

## 四、一键清理未引用的附件（孤儿附件）

附件库是「导入即进库」：批量导入 SOP 截图、临时传一份再删，都会留下**没人引用的原件**——
既占空间，又在附件中心混在真资料里。逐个删是折磨。

```bash
nx-sk file cleanup --dry-run    # 先看会删哪些（名字 / 体积 / 物理路径）
nx-sk file cleanup              # 真删：物理原件一并删除，不可撤销
```

- 判据与「未引用」筛选片**完全同一套**：没有任何条目的 `file` 字段引用它、正文里没有引用它的图、
  资料袋里也没有指着它的 item。两套判据会出现「筛选片里看不到、清理却删了」这种吓人的不一致。
- 被引用的附件**一律不动**；同一个原件可以被多条条目共享，所以「已被引用」不是删除理由。
- 不可撤销：要留底就先 `nx-sk transfer export`。
- 面板上：附件中心工具条有「清理未引用（N）」，点了弹确认，报清数量。

## 五、导入：默认移动，`--copy` 才复制

```bash
nx-sk file add --path "D:\简历\张三-简历.pdf"          # 默认把原件**移动**进库（原件不再留在原地）
nx-sk file add --path "D:\简历\张三-简历.pdf" --copy   # 只复制一份进库，原文件留着
nx-sk file add --path C:\扫描\成绩单.pdf --tags 成绩单 --note "教务处盖章版"
```

- **默认移动**是本工具的取舍：提交附件 = 把原件搬进 `~/nx-sk/files/` 统一管理。
  想保留原地那份就显式 `--copy`。
- 同 sha256 的文件直接复用已有记录（返回 `duplicated`），不会重复占空间。
- `file add --dry-run` 只计算落点与校验，不移动、不写台账。

## 六、链接：`file` 字段值 = 附件 id 的**列表**（可挂多个）

条目**不复制文件**，只存附件 id。把 id 写进栏目里 `file` 类型的字段，链接就建立了；
**一个字段可以挂多个附件**（简历多个版本、头像多张、证书多份），值是 id 的数组：

```bash
# 先拿到附件的 id（file add 的输出 / file list --json 里的 files[].id）
nx-sk file add --path "D:\简历\张三-简历.pdf" --category resume

nx-sk entry update 张三 --set resumeFile=f_aaa,f_bbb   # 逗号分隔 = 挂两个（也可用 --data 传 JSON 数组）
nx-sk entry update 张三 --set resumeFile=f_aaa          # 只挂一个（存下来也是单元素数组）
nx-sk entry get 张三 --section job                # 每个附件各占一行：附件名 + 物理路径

# 反查：这个附件被哪些栏目 / 条目 / 字段引用
nx-sk file get f_bbb
#   被引用: 求职 / 张三 / 简历附件
```

- 求职条目里的「简历附件 / 头像图片 / 成绩单 / 证书扫描件」就是 `file` 字段。
- **别用文件名或路径去填** —— 值只认附件 id；填了别的东西条目侧会显示成「未解析」。
- 需要限制个数时给字段配 `maxItems`（与 `tags` 同一套；不配 = 不限）。
- 老数据里存的**单个 id 字符串**原样兼容：读、反查、搜索、面板编辑都按「单元素列表」处理，
  不需要迁移；下一次在面板里编辑该字段保存后，会统一成数组。

## 七、还原（可逆）

```bash
nx-sk file restore f_xxxx                         # 移回**原始位置**并撤销台账（默认）
nx-sk file restore f_xxxx --to "D:\资料" --copy   # 或导出副本到指定目录，库里保留原件与台账
nx-sk file restore f_xxxx --to "D:\资料"          # Web 上传件没有原始位置时，必须用 --to 指定目录
```

| 形态 | 效果 |
| --- | --- |
| `restore`（移动） | 物理原件移回原始位置（或 `--to` 目录），**台账记录撤销** |
| `restore --copy` | 只**导出副本**到目标目录，库中原件与台账**都保留** |

- Web 上传进来的附件没有「原始位置」，还原时必须给 `--to`。
- 还原/删除都不留本地备份；删之前先 `transfer export` 导一份——见 `60-transfer`。

## 八、Web 面板

`nx-sk serve` → 顶部「附件」页：

- 上传（拖拽 / 选文件）、本机路径导入、搜索、图片缩略图、内联预览、下载、复制物理路径 / 链接；
- **组织方式由栏目驱动、不预定义分类**：筛选片按「哪些栏目在引用附件」动态生成（外加「未引用」），
  每张卡片显示被哪个栏目 / 条目 / 字段引用；
- **两种引用都算已引用**：`file` 字段里选了本附件，或 `md` 字段正文里写了
  `![说明](f_xxx)`（外链图片 `https://…` 不算，它本来就不在附件库里）。
- 编辑弹窗可改名称 / 分类 / 标签 / 备注（改分类或文件名时物理原件随之移动）；
- **「清理未引用（N）」**：一键删掉所有没有任何条目引用的附件（判据与「未引用」筛选片同一套），
  物理原件一并删除，操作前弹确认；
- 条目表单里的 `file` 字段是**列表**：文件可直接**拖进字段框**（可多选）、点「上传文件」多选、
  从库里逐个追加、逐行移除；保存即建立链接。

### 字段里的附件选择器（可搜索 + 未引用优先）

点「从附件库选…」打开的是**选择面板**，不是下拉框：

- **可搜索**：按名称 / 备注 / 标签过滤（库里几十个附件时，下拉框根本没法挑）；
- **未引用优先**：没有任何条目引用的原件排在前面（刚导入还没挂上去的就在最上面），
  已被引用的排在后面并标注「已被 N 处引用」——仍然可选（同一原件可被多条条目共享）；
- 点一行即**追加**到本字段，可以连点多个；已挂上的会从列表里消失（它已经在这个字段里了）。

> 附件 id 是**全局唯一**的：同一个原件被两个条目挂上，两边指的是同一条记录。
> 「已被 N 处引用」说的就是这件事，不是「不能选」。

## 九、看不到 `file` 上传字段 / 条目里解析不到附件

1. **栏目里没有这类字段** —— 栏目字段台账是**持久化数据**：栏目实例化时深拷贝模板字段，
   此后独立演化，模板**后来**新增的字段不会自动回溯到已建栏目。用
   `nx-sk section sync <栏目>`（可先 `--dry-run`）把模板新增的分组与字段补进来（只增不改不删）；
   面板侧是「栏目 → 编辑 → 同步模板字段」。
2. **字段值不是有效的附件 id** —— `file get` 确认那个 id 存在；字段值必须是被导入过的附件 id，
   不是文件名、不是路径。
