# 20 · 文件与资料怎么进袋

> `sk-source` skill 的详细页。**什么时候读**：用户丢来的是文件、截图、PDF、
> 邮件、表格这些「非纯文字」的东西时。

## 原则：原件进附件库，袋里只留引用

```bash
nx-sk source add <条目> --file "D:\资料\用户指南.pdf" --name "平台用户指南 v1.3"
```

- `--file` 会把文件**复制**进 `~/nx-sk/files/`（原件保留在原处，不搬走），
  同内容自动去重（sha256），袋里留一个附件 id。
- 想要「原件搬进库里」那是 `nx-sk file add` 的语义（它默认移动）——两者别混。
- 袋里的 `file` item 只存 `fileId`；读的时候用 `nx-sk file get <fileId>` 或
  `source get --json` 里的 `files[fileId].path` 找物理路径。
- **袋里的文件算「已引用」**：`file cleanup` 不删它、`transfer export` 随包带走——
  袋是溯源的锚点，整理错了随时能点开原件回看。所以文件先入袋没有代价；
  不入袋的原件躺在库外，清理、移动、丢失都没有任何机制能拦。

## 各类资料的进法

| 资料形态 | 进法 | 注意 |
| --- | --- | --- |
| 截图（PNG/JPG） | `--file` | 面板里可多选一次拖一批；OCR 不准的数值**不要**直接写进字段 |
| 一段话 / 聊天记录 | `--text`（原文照抄，保留换行） | 别顺手"整理"成一段话——原文里的换行与缩进常常就是结构 |
| 一个网址 | `--url` | 网址本身可能就是信息（"这个链接是入口"）|
| 邮件 | `--text` 抄正文 + 需要的附件 `--file` | 抬头/发件人/时间写进 `--name` 或 `--note` |
| 表格 | 抄成 `--text`（制表符/逗号分隔），或整理成 `entrylist` 的行 | 表格往往就是「结构化清单」的原料，见下 |
| PDF | 抽文字后 `--text`；整份留档用 `--file` | 要图文 SOP 走 `sk-pdf`，别在这里手搓 |
| Word/Excel | 另存为 PDF 或纯文本再进 | 直接塞二进制没法读 |

## 表格 → 清单行

表格类资料常常**已经接近结构化**了。两种处理：

1. **留在袋里**（推荐先这样）：`--text` 存原文，第 3 步再决定怎么落。
   原文留着，整理错了还能回看。
2. **直接落成 `entrylist` 的行**：栏目里有 `entrylist` 字段时，把表格的每一行
   写成一条 `{列名: 值}`（`--data` 传 JSON 数组），列在字段定义的 `fields` 里声明。

别在第 1 步就落成清单行——**先收下**是这条流程的第一原则。

## 批量进一批文件

面板最快：条目表单底部「原始资料」折叠条 → 抽屉 → 「＋ 选择文件」（可多选）
或直接把一批文件拖进左栏。

CLI 逐个加（每条一次调用）：

```bash
for f in /path/to/*.png; do nx-sk source add <条目> --file "$f" --name "$(basename "$f")"; done
```

## PDF 的两种去向

| 你要做的是 | 走哪条路 |
| --- | --- |
| 把这份 PDF 变成图文 SOP 栏目 | `sk-pdf`（抽图、按版面挑图、建栏目、图文步骤）|
| 只是把这份 PDF 存下来、以后当资料引用 | 本页：`--file` 进袋，留个 `--name` |
| 把 PDF 里的表格/清单抽出来整理成字段 | `sk-pdf` 的 `pdf_extract.py` 抽文字 → `--text` 进袋 → 第 3 步整理 |

## 命名怎么起

`--name` 是这条资料在清单里显示的名字（人读）。规则：**能认出是什么就行**。

- 好：`李晶老师的资源分配邮件`、`平台用户指南 v1.3`、`控制台首屏截图`
- 差：`未命名`、`1.png`、`新建文件`（认不出就没法整理，等于没分类）

## 收进来的东西要不要整理、什么时候整理

**当场不问、也不整理**：用户只是「先存着」的时候，把东西收进袋、告诉他在哪，
别顺手就整理——他可能还没想好这些资料该怎么归。

**当场整理**：用户说了「整理成表」「归档到字段」，或者资料本身很明确
（一封只包含一个地址的邮件），那就走完第 3–4 步。

**一个袋塞太多**：一个条目里堆了几十条还没整理的资料，
建议**拆成多个条目**（按主题分），或者先在袋里分好组再整理。
袋子上限是 500 条，但**超过十几条就该考虑拆条目了**——那不是袋的问题，是条目粒度的问题。
