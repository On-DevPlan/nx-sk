# 结构与装订（设计开发类）

## 论文由哪几块组成

```
内页封面
目录（只提取到三级标题）
标题页：中文题目 → 专业+姓名 → 导师 → 摘要 → 关键词
        → 英文题目 → 英文作者 → Supervisor → Abstract → Key words
正文：1 绪论 … 6 结论
参考文献（另起一页）
致谢（另起一页）
附录（另起一页）
```

内页封面、目录、标题页**不编页码**；标题页之后从 1 开始编。

## 正文该有什么（设计开发类）

规范给的骨架是：**开发背景 → 相关方法与技术 → 总体功能结构设计 → 重点模块设计与实现 →
系统测试 → 小结**。落到 6 章，推荐：

| 章 | 内容 | 评审在看什么 |
| --- | --- | --- |
| 1 绪论 | 研究背景与意义、国内外研究现状、主要研究内容与论文结构 | 你知不知道这个题为什么值得做 |
| 2 相关方法与技术 | 涉及的理论、算法、系统环境、开发工具 | 每种技术在**你的项目里**起什么作用，不是教科书式罗列 |
| 3 需求分析与总体设计 | 需求、功能结构、模块结构、数据结构、实施架构 | 有没有用软件工程方法做设计，图能不能看懂 |
| 4 重点模块详细设计与实现 | 挑 2–4 个特色模块讲透 | 「重点」和「特色」；不要平铺所有模块 |
| 5 系统测试与结果分析 | 测试方法、流程、用例选取、结果分析 | 数据是否可信、结论是否由数据支撑 |
| 6 结论 | 主要结果、创新点、不足与后续工作 | 有没有自己的判断，别写成摘要的复制 |

顺序不能颠倒：没有需求与设计，直接讲实现，会被问「你凭什么这么设计」。

## 各部分写作要求

- **题目**：体现研究对象、研究内容与要解决的问题；原则上 ≤20 字；必要时加副标题。
- **中文摘要**：250–300 字，不分段，按【目的】【方法】【结果】【结论】组织；不出现公式图表、
  不标引用编号。
- **关键词**：3–5 个，分号分隔，外延由大到小。
- **英文部分**：与中文一一对应；题目实词首字母大写（介词、连词除外）。
- **参考文献**：≥15 篇、外文 ≥2 篇，近 5 年期刊为主；正文必须有引用，按出现顺序编号。
- **致谢**：另起一页，「致谢」黑体四号居中，200 字以上。
- **附录**：另起一页，格式参照正文；放原始数据、数据库详细结构表、运行截图、程序全文。

## 开题报告 vs 毕业论文：别混用一套样式

| 元素 | 开题报告 | 毕业论文 |
| --- | --- | --- |
| 一级标题 | 黑体小四 | **黑体四号** |
| 二级标题 | 宋体小四 | **黑体小四** |
| 三级标题 | 宋体小四 | 宋体小四 |
| 四级标题 | 不设；必要时（1）（2）接排 | 同左 |
| 正文 | 宋体小四 | 宋体小四 |
| 图表标题 | 黑体五号 | 黑体五号 |
| 表内文字 | 宋体五号 | 宋体五号 |
| 参考文献 | **五号** | **小四** |
| 字数 | ≥3500 字 | ≥8000 字，尽量 25 页以上 |
| 页码 | 每页都编 | 封面/目录/标题页不编，正文起为 1 |

开题报告正文结构：题目 → 立题依据（项目背景 / 国内外研究进展 / 设计目的与意义）→
研究的主要内容及预期目标 → 设计实现方案（系统分析与设计 / 技术路线）→ 进度安排 → 参考文献。
导师意见不少于 50 字。

## 装订顺序（8 项，别漏）

1. 论文（设计）答辩记录及成绩评定表
2. 本科毕业论文（设计）导师评分表
3. 本科毕业论文（设计）答辩评分表
4. 开题报告答辩记录表
5. 开题报告
6. 选题更改申请表（仅改题时）
7. 新的开题报告（改题后）
8. 论文内页封面、目录、正文

左侧装订，用学校统一发放的硬皮封面。

## 时间红线

- 进度：从选导师当年 **11 月**到毕业年份 **3、4 月**；分阶段、阶段之间不能断。
- **导师意见签署日期必须早于答辩日期**——答辩后再找导师签，会被退回。
- **封面完成日期必须晚于答辩委员会日期**。
- 成绩构成：导师审阅 50% + 答辩 50%（有学生互评的专业为 40% + 10% + 50%）。
