# sk-pdf · PDF → nx-sk 图文 SOP

把一份 PDF 变成 nx-sk 里的一个栏目，新手打开这个栏目就能照着做完所有操作。

**核心不是"把文字抄进去"，是"图文按版面原样拼回去"。** 手册的价值一半在截图里；
只抽文字等于丢了操作步骤，而零散截图没有上下文等于没用。

## 三条铁律

1. **先看清楚 PDF 的版面，再动手。** 52 页手册里 51 张图，其中只有一部分该进 SOP。
   照单全收会灌进几十张无关截图，照页码顺序猜则会插错位置。
2. **截图必须上传成附件，正文里用 `![说明](附件id)` 引用**，不要把图片链接写成外链。
   本地路径不是 URL，外链会失效；附件 id 才能在面板里点开、放大、被 `transfer` 带走。
3. **正文里的密码账号绝不写进 `md` 字段。** 用 `sensitive: true` 字段存，md 里只写「见〈某字段〉」。
   md 字段是明文渲染的，截图里出现密码也一样会被带出去 —— 提醒用户打码或改图。

## 流程

### 第 0 步：判断这份 PDF 适不适合转

先跑探查，拿到事实再决定（脚本见 [[10-extract]]）：

```bash
python scripts/pdf_probe.py <pdf路径>
```

输出：页数、每页图数与文字量、图片尺寸分布、页面尺寸是否统一。

- **图 ≤ 5 张**：不叫图文 SOP，直接抽文字建成普通条目更合适。
- **图很多但都是小图标/装饰**：抽文字为主，截图跳过（看尺寸分布就能判断）。
- **图多且都是大幅截图**：走完整图文流程。

### 第 1 步：抽文字 + 建立图文骨架

`pdf_probe.py` 之后，用 `pdf_extract.py` 生成一份**带图片占位符**的 markdown：

```bash
python scripts/pdf_extract.py <pdf路径> --out /tmp/pdf-out
```

它的做法（细节与理由见 [[10-extract]]）：把每页的文字块和图片矩形**都按 y 坐标排序**，
文字照常输出，图片输出成 `![p6-1](IMG_006_1)` 占位。这样图文相对顺序天然正确，
不用猜"这张图该配哪段文字"。

### 第 2 步：挑图（这一步最容易做错）

51 张全要 = 灌噪音；按页码顺序猜 = 插错位置。判据是**内容相关度**：

| 情形 | 处理 |
| --- | --- |
| 界面截图、配置面板、步骤图 | **要**，这是 SOP 的主体 |
| 同一页的多张图、每页固定 1–2 张、统一左边距 | **要**，这是手册的排版特征，说明每步配一图 |
| 页眉页脚 logo、装饰条、纯色块 | 不要（看显示尺寸，宽度接近整页而高度很小） |
| 与本次 SOP 无关的章节（如附录、法规全文） | 不要 |

**先看图再决定。** 把候选图导到一个临时目录，用图片查看器翻一遍：

```bash
python scripts/pdf_extract.py <pdf> --images-only --img-dir /tmp/pdf-imgs
```

然后逐张看，删掉不要的，把编号（`006_1` 这样的 `页码_页内序号`）记下来传给下一步。

### 第 3 步：把选中的图上传成附件

```bash
nx-sk file add --path /tmp/pdf-imgs/006_1.png --category other --json
```

- 一次上传一张，返回里有 `id`。
- 名字带上页码便于回溯：`--note "容器平台指南 p6 第1图"`。
- 上传默认**移动**原件 —— 从临时目录抽出来的图无所谓；如果你要保留抽取结果，加 `--copy`。

### 第 4 步：建栏目结构（见 [[20-sop-schema]]）

**不要照抄 PDF 的章节层级**，要按「新手照着能做完全流程」来组织。聚合类文档的标准结构：

| 字段 | 类型 | 放什么 |
| --- | --- | --- |
| 简介 | md | 这套平台是什么、能干什么、文档版本 |
| 准备材料 | md | **动手前要准备什么**：登录哪些网站、认证哪几层、装哪些工具、各环境用哪个执行器 |
| 入口与地址 | md | 所有 URL（控制台、堡垒机、VPN、文档站），一条一行 |
| 操作手册 | md | **图文 SOP 主体**，按任务分步骤，每步配截图 |
| 常见问题 | md | 报错原文 → 原因 → 处理 |
| 自检清单 | md | `- [ ]` 可勾选项，做完打勾 |

三层的账号体系（平台账号 / 统一认证 / 各子系统）**各自一个 `sensitive` 字段**，
在「准备材料」里点名引用，别把密码贴进正文。

### 第 5 步：写条目

```bash
nx-sk section add <栏目id> --title "<标题>" --json
nx-sk entry add --section <栏目id> --title "<条目名>" --json
nx-sk entry update <条目名> --set 简介="..." --json
```

`md` 字段的内容用 `--set` 传时注意转义（大量换行 + 反引号），更稳的做法是
**先写文件再读入**：

```bash
SOP="$(cat /tmp/sop.md)"
nx-sk entry update <条目名> --set "操作手册=$SOP" --json
```

正文里引用附件：

```markdown
1. 登录容器平台

![容器平台登录页](f_abc123)

2. 右上角「工作负载 → 部署」
```

### 第 6 步：回读验收

```bash
nx-sk entry get <条目名> --section <栏目id> --json
```

必查三件事：

1. **图片没有显示「缺失」** —— 有缺失说明占位符没换成真附件 id。
2. **图配对了步骤** —— 抽查 2–3 张，看说明文字和截图内容是不是一件事。
3. **附件中心的引用是通的** —— `nx-sk file list --json` 里这些图的 `usedBy`
   应指向本栏目本条目（md 正文里的图片算正式引用，详见 [[30-pitfalls]]）。

最后确认一遍渲染：

```bash
nx-sk serve --port 7866
```

打开栏目逐屏看，**图文错位一眼就能看出来**，比读 JSON 快得多。

## 工具

`scripts/` 下两个零依赖脚本（本 skill 随 nx-sk 分发，也可单独拷走用）：

| 脚本 | 作用 |
| --- | --- |
| `pdf_probe.py` | 探查：页数 / 每页图数 / 图片尺寸分布 / 页面尺寸 |
| `pdf_extract.py` | 抽取：文字 + 图片占位的 md、图片导出、`--images-only` |

依赖 PyMuPDF（本机 managed venv 已装）：

```bash
~/.workbuddy/binaries/python/envs/default/Scripts/python.exe -c "import pymupdf; print(pymupdf.__version__)"
```

## 硬约束

- **绝不把密码、token、私钥写进 `md` 字段**，一律走 `sensitive: true` 字段。
- **绝不把本地文件路径写成 `![](...)` 的值** —— 面板只认附件 id 与 http(s) 外链，
  路径既渲染不出来也传不出去。
- 扫描件（无文字层）先 OCR，转成带文字层的 PDF 再走本流程；不要对着纯图像页猜正文。
- 图文顺序以**版面位置**为准，不以页码为准。
