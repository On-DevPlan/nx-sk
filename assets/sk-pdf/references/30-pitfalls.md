# 踩过的坑

都是实际做一份 52 页手册时踩到的，不是假想。

## 1. 图 51 张，SOP 只要 18 张 —— 剩下的是什么

`pdf_probe.py` 报 51 张，但直接全灌进去就是噪音。真正进 SOP 的是**界面操作截图**；
其余是目录页截图、附录里的架构图、与本次任务无关的章节。

**做法**：先导出全部图片，**逐张看过再挑**。
判断不了就宁可多留 —— 留错了删掉是一分钟，漏了用户照着做不下去。

一整份文档不要只凭尺寸筛：尺寸只能滤掉装饰件（页眉 logo、分隔线），
筛不出「内容不相关」。

## 2. 图配错步骤：顺序必须来自版面，不能来自页码

最贵的错误 —— 文字全对，截图全错位，用户照着图文对不上，完全做不下去。
原因见 [[10-extract]]：`get_images()` 的 xref 顺序与版面无关。

`pdf_extract.py` 已经按 y 坐标排好了，直接用它出 md，别自己拼。

## 3. 占位符忘了换成附件 id

抽取出的 md 里是 `![p6-1](IMG_006_1)`。`IMG_006_1` 是**占位符**，不是附件 id，
面板只会显示「图片缺失」。

上传后要把占位符整体替换成真实 id：

```bash
pic=$(nx-sk file add --path images/006_1.png --category other --json | python -c "import json,sys;print(json.load(sys.stdin)['id'])")
sed -i "s#IMG_006_1#$pic#g" sop.md
```

**验收必查「有没有显示缺失」** —— 有缺失就是忘了替换。

## 4. 本地路径不能当图片地址

写成 `![图](C:/Users/.../006_1.png)` 面板**渲染不出来**，
因为它只认两种值：附件库 id 与 http(s) 外链。
`transfer` 打包时也带不走这种引用。

（注意 nx-sk 的 md 渲染与标准 markdown 有差别：标准写法允许相对路径，
这里不支持；这是有意为之 —— 相对路径换个机器就失效，而 id 能被包带走。）

## 5. 密码写进正文 = 泄漏

`md` 字段是明文渲染的，还会进导出、截图、分享出去的包。
账号密码一律走 `sensitive: true` 字段，正文只写「见〈某字段〉」。

**截图里的密码也要管**：如果 PDF 原图里就打着密码，要么提醒用户打码重截，
要么别放这张图 —— 图片本身也是明文。

## 6. md 正文里的图片，附件中心曾经显示「未引用」

2026-10-18 之前，`fileReferences` 只扫 `file` 字段、不看 md 正文，
于是图片明明在 SOP 里用着，附件中心却说未引用。已修（`core/attachments.js`），
现在两种引用都认，命中判定也改成按 id 比而不是对象引用相等。

如果又看到「未引用」而图片明明在正文里，先确认 nx-sk 版本 ≥ 修好的版本。

## 7. 附件按 sha256 去重 —— 测试与实际导入都会撞

同一张图重复上传会**复用已有记录**（不存两份）。这是特性，但有两个后果：

- 写测试时用相同字节造两张图，第二张会拿到第一张的 id，测试看着失败其实是用例写错；
- 换了一张内容完全相同的图却发现 id 没变，先确认是不是同一张图。

## 8. `file add` 默认移动原件

`nx-sk file add --path x.png` 会把 x.png **搬进** `~/nx-sk/files/`。
从临时目录抽的图无所谓；想保留抽取结果就加 `--copy`。

同理，别对唯一的原始 PDF 跑任何「移动」语义的命令。

## 9. 页脚混进正文

PDF 页脚（`Copyright © 2023 …`）会被当成正常文字抽出来，出现在步骤中间，
读起来很怪。抽取后**扫一遍 md**，把重复出现的页脚删掉。

（`pdf_extract.py` 目前不自动滤页脚 —— 不同文档页脚样式差异太大，
按位置（y 接近页底）+ 跨页重复来判定更准，这一步留给人工更稳。）

## 10. 扫描件抽出来是空

没有文字层的 PDF，`get_text()` 返回空串 —— md 里只剩图片占位符。
先 OCR 再走本流程，别对着纯图像页猜正文（很容易编造出原文没有的内容）。

`pdf_probe.py` 会列出无文字层的页码，部分页缺层时要明确告诉用户那部分正文缺失。
