# sk-needdo · 混乱数据 → nx-sk 栏目与条目

一句话：**先想清「这些是什么」，再决定「放哪」，最后才写。**

用户的输入通常是一团：一段话里三件事、一个链接、一份 Word、一列待办。你的活不是"把字抄进库里"，
而是**替他想清楚结构**：这件事属于哪个栏目？这个栏目该有哪些字段？然后按结构填。

## 三条铁律

1. **先查后建。** `nx-sk section list` 已经有能装的栏目就别新建。
   栏目是**永久成本**：每个栏目都要维护字段台账、在面板上占一个 tab、导出时多一份。
   为了三行数据新建一个栏目，三个月后你自己都不知道该往哪写。
2. **结构先定，值后填。** 字段台账是数据不是代码，写下去容易、改起来难（面板按台账渲染）。
   所以先让用户看到「复用/新建哪个栏目 + 哪些字段 + 预计几条」，拍板后再写盘。
3. **原文不丢。** 文件进附件库、长文进 `md` 字段、链接原样留在链接字段。
   摘要可以重写，原文不能只剩摘要 —— 收件箱的第一承诺是「收进来」，不是「总结掉」。

## ⚠️ md 字段的可交互特性（务必告诉用户）

当一个字段的 type = **`md`** 时（备忘、会议纪要、SOP、待办清单、带图的资料……都常用它），
里面写的 `- [ ]` / `- [x]` 是**可点的复选框**——预览里勾一下，写回正文里把 `[ ]` 改成 `[x]`
（基于 `mdSource.toggleTaskAtLine`，行号定位、只动复选框、不动其他字符）。这一条比
看起来重得多：往 md 字段里多塞一段带 `- [ ]` 的清单，等于在面板里**白送**一个人能勾选的
进度面板；不写 `- [ ]` 而写一段"1. 交周报 2. 报销"——它就只是两行字，**不会**变成可点的东西。
因此推荐做法：**任何「一串要做的事」**（待办、清单、步骤、验收项），只要它落在 md 字段里，
就用 `- [ ]` / `- [x]` 语法写，不要写"1. xxx 2. yyy"，效果差一个量级。

同样的原则也适用于「会议纪要里有几个 Action」「复现步骤清单」「上线 checklist」——
让用户**点得动**，而不是只能读。

入口（每一步里都会再点一次名）：第 5 步落值时给 `md` 字段写带 `- [ ]` 的清单；
第 6 步自检时打开面板亲手勾一项，确认写回（不是只渲染）。

## 流程（七步，别跳第 3 步）

### 第 0 步：摊开清点（先别写）

把输入拆成「条目候选」：**一条 = 一件独立的事 / 一份独立的资料**。

| 输入形态 | 拆法 |
| --- | --- |
| 一段话混了三件事 | 拆成 3 条 |
| 一份 PDF / Word / 截图 | 1 条 + 原件进附件库，正文写「这份文件是什么」 |
| 一个链接 | 1 条（链接本身就是内容） |
| 表格 / 清单 / 群公告 | 一行（或一条公告）一条 |
| 重复出现的东西 | 先合并，别建两条同名条目 |

拆条的判据、混排里抽链接的规则、以及"哪些其实不该入库"，见 [[10-inbox]]。

### 第 1 步：侦察现有栏目

```bash
nx-sk bootstrap --json                 # 栏目 / 设置 / 命令表，一次拿齐
nx-sk section list --json              # 有哪些栏目、各几个字段几条
nx-sk section dump <候选栏目> --json   # 字段台账 + 条目 + 每条未填清单
```

三选一，**按顺序判断**：

- **能装**（字段覆盖 ≥ 80%）→ 复用，缺的字段补一两个。
- **差得远但主题一致**（比如"服务器"栏目里要加 k8s 字段）→ 补字段，别新建。
- **确实没有归属**（新主题、跟现有栏目都不搭）→ 新建。

拿不准时看 `description` 和现有条目的形状：栏目是"装什么"的声明，条目是"长什么样"的证据。

### 第 2 步：设计结构

字段怎么定（key 命名、类型选择、分组、必填/可选、密文）见 [[20-schema]]。最低要求：

- 每个字段有 **key**（英文小写下划线、稳定）、**label**（中文）、**type**、**group**
- 一条目一个**主标题字段**（`titleField`），否则条目列表全是"（无名）"
- 密码 / token / 身份证号 → `sensitive: true`（密文落盘），或直接放 `secret` 这个 KV 栏目
- 明显不是每次都有的信息（备注、附件、来源）→ `fill: optional`，别拉低完整度

### 第 3 步：让用户拍板（一步，别省）

用一段话 + 一张表说清四件事，然后**停下来等确认**：

1. 复用哪个栏目 / 新建哪个（id + 中文标题）
2. 加哪些字段（key · 标签 · 类型）
3. 预计落几条、哪些信息还缺
4. 哪些内容**没**入库、为什么（敏感 / 重复 / 不像数据）

用户说"就这样"再往下走。这一步花 30 秒，省掉的是"建错栏目再删"的十分钟。

### 第 4 步：建结构

```bash
# 新建栏目：字段与分组都走文件，别在命令行里拼 JSON
# --titleField 指定"用哪个字段的值当条目名"，不给就得逐条 --title
nx-sk section add memo --title "备忘" --titleField name --titleLabel 名称 \
  --fields @fields.json --groups @groups.json --dry-run
nx-sk section add memo --title "备忘" --titleField name --titleLabel 名称 \
  --fields @fields.json --groups @groups.json

# 复用栏目：补字段（key 已存在会报 conflict，先 section dump 看清）
nx-sk section update memo --add-field '{"key":"due","label":"截止","type":"date","group":"main"}' --dry-run
```

`--fields` 是**整份替换**，`--add-field` 是**追加**。只想改某个字段的标签/hint 时，只能拿
`section dump` 的字段数组改完整体 `--fields`（小心：漏掉字段就是删字段）。

### 第 5 步：填值

一条一个 `entry add`，值走文件（命令行转义多行中文是自找麻烦）：

```bash
nx-sk entry add --section memo --title "10 月值班表" --data @item-1.json --dry-run
```

- `--data` 可以是扁平 `{字段: 值}`，也可以是 `{values: {...}}`
- 图片/文件先进 `file add` 拿 id，再在 `md` 字段里写 `![说明](f_xxx)`
- 同名条目会报 `CONFLICT`：重跑前先 `entry list` 看有没有，有就 `entry update`
- 细节（附件、md 字段、幂等、来源留痕）见 [[30-fill]]

### 第 6 步：自检

```bash
nx-sk section dump <栏目> --json    # 条目数 / 完整度 / 未填清单
nx-sk entry get <条目> --json       # 回读单条，确认值真的进去了
```

再看一眼面板（`nx-sk serve`）：`md` 字段的图片有没有显示、待办勾选框在不在、链接能不能点。
**"存了却没生效"最常见的原因是字段没登记进台账** —— 面板按台账渲染，台账里没有的键看不见。

### 第 7 步：汇报

四句话说完：给了什么 → 落成什么（栏目 / 条目数 / 附件数）→ 哪些没落（缺信息 / 敏感 / 重复）→
建议下一步（补哪几个字段、要不要开面板看）。

## 这套流程从哪来

它原本是一个独立应用的 NeedDo 收件箱模块（捕获 → 确定性归类 → 整理报告 → 归档）。
那个模块的几条经验直接搬过来了，别丢：

- **确定性优先**：能按规则判断的（整行是不是 URL、是不是待办）就别问模型；规则可解释、可回归。
- **原文一字不动**：抽链接只是"附挂"，不改写正文。
- **人的判断最高**：用户显式指定的分类/字段，永远不被自动规则覆盖。
- **幂等**：同一批数据重跑不该产生第二份；靠"同名条目 → update"和"来源字段"去重。
