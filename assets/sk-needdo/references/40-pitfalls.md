# 踩过的坑（每条都真实发生过）

## 1. 字段没登记 → 存了却看不见

面板按**字段台账**渲染。`entry add --set 临时字段=值` 会自动登记，但如果你直接改 store 或用
没声明过的键，值在库里、面板上看不到 —— 表现就是"我明明存了"。

**判据**：写完 `section dump <栏目> --json`，看 `fields` 里有没有这个 key。

## 2. 栏目爆炸

每来一批数据就新建一个栏目，三个月后侧边栏 30 个 tab，每个栏目 2 条数据。
**规则**：能塞进现有栏目就塞；只有当主题确实不同（求职 vs 服务器）才新建。
新建前先 `section list --json` 看一眼 `description`。

## 3. 把一整批塞进一个 `md` 字段

"这 20 条待办我全写进一个 md" → 没法按截止日期排序、没法标记谁负责、没法单条完成。
**一条一件独立的事**，md 只装"这件事的说明"。

## 4. 密文进了普通字段

`text` 字段是明文落盘的，导出、`transfer`、截图都会带出去。
密码 / token / 证件号 → `secret` 类型字段或 `secret` 栏目（KV + AES 密文）。
`md` 字段里也**不要写密码**（它是明文渲染）。

## 5. `file add --path` 把用户的原件搬走了

默认是**移动**。用户说"把这个文件存进库"通常不是"从我的下载目录里删掉它"。
**默认加 `--copy`**，除非用户明确说"移进去"。

## 6. 重复导入产生 `（导入）` 副本

同名条目重跑 `entry add` 会 `CONFLICT`；如果用 `transfer import --on-conflict copy` 反复导入同一份包，
会得到 `甲（导入）`、`甲（导入 2）`…… 一批越来越长的副本。
**重跑用 `entry update`**，导入前先看预览里的冲突明细。

## 7. 抽链接把中文标点吃进去

`https://a.com/x，第一遍` 里的 `，`、`（见 https://a.com）` 里的 `）` 都不是 URL 的一部分。
只认 `http(s)`，并把尾部的中文标点与不配对括号剥掉。
（nx-sk 的预览层已经处理了这件事，但你自己抽链接写进字段时要按同一口径。）

## 8. 标题为空 → 条目叫「（无名）」

`titleField` 没填、`--title` 又没给，面板上就是一排"（无名）"。
**每条都必须有标题**：取首行、文件名、或"<类型> · <日期>"。

## 9. 完整度虚高 / 虚低

- 把"备注""来源""附件"设成必填 → 永远 80%，完整度失去意义
- 把所有字段设 `optional` → 永远 100%，也失去意义
**只给"每次都有"的字段必填。**

## 10. 分组没声明 → 整组字段消失

字段的 `group` 必须在 `groups` 数组里声明过。`--add-field` 会自动补声明，但手写
`--fields` 整体替换时容易漏 —— 漏了面板就渲染不出这一组（CLI 看不出来）。

## 11. 在命令行里拼多行中文 JSON

引号、换行、中文标点会在 shell 层被吃掉一部分，报错还看不懂。
**一律写文件，用 `@file.json`**。

## 12. 把「不该入库的」也收进来

一次性验证码、别人的隐私、纯寒暄、已经存在的重复内容 —— 收进来只会增加清理成本。
先问一句"这个要长期留着吗"，比事后删十条便宜。
