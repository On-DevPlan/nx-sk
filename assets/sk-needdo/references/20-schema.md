# 字段设计：给这批数据定一个「以后还能长」的骨架

字段台账（section.fields）是**数据不是代码**：它随栏目存在 store 里，面板、CLI、agent 看到的是同一份。
所以字段一旦写下去，就是"这个栏目长什么样"的长期承诺。

## 先定 titleField

`section add` 一定要带 `--titleField <字段key>`（和 `--titleLabel <中文名>`）：

```bash
nx-sk section add memo --title "备忘" --titleField name --titleLabel 名称 \
  --fields @fields.json --groups @groups.json
```

- 它决定"用哪个字段的值当条目名"。**不给的话**，每条都得 `entry add --title …`，
  否则报「无法确定条目名」；给了就能直接 `entry add --data @item.json`。
- 选**最短、最能代表这件事、几乎不会变**的那个字段（名称、标题、公司名）。
- 别选会频繁改的字段（备注、状态）—— 条目名是 `entry get <名字>` 的定位键。

## 一个字段由这些组成

```json
{
  "key": "due",
  "label": "截止",
  "type": "date",
  "group": "main",
  "hint": "报销单要在这一天前提交",
  "fill": "optional",
  "sensitive": true,
  "options": ["待办", "进行中", "已完成"],
  "maxItems": 3
}
```

| 属性 | 必填 | 说明 |
| --- | --- | --- |
| `key` | ✅ | 英文小写下划线，**稳定**（改名等于换字段） |
| `label` | ✅ | 中文标签，面板上显示的就是它 |
| `type` | ✅ | 见下表 |
| `group` | ✅ | 分组 id（要在 `groups` 里声明，否则面板渲染不出来） |
| `hint` | | 一句话说明"填什么"，直接显示在输入框下面 —— 三个月后救的是你自己 |
| `fill` | | `optional` 不必填 / `avoid` 填了可能减分（求职场景）/ 缺省 = 正常 |
| `sensitive` | | `true` = 密文落盘（AES-256-GCM），面板打码 |
| `options` | | `select` 的候选值 |
| `maxItems` | | `tags` / `file` 的上限 |

## 类型怎么选

| 内容 | type | 反例（别这么干） |
| --- | --- | --- |
| 名称、标题、短句 | `text` | 把备注写成 text，长文本会挤成一行 |
| 多行说明、步骤 | `textarea` | 用 text 存 500 字 |
| 要贴图 / 要待办 / 要表格 | `md` | 用 textarea 存 `![](f_x)`，图不会显示 |
| 日期 | `date`（`YYYY-MM-DD`） | 塞进 text 写成"下周三" |
| 月份 | `month`（`YYYY-MM`） | |
| 金额、数量 | `number` | 写成"约 300 元"（没法排序/汇总） |
| 是 / 否 | `bool` | 用 text 写"是"/"否" |
| 固定几个状态 | `select` + `options` | 用 text 随便写，之后没法筛 |
| 多个标签 | `tags` | 用一个 text 存"a、b、c"，没法单独筛 |
| 密码 / token / 证件号 | `secret` 或 `sensitive: true` | **绝不放普通 text** |
| 附件（简历、合同、截图） | `file` | 把文件路径写成 text（路径会失效） |

`md` 是 nx-sk 的特色：一段 markdown 正文，能嵌附件库的图片、能写待办（`- [ ]`）、
预览里标题/列表/表格/代码块都按标准 markdown 渲染，裸 IP 点击即复制、裸域名点击即打开。
"说明 + 截图混排"的东西（SOP、报错复现、会议纪要带图）优先用它。

## key 怎么起

- 英文、小写下划线：`due`、`owner`、`meeting_room`、`reimburse_amount`
- **别用中文当 key**（虽然合法）：面板、CLI、`--set` 混着用时最容易写错
- **别用 label 当 key**：label 是给人看的，随时可能改；key 是给程序用的，改了等于换字段
- 同一个栏目里 key 唯一；跨栏目可以重名（互不影响）

## 分组：按"读的时候的注意力顺序"

- **≤ 4 组**，组名是中文短语（"基本信息""进度""附件"）
- 第一组放"一眼要看到的东西"（名称、状态、截止），后面放细节
- 组 id 用英文（`main` / `detail` / `files`），title 用中文
- 新增字段时**一定要给 group**，且该 group 必须在 `groups` 数组里声明过 ——
  否则面板读声明数组渲染，整组字段会静默消失（CLI 从字段推导，看不出来）

## 必填与完整度

- 缺省 = 必填，会计入完整度；`optional` 不计入
- **只给"每次都有"的字段必填**：给"备注""来源""附件"设必填，等于永远 80% 完整度，完整度就没人看了
- `avoid` 用在"填了可能减分"的场景（求职栏目的政治面貌、婚育），不是"不想填"

## 字段数量的经验值

- **3–8 个**：一个栏目读起来舒服的区间
- **超过 12 个**：八成该拆成两个栏目（"基本信息" vs "过程记录"）
- **只有 1–2 个**：可能不值得建栏目，塞进现有栏目的 `md` 字段或 `notes` 更合适

## 先给用户看的格式

设计完别直接建，用这张表让用户拍板：

```
栏目：备忘（memo，新建）
  名称      text     必填   一眼知道是什么
  类型      select   必填   待办 / 通知 / 资料
  截止      date     可选   过期就不显眼
  正文      md       可选   截图、步骤、清单
  来源      text     可选   贴来的 / 链接 / 文件路径（去重用）
```

用户看得懂这张表，看不懂 JSON。
