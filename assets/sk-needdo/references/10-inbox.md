# 拆条：一团输入到底算几条

拆错的代价是双份的：拆太细 → 几十条碎片，谁也读不出上下文；拆太粗 → 一条里塞三件事，
以后想按"截止时间"排序、按"状态"筛都做不到。

## 判据：一条 = 一件独立的事 / 一份独立的资料

问自己三个问题：

1. **它会单独被"完成"或"使用"吗？** 会 → 独立一条。
2. **它有自己的时间 / 状态 / 归属吗？** 有 → 独立一条。
3. **删掉它，另一条还完整吗？** 完整 → 本来就是两条。

| 输入 | 拆法 | 理由 |
| --- | --- | --- |
| "明天下午三点开会，记得带 Q4 预算，会议室在 3 楼" | **1 条**（会议），时间/地点/要带的东西进字段 | 同一件事的三个属性 |
| "① 交周报 ② 报销截止周五 ③ 服务器到期提醒" | **3 条** | 三件互不相关的事 |
| 一份《2026 值班表.pdf》 | **1 条** + 原件进附件库 | 一份资料一条 |
| 群公告里 5 个人的任务分配 | 先问：**只存公告**（1 条），还是**每人一条待办**（5 条）？ | 两种都合理，取决于用户要"查公告"还是"催人" |
| 一列 `A 100 元 / B 200 元` | **2 条**（明细），除非它本身是"报销单"（1 条 + 明细字段） | 明细要不要独立，看是否单独流转 |

**拿不准就问一句**，别自己拍。拆条是最容易返工的一步。

## 文字里混着链接：原文不动，链接附挂

一段话里出现 `https://…` 时：

- **整行只有一个 URL** → 这条是"链接条目"，链接是它的主体。
- **URL 夹在句子里** → 仍按文字条目存，原文一字不改，另外把链接抽出来放进 `links` 字段
  （或直接在 `md` 字段里保留，nx-sk 的预览里裸链接可点）。

抽链接的边界（这几条都是踩出来的）：

- **中文标点不是 URL 的一部分**：`https://a.com/x，第一遍` 里的 `，` 必须断开。
  顿号、句号、括号、书名号同理。
- **尾部 ASCII 标点要修剪**：`（见 https://a.com/x）` 的 `）`、`https://a.com/x.` 的 `.`。
- **只认 http(s)**：`ftp://`、`www.example.com`、`mailto:` 不当链接（否则文件名、包名全变成可点的）。
  nx-sk 的预览会自己把裸域名识别成可点链接（默认补 `http://`），不用你手动改。

## 文件：原件是资产，提取文本是加分项

| 类型 | 处理 |
| --- | --- |
| PDF / DOCX / TXT / MD | 原件进附件库；能提文本就把关键内容写进 `md` 字段 |
| 扫描件 / 加密 PDF / 图片 | **不提文本**：原样进附件库，标题写清"这是什么"，别硬猜内容 |
| 图片（截图） | 进附件库，`md` 里 `![说明](id)`；截图里的密码提醒用户打码 |
| 表格（xlsx/csv） | 原件进附件库；行数少就把关键几行写进 md 表格，行数多只存原件 |

**原件一律 `file add --path <路径> --copy`**（`--path` 默认是**移动**原件！用户的文件不该被搬走）。

提取文本失败不是错误：收件箱的第一承诺是"收进来"，文本化是加分项。

## 不该入库的东西

- 寒暄、感谢、纯查询（"这个怎么用"）—— 那不是数据。
- 一次性验证码、临时口令 —— 用完就没意义，存了反而是泄漏面。
- 别人的隐私（同事的手机号、客户名单）—— 除非用户明确要求且说清用途。
- 已经存在的内容 —— 先 `entry list --q <关键词>` 查一遍，重复入库比不入库更糟。

## 标题与摘录

- **标题**：取首行 / 文件名 / 会议名，**≤ 60 字**。超过就截断，别让面板列表变成一堵墙。
- **摘录**：≤ 200 字，只用于列表里的一行提示；全文进正文或 md 字段。
- 标题里不要带日期前缀（`2026-10-18 开会`）——日期有专门的字段，塞进标题就没法按日期排了。
